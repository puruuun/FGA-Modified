# 0007 프렌드 포인트 소환 + 자동 판매 루프

- 상태: 구현 완료 (검증: `docs/releases/beta/FGA-beta-1.4.0-beta.1-validation.md`)
- 버전: 베타 **1.4.0-beta.1** (`1004001`). §9 항목도 beta.1에 포함
- 대상 서버: **KR, JP** (KR 화면은 소유자 제공. JP 화면은 소유자에게 요청 — 6절)
- 기본 팀: 구현 Codex gpt-6.1-sol medium. 실제 게임 QA는 소유자가 지시할 때만, **시험 모드 먼저**.

## 1. 배경

`AutoFriendGacha`(`scripts/.../entrypoints/AutoFriendGacha.kt`)는 프렌드 포인트 10연속 소환을 반복하다가 인벤토리 가득 참(`Images.InventoryFull`)을 만나면 `ExitReason.InventoryFull`로 종료합니다. 소유자는 이 뒤에 **자동 판매 → 소환 화면 복귀 → 다시 소환**을 이어 붙이길 원합니다.

소유자 화면(`build/orchestration/inputs/0007/15~28.webp`, KR, 블루스택 창 캡처 1971×1131, 창 테두리 포함):

|---|---|

| 16 | 기존 동작: "스크립트 종료됨 / 인벤토리 꽉 참" |
| 17 | 가득 참 경고: "서번트칸(+100칸)이 한계입니다… 현재 보유 수 1009/900", 버튼 **판매 / 강화 / 영기 보관실 / 닫기** |

## 2. 목표 / 비목표

**목표**
- 프렌드 포인트 소환 중 서번트칸 가득 참 경고가 뜨면, 설정한 종류만 판매하고 처음 시작한 소환 배너로 돌아와 소환을 계속합니다.
- 판매 대상 종류: **1★·2★·3★·4★ 서번트, 4★·5★ 경험치 카드.** 종류마다 켜고 끕니다.
- **시험 모드**: 판매 대상을 선택까지만 하고 판매(확인)는 하지 않습니다. 선택 결과를 확인할 수 있게 한 뒤 정지합니다.
- KR, JP 모두 지원합니다.

**비목표**
- 개념예장, 커맨드 코드 판매(개념예장칸이 가득 차면 정지)
- 게임 안 필터·정렬 변경
- QP 상한 처리(소유자 결정: 고려하지 않음)
- 5★ 서번트 판매(설정 항목도 만들지 않음)

## 3. 결정 사항 (소유자 답변 2026-10-18 반영)

- **D-1. 기본값.** 1★·2★ 서번트 판매 **켬**, 3★·4★ 서번트 판매 **끔**, 4★·5★ 경험치 카드 판매 **켬**. 자동 판매 기능 자체는 기본 **꺼짐**(옵트인).
- **D-2. 잠긴(자물쇠) 항목은 어떤 경우에도 선택하지 않습니다.** 잠금을 풀지 않습니다. 잠금 판별이 불확실한 칸도 선택하지 않습니다(불확실 = 제외).
- **D-3. "NEW!만 판매" 옵션, 기본 켬.** 이번에 새로 얻은 것만 판매해 기존에 가진(육성한) 서번트를 보호합니다.
  - 성능: 칸 하나에 템플릿 매칭 1회 추가(720p 작은 영역)라 화면당 수십 ms 수준이고, 탭과 대기 시간에 비해 무시할 수 있습니다.
  - 반짝임: NEW! 글자는 밝기가 계속 바뀝니다(26·28번에서 밝기 차이). FGA 매칭(`TM_CCOEFF_NORMED`)은 밝기·대비가 함께 변하는 것에 강하므로 영향이 작습니다. 그래도 어두운 순간과 밝은 순간 **두 장의 템플릿**을 쓰고, 판정이 애매하면(기준 근처) 0.3초 뒤 다시 캡처해 한 번 더 봅니다. 그래도 애매하면 **NEW!가 없는 것으로 보고 선택하지 않습니다**(안전 쪽).
  - fixture로 밝은/어두운 NEW! 모두 인식하는지, NEW! 없는 칸을 NEW!로 잘못 보지 않는지 확인합니다.
- **D-4. 아이콘 크기.** 판별은 **작은 아이콘(7열)** 기준으로만 합니다. 판매 화면에서 7열이 아니면 아이콘 크기 전환 버튼을 눌러 7열로 맞춘 뒤 판별합니다(소유자 허락: 게임 설정이 바뀌어도 됨). 5·6열까지 판별하려면 템플릿과 좌표가 세 벌 필요하고 검증 부담이 커서 하지 않습니다.
  - 전환 버튼은 왼쪽 버튼 줄 맨 아래에 있고 FGA 재생 버튼에 가려질 수 있습니다. 탭 위치는 가려지지 않는 부분으로 잡고, 전환 후 열 수를 다시 확인합니다. 3번 눌러도 7열이 안 되면 정지합니다.
- **D-5. 칸 판별(7열).** 각 칸에서 다음을 판별합니다.
  1. 종류: 아래쪽 라벨 **"Servant"** / **"Exp. UP"**(서버 공통 영어 표기인지 JP 화면으로 확인)
  2. 별 개수: 라벨 위 별 줄(1~5★)
  3. NEW! 여부(D-3)
  4. 잠금 여부(D-2): 잠금 아이콘 템플릿. 잠금 칸 fixture가 없으면 소유자에게 요청하고, 그 전까지는 **잠금 판별 불가 시 판매 기능 전체를 시험 모드로만 허용**합니다.
  5. 이미 선택됨(하늘색 테두리) 여부
  - 위 판별 중 하나라도 확신하지 못하면 그 칸은 **선택하지 않습니다.**
- **D-6. 선택과 판매.** 서버 탭이 "서번트"인지 확인한 뒤, 화면의 대상 칸을 위에서부터 탭해 선택합니다. 스크롤하며 끝까지 선택(선택은 스크롤해도 유지, 최대 999). 끝까지 가면 **확인 → 변환 → 닫기**. 선택된 수가 0이면 판매하지 않습니다.
- **D-7. 배너 기억과 복귀.** 소환을 시작할 때(첫 프렌드 소환 화면 판별 시점) 다음 두 가지를 저장합니다.
  - 아래 점 줄에서 **켜진 점의 순번**(점 줄 영역에서 켜진 점 위치를 찾아 순번 계산)
  - **배너 중앙 제목 영역 이미지**(소환 배너 고유 그림)
  - 복귀 시: 다빈치 공방 → MENU → 소환 → 열린 배너의 켜진 점 순번을 읽어 차이만큼 좌/우 화살표 → 배너 이미지가 일치하는지 확인(유사도 0.85 이상). 이미지가 다르면 한 칸씩 더 넘기며 최대 점 개수만큼 찾아보고, 못 찾으면 정지(`BannerNotFound`).
- **D-8. 종료 조건.**
  - 판매 후 다시 소환했는데 곧바로 서번트칸 가득 참이 다시 뜨고 **직전 판매에서 판 수가 0**이면 정지(`InventoryFullNothingToSell`).
  - 개념예장칸 가득 참 경고면 정지(`CeInventoryFull`).
  - 기존 소환 횟수 제한(`limitFP`)은 그대로 적용.
  - 시험 모드에서는 첫 선택이 끝나면 정지(`SellDryRunDone`). 선택 상태는 그대로 두어 소유자가 화면에서 확인할 수 있게 합니다.
- **D-9. 화면 처리 방식.** `AutoFriendGacha`의 화면 판별 → 처리 맵 구조를 유지하고, 판매·복귀 단계는 별도 모듈(`scripts/.../modules/FpAutoSell.kt`, `FpBannerReturn.kt`)로 분리합니다. 판매 기능이 꺼져 있으면 기존 동작(가득 차면 종료)과 완전히 같아야 합니다.

## 8. 추가 결정 (2026-10-18, 구현 agent 질문에 대한 설계자 결정)

- **D-10. 시험 모드에서는 잠금 불확실 칸도 선택해서 보여 줍니다.** 시험 모드는 [확인]을 누르지 않고 멈추므로 어떤 선택도 판매로 이어지지 않습니다(선택은 "선택 모두 해제"로 되돌릴 수 있음).
  - 시험 모드: D-5의 1~3·5번 판별로 대상이 되는 칸은 선택합니다. 잠금 판별이 불확실하거나 잠금 템플릿이 없는 칸은 선택하되, 로그와 종료 안내에 "잠금 판별 안 됨 N칸"으로 따로 셉니다. 잠금으로 **확실히** 판별된 칸은 시험 모드에서도 선택하지 않습니다.
  - 실제 판매: D-2 그대로입니다. 잠금 판별이 불확실하면 선택하지 않고, 잠금 템플릿이 없으면 실제 판매 자체를 막습니다(시험 모드만 허용).
  - 게임이 잠긴 칸의 선택을 막는지는 확인되지 않았으므로 이 동작에 기대지 않습니다.
- 시험 모드 종료 안내에는 선택한 칸 수, 종류별 수, 잠금 판별 안 됨 수를 보여 줍니다.

   - 로그에서도 `tiles=28 evaluated=21`인데 칸 줄은 r2·r3만 나옵니다(gridTop 7칸 + 14칸).
2. **별 수 판별 불가(`stars=?`)가 잦습니다.**
   - 1★ 칸의 첫 별 칸 점수는 0.70~0.85입니다. 그런데 빈 칸이 그림 때문에 0.41~0.45까지 올라옵니다.
   - beta.4 규칙("다음 칸 0.40 이하")을 넘어서 같은 열의 같은 그림이 계속 null이 됩니다(로그 c1·c6).
   - 별 점수만으로는 여유가 없습니다.
3. **7열(오른쪽 끝) 선택 확인 실패.**
   - 게임에서는 선택됐습니다(214번 칸). 그런데 D-19 청록 띠를 읽지 못했습니다.
   - beta.4 보고에서도 JP 45 오른쪽 끝 열은 위치가 어긋났습니다. 열 간격(267px) 누적 오차로 오른쪽 열의 띠가 테두리에서 벗어나는 것으로 봅니다.

### D-23. 스크롤은 판별한 줄 수보다 적게 넘긴다
- 한 번 스와이프로 넘기는 거리는 "이번 쪽에서 완전히 판별한 줄 수 − 1" 줄 이하로 합니다. 최소 1줄이고, 실제로는 약 1.5~2줄(1440p 기준 400~560px)입니다.
- 겹쳐 다시 보이는 칸은 이미 선택되어 있으면 `selected=true`로 건너뜁니다. 그러니 겹침은 안전하고, 빠짐은 허용하지 않습니다.
- 맨 아랫줄도 라벨이 격자 안에 있으면 읽도록 `labelColumn`·`grid` 아래 경계를 맞춥니다.
- 스와이프 관성으로 더 넘어가는 것을 막는 방법(누른 채 멈춤 등)은 구현자가 정합니다.
- 검증: 쪽 사이 줄 연속성을 로그로 남깁니다. 이전 쪽 마지막 판별 줄의 칸이 다음 쪽에서 위쪽 판별 줄 또는 gridTop 아래에 다시 보여야 합니다. 이것을 단위 테스트나 기기 사례로 확인합니다.

### D-24. 등급은 테두리 색으로 먼저 나누고, 별은 그 안에서만 센다
- 칸 테두리 색은 그림이 섞이지 않습니다. 동색은 1·2★, 은색은 3★, 금색은 4·5★입니다. D-19와 같은 색 띠 방식으로 읽습니다.
- 선택된 칸은 테두리가 청록이므로 등급을 읽지 않습니다. 이미 선택된 칸은 건너뛰니 문제없습니다.
- 동색 안에서 1★/2★는 둘째 별 칸을 첫째 별 칸과 비교해 나눕니다(상대 비교). 금색 칸은 다섯째 별 칸이 확실히 비어 있을 때만 4★로 봅니다. 애매하면 null(선택 안 함)입니다.
- 은색은 3★로 확정합니다.
- 테두리 색이 동·은·금 어디에도 확실히 속하지 않으면 null입니다.
- COST 배지는 D-14대로 기준으로 쓰지 않습니다.

### D-25. 선택 띠 위치는 열마다 실제 테두리에 맞춘다
- 오른쪽 열에서도 띠가 테두리 위에 오도록 한 쪽 안에서 칸 왼쪽 테두리 x를 찾아 씁니다. 예: 라벨이나 칸 위치에서 역산, 또는 띠 탐색 범위를 넓힘.
- 47·48번 프레임의 선택된 칸(203~214)은 7열을 포함해 모두 `selected=true`, 미선택 칸은 `false`여야 합니다.

### 로그
- logcat 버퍼가 작아 앞쪽 로그가 사라집니다. 칸 한 줄씩 남기는 것은 유지합니다.
- 쪽마다 `rows=`(판별한 줄 y 목록)와 스와이프 거리를 추가합니다.
