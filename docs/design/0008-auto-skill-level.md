# 0008 스킬 자동 강화 (Auto Skill Level)

- 상태: 설계 (화면 자료 대기)
- 버전: 베타 **1.5.0-beta.1** (`1005001`)
- 대상 서버: **KR, JP** (EN·CN·TW는 이번 범위 아님)
- 기본 팀: 구현 Codex gpt-6.1-sol medium(한도 시 Sonnet 5.5 medium). 실제 게임 QA는 소유자가 지시할 때만.

## 1. 배경

FGO는 서번트 스킬 레벨을 올릴 때 **강화 → 스킬 강화**에서 서번트를 고르고, 스킬을 하나씩 눌러 확인창에서 강화를 반복합니다. 1→10까지 스킬 3개면 탭이 수십 번 필요합니다.

다른 FGA 포크(ArthurKun21의 FGA Preview)에 같은 기능("Auto Level Skills")이 있습니다. 하지만 **소스가 비공개**(`ArthurKun21/FGA-Preview`, 빌드 시 토큰으로 받음)이고 APK는 난독화되어 있습니다. 코드를 가져오지 않고, 공개 설명서(`docs/scripts/auto-level-skills.md`)의 **동작만 참고해 우리 구조로 새로 만듭니다.** 그 저장소의 코드·이미지는 복사하지 않습니다.

우리 포크에는 비슷한 틀이 있습니다.
- `scripts/.../entrypoints/AutoServantLevel.kt`: 강화 화면 스크립트. `ExitReason`, `ConnectionRetry` 사용 방식
- `scripts/.../entrypoints/AutoDetect.kt`: 화면을 보고 `ScriptModeEnum`을 고름
- `libautomata` OCR(`Region.detectText`, `OcrService.detectTextLine`)
- 서버별 템플릿 체계(`docs/agents/servers-and-assets.md`)

## 2. 목표 / 비목표

**목표**
- 스킬 강화 화면에서 서번트를 고른 상태로 시작하면, 스킬 1·2·3을 설정한 목표 레벨까지 자동으로 강화합니다.
- QP 부족·재료 부족을 감지해 멈추고, 스킬마다 시작 레벨·끝 레벨·멈춘 이유를 요약해 보여 줍니다.
- KR, JP를 지원합니다.

**비목표**
- 어펜드 스킬 강화(다음 단계 후보)
- 서번트 선택·재료 구매·QP 획득 같은 준비 작업
- 성정석·사과·상점 사용(어떤 경로로도 하지 않음)
- 스킬 레벨 10 이상(최대 10)

## 3. 결정 사항

### D-1. 설정은 스킬마다 "켜기 + 목표 레벨"
- 스킬 1·2·3 각각: 켜기/끄기, **목표 레벨**(2~10, 기본 10)
- 참고 포크는 "올릴 레벨 수"를 받지만, 우리는 **목표 레벨**로 받습니다. 이미 목표 이상이면 그 스킬은 건너뜁니다(사유 "이미 목표 레벨").
- 기본값은 세 스킬 모두 켬, 목표 10.

### D-2. 시작 조건과 자동 감지
- 시작 화면은 **스킬 강화 화면에 서번트가 선택된 상태**입니다.
- `AutoDetect`가 스킬 강화 화면 제목(배너)을 보면 새 `ScriptModeEnum.SkillLevel`을 고릅니다. 서번트 강화 화면(`ServantLevel`)과 겹치지 않아야 합니다.
- 서번트가 선택되지 않았으면 `NoServantSelected`로 정지합니다.

### D-3. 현재 레벨은 OCR로 읽고, 탭마다 다시 읽는다
- 스킬 아이콘 근처의 "Lv.N" 숫자를 OCR로 읽습니다(숫자 화이트리스트, 1~10만 유효).
- **강화 한 번마다 다시 읽어** 레벨이 1 올랐는지 확인합니다.
  - 올랐으면 계속합니다.
  - 안 올랐으면(탭이 씹힘) 한 번만 다시 시도합니다.
  - 그래도 안 오르면 그 스킬은 "레벨 확인 실패"로 멈추고 다음 스킬로 갑니다.
- 레벨을 읽지 못하면(OCR 실패) 그 스킬은 강화하지 않습니다. 모르는 상태로 탭하지 않습니다.

### D-4. 한 단계 흐름
1. 스킬 아이콘 탭 → 강화 확인창이 떴는지 확인합니다(템플릿).
2. 확인창의 결정/강화 버튼 탭 → 완료 연출 → 스킬 강화 화면 복귀를 확인합니다.
3. 레벨을 다시 읽습니다(D-3).
- 버튼은 템플릿으로 확인한 뒤에만 누릅니다. 0007 D-37처럼 화면 전환 뒤 짧게 기다렸다가 찾습니다.
- 대기 값은 상수 한 곳에 모읍니다(0007 `FpSellTiming`처럼).

### D-5. 자원 부족
- 확인창 대신 **QP 부족** 알림이 뜨면 그 스킬은 "QP 부족"입니다. 남은 스킬도 QP가 필요하므로 모두 "QP 부족으로 건너뜀"이고 스크립트는 정지합니다.
- **재료 부족** 알림(또는 강화 버튼 비활성)이 뜨면 그 스킬만 "재료 부족"으로 멈추고 다음 스킬로 갑니다. 스킬마다 재료가 다르기 때문입니다.
- 알림은 닫기 버튼으로 닫은 뒤 다음 단계로 갑니다.

### D-6. 잠긴 스킬
- 아직 열리지 않은 스킬(2·3번 잠금)은 "사용 불가"로 건너뜁니다.

### D-7. 종료 요약
- 정지 메시지에 스킬마다 `켜짐 / 시작 Lv / 끝 Lv / 목표 Lv / 이유`를 표시합니다.
- 이유: 목표 도달, 이미 목표 레벨, QP 부족, QP 부족으로 건너뜀, 재료 부족, 사용 불가, 레벨 확인 실패, 꺼짐
- 전체 종료 사유: 완료, 서번트 미선택, 수동 정지, 예기치 않은 오류
- `SkillLevel` 로그 태그(0007의 `FpSell`처럼)로 단계마다 한 줄씩 남깁니다.

### D-8. 안전
- 스킬 강화는 QP와 재료를 쓰는 되돌릴 수 없는 동작입니다. 설정한 목표 레벨을 **절대 넘지 않습니다.** 매 탭 전에 "현재 < 목표"를 다시 확인합니다.
- 화면을 모르면(확인창도 완료도 강화 화면도 아님) 탭하지 않고 정지합니다.

## 6. 검증 방법
- 단위 테스트·Main CI·기기 QA(고정 화면)로 검증합니다.
- **검증하지 않는 범위**: 실제 게임 강화는 QP·재료를 쓰므로 소유자가 직접 확인합니다. 권장 순서: 스킬 하나, 목표 = 현재 + 1로 첫 확인.

## 7. 위험과 대응
- **OCR 오판**: 목표를 넘으면 자원이 낭비됩니다. D-3 매 탭 재확인과 D-8 목표 초과 금지로 막습니다. 1~10 이외 값은 실패로 처리합니다.
- **탭 씹힘·연출 지연**: D-3의 한 번 재시도와 상수 대기로 대응합니다. 이중 강화를 막기 위해 레벨 확인 전에는 다음 탭을 하지 않습니다.
- **서버별 화면 차이**: KR·JP 템플릿과 사례를 각각 둡니다.

## 8. 소유자에게 받을 화면 (KR·JP 각각, 블루스택 창 캡처면 충분)
1. 강화 메뉴에서 **스킬 강화** 들어가기 직전 메뉴
2. **서번트 선택 전** 스킬 강화 화면
3. **서번트 선택 후** 스킬 강화 화면. 스킬 3개 레벨이 보이게, 가능하면 레벨이 서로 다른 서번트(예: 1·4·10)
4. 스킬 아이콘을 눌렀을 때 뜨는 **강화 확인창**(필요 재료·QP·버튼이 보이게)
5. 강화 **완료 연출/결과 화면**과, 그 뒤 돌아온 화면
6. **QP 부족** 알림
7. **재료 부족** 알림 또는 버튼이 비활성인 확인창
8. 스킬 2·3이 **잠긴** 서번트 화면(있으면)
9. **레벨 10**(최대) 스킬을 눌렀을 때의 화면

## 9. 소유자 화면과 결정 (2026-10-19, 1차) — 이 절이 앞 절보다 우선

자료: `build/orchestration/inputs/0008/01~09-jp.webp`. JP, BlueStacks 창 캡처 2000×1147, 창 테두리 포함.

| 번호 | 화면 |
|---|---|
| 01 | 스킬 강화, 서번트 선택 전 (`閉じる`, "タッチして強化するサーヴァントを選択してください") |
| 02, 03 | 스킬 강화, 서번트 선택 후 (`強化メニューに戻る`, `サーヴァント再選択`, 스킬 3칸 `Lv. N/10`, 오른쪽 아래 `強化する`) |
| 04 | 강화 확인창: 스킬 이름, **`Lv.4 › Lv.5`**, 필요 QP, `キャンセル` / `決定`, `confirmation` 워터마크 |
| 05 | 결과: `スキルレベルアップ`, "画面をタッチしてください" |
| 06 | 결과를 탭한 뒤 스킬 강화 화면으로 복귀 |
| 07 | 선택한 스킬이 10/10이면 버튼이 빨간 글씨 `これ以上強化できません` |
| 08 | 어펜드 강화, 서번트 선택 후: 5칸. 잠긴 칸은 자물쇠, 레벨은 아이콘 위에 작게 `Lv.10/10`. 잠긴 칸을 고르면 버튼이 `解放する` |
| 09 | 어펜드 강화, 서번트 선택 전 |

소유자 설명:
- `強化する` 글씨는 계속 조금씩 커졌다 작아졌다 합니다.
- 연출 중 화면을 반복해서 탭하면 스킵됩니다. 결과 화면은 아무 데나 탭하면 복귀합니다.
- 재료가 부족하면 별도 창 없이 버튼이 눌리지 않습니다. 참고: 다른 포크의 자료로 보면, JP는 위쪽 안내 줄에 빨간 `必要アイテムが足りません` / `QPが足りません!`가 뜹니다.

### D-9. 범위: 스킬 + 어펜드 (D-1·D-6 보강)
- **스킬**(3칸)과 **어펜드**(5칸)를 모두 지원합니다. 두 스크립트의 흐름은 같습니다.
- 설정은 칸마다 **목표 레벨**(스킬 1~10, 어펜드 1~10)입니다. "끔"은 목표 0 또는 스위치로 표현합니다(구현자가 UI를 정함). 기본값은 끔입니다. 실수로 자원을 쓰지 않게 하기 위해서입니다.
- **잠긴 어펜드 칸은 해제하지 않고 건너뜁니다**(소유자 결정). 사유는 "잠김"입니다. `解放する` 버튼은 어떤 경우에도 누르지 않습니다.

### D-10. 시작과 설정 창 (D-2 대체)
- `AutoDetect`는 스킬 강화 제목(`サーヴァントスキル強化` / KR 대응)이 보이면 `SkillLevel`, 어펜드 강화 제목(`アペンドスキル強化`)이 보이면 `AppendLevel`을 고릅니다.
- **서번트 선택 여부**는 왼쪽 위 `サーヴァント再選択` 버튼으로 판단합니다. 선택 전 화면(01·09)은 `閉じる`만 보입니다.
  - 선택 전이면 설정 창 없이 "서번트를 먼저 선택하세요"로 끝냅니다. 소유자 결정: 선택 전 화면에는 기능을 넣지 않습니다.
- 시작 버튼을 누르면 설정 창이 뜹니다(스킬 3줄 / 어펜드 5줄, 목표 레벨). 확인을 누르면 실행합니다. 설정값은 저장해 다음에 기본값으로 씁니다.

### D-11. 레벨은 확인창에서 읽는다 (D-3 대체)
스킬 화면의 `Lv. N/10`이나 어펜드 아이콘 위 숫자는 읽지 않습니다. 대신 **확인창의 `Lv.현재 › Lv.다음`**을 읽습니다. 서버·스킬 종류와 무관하게 크고 선명합니다.

한 칸의 반복:
1. 칸 아이콘을 탭합니다(선택). 어펜드의 잠긴 칸은 D-9대로 건너뜁니다. 잠김은 자물쇠 템플릿 또는 버튼 `解放する`로 판단합니다.
2. 1초 뒤 `強化する` **위치를 탭**합니다. 버튼 글씨가 움직이므로 버튼 템플릿 매칭으로 판단하지 않습니다.
3. 최대 2초 안에 **확인창**(`confirmation` 워터마크 + 결정 버튼)이 뜨는지 봅니다.
   - 안 뜨면 이 칸은 "강화 불가"입니다(최대 레벨, 재료 부족, QP 부족). 가능하면 사유를 구분합니다: 버튼 `これ以上強化できません` 템플릿 → 최대, 위쪽 빨간 문구 → 재료/QP. 구분이 안 되면 "강화 불가"로 다음 칸으로 갑니다.
4. 확인창이 뜨면 `Lv.현재`를 OCR로 읽습니다. 숫자만, 1~9만 유효합니다. 확인창이 떴다면 10은 아닙니다.
   - 못 읽으면 **キャンセル** 후 이 칸은 "레벨 확인 실패"로 다음 칸으로 갑니다.
   - `현재 ≥ 목표`면 **キャンセル** 후 다음 칸으로 갑니다(목표 도달).
   - `현재 < 목표`면, 직전 확인창의 현재 레벨보다 정확히 1 높은지(첫 회는 생략) 확인합니다. 맞으면 **決定**을 누릅니다.
   - 같은 레벨이 다시 나오면(직전 決定이 반영 안 됨) 決定 없이 キャンセル하고 "레벨 확인 실패"로 다음 칸으로 갑니다. 이중 강화를 막기 위해서입니다.
5. 決定 뒤에는 **스킵 탭**을 반복합니다. 탭 자리는 오른쪽 위 제목 영역입니다. 스킬 화면에서 눌러도 반응이 없는 자리입니다. 스킬 강화 화면(`サーヴァント再選択` + 제목)이 다시 보일 때까지 0.5초 간격, 최대 20초 반복하고, 넘으면 정지합니다.
6. 1로 돌아갑니다.
- 각 칸은 설정한 목표를 **절대 넘지 않습니다.** 4번에서 매회 확인합니다.
- QP 부족은 별도 연쇄 처리가 없습니다. 이후 칸도 확인창이 안 떠서 자연히 넘어갑니다.

### D-12. 종료 요약 (D-7 보강)
- 칸별 결과: `시작 Lv(첫 확인창의 현재 레벨) → 끝 Lv / 목표 / 사유`
- 사유: 목표 도달, 강화 불가(최대·재료·QP, 구분되면 표시), 잠김, 레벨 확인 실패, 끔
- 로그 태그는 `SkillLevel`입니다.

### D-13. 다른 포크 자료는 쓰지 않는다
FGA Preview APK의 템플릿은 복사하지 않습니다. 그 저장소에는 라이선스 표시가 없습니다. 모든 템플릿은 소유자 화면에서 직접 자릅니다. 확인창 방식이면 1~10 숫자 이미지는 필요 없습니다.

### D-14. 잠긴 어펜드를 실수로 해제하지 않는 이중 장치 (D-9 보강)
- 13번처럼 **잠긴 칸이 선택된 상태에서 버튼 자리를 누르면 `해방`/`解放する`(해제)가 눌립니다.**
- 그래서 어펜드 칸마다 버튼을 누르기 **전에** 다음 두 가지를 모두 확인합니다.
  1. 그 칸 아이콘에 **자물쇠가 없음**: 자물쇠 템플릿, 서버 공통
  2. 그 칸을 탭한 뒤 **버튼이 해방/解放する가 아님**: 버튼 글자 템플릿 KR/JP. 글씨가 움직이므로 낮은 기준으로 "해방이면 건너뜀"
  - 하나라도 걸리면 그 칸은 "잠김"으로 건너뜁니다.
- 확인창에서도 한 번 더 막습니다. 확인창 `Lv.현재`가 **0이거나 읽히지 않으면** 결정을 누르지 않고 취소합니다. 해제 확인창은 0→1로 보일 것으로 봅니다. 확인창 제목이 강화(`スキル強化`/`스킬 레벨업`) 계열이 아니어도 취소합니다.
- 스킬(일반) 화면에는 잠금이 없으므로 이 확인은 어펜드에만 적용합니다.

## 11. 어펜드 자료와 구현 확정 (2026-10-19, 3차)

자료: `build/orchestration/inputs/0008/17~24`

| 번호 | 화면 |
|---|---|
| 17-kr | 어펜드 강화 확인창: 제목 `어펜드 스킬 강화`, 스킬 이름, **`Lv.5 › Lv.6`**, `취소` / **`확인`**(스킬 확인창은 `결정`), `confirmation` |
| 18-jp | 어펜드 강화 확인창: `アペンドスキルの強化`, **`Lv.1 › Lv.2`**, `キャンセル` / `決定` |
| 19-kr, 20-jp | 어펜드 결과 `어펜드 스킬 강화` / `アペンドスキル強化` `APPEND SKILL UP`, "화면을 터치해 주세요" |
| 21-jp, 24-kr | 잠긴 칸이 선택된 상태, 버튼 `解放する` / `해방`, 위쪽 안내 줄 "「解放する」ボタンを…" / "'해방' 버튼을…" |
| 22-jp, 23-kr | 코인 부족: 위쪽 안내 줄이 **빨간 글씨** `必要なサーヴァントコインが足りません` / `서번트 코인이 부족합니다`, 버튼은 회색 |

확인 사항:
- 확인창은 스킬과 어펜드가 **같은 배치**입니다. `Lv.현재 › Lv.다음`, 오른쪽 결정 버튼 위치, `confirmation`이 같습니다. 오른쪽 버튼 글씨만 KR 어펜드는 `확인`이고 나머지는 `결정`/`決定`입니다. 버튼은 **위치로 누르고**, 확인창 판별은 `confirmation`으로 합니다. 버튼 글씨 템플릿은 쓰지 않습니다.
- 위쪽 안내 줄은 상태를 알려 줍니다. 강화 가능할 때는 "「強化する」ボタン…" / "'강화' 버튼…"이고, 잠김은 "해방" 안내, 부족은 빨간 글씨입니다. D-11 3번과 D-14의 판단에 **이 안내 줄을 1차 신호**로 씁니다.
  - "강화" 안내 → 버튼 탭 진행
  - "해방" 안내 → 잠김, 건너뜀
  - 빨간 글씨 → 부족, 건너뜀
  - 그 밖(최대 레벨 등) → 버튼을 탭하고 확인창 여부로 판단
  - 서버별 템플릿(KR/JP)은 안내 줄 왼쪽 글자 일부에서 자릅니다.
- 결과 화면은 스킬·어펜드 모두 "화면을 터치"로 닫힙니다. D-11 5번 스킵 탭을 그대로 씁니다.

## 12. 첫 실제 실행 (2026-10-19, beta.2 → 1.5.0-beta.3)

### D-15. 대기 추가 (소유자 결정)
