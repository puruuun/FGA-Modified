# 0017 주간 루트 목록 스크롤: 스크롤 막대로 끝 판단 (2026-10-23 소유자 요청)

- 상태: 설계
- 버전: 1.6.2-beta.7 / 1006207
- 대상: `WeeklyRouteDriver.scanList`. 홈 화면, 메인 레코드 목록, 메인 인터루드 목록에서 장 배너·버튼을 찾을 때 쓰는 스크롤입니다.

## 지금 동작과 문제
- `scanList`는 먼저 현재 화면에서 찾습니다. 없으면 `ListSearchDirection.entries` 순서(Down → Up)로 **방향마다 최대 14번(`MAX_LIST_SCROLLS`)** 스크롤하며 찾습니다.
- 끝에 닿았는지는 보지 않습니다. 그래서 지도에서 돌아왔을 때 목록이 **이미 맨 아래**이면, 아래쪽 탐색 14번이 화면을 전혀 움직이지 못한 채 낭비됩니다(소유자 관찰). 위쪽 탐색도 같은 문제가 생길 수 있습니다.
- 이 화면들에는 오른쪽에 **스크롤 막대**가 있어 현재 위치(맨 위, 중간, 맨 아래)를 알 수 있습니다.

## D-1. 스크롤 막대로 끝 판단
- 각 목록의 스크롤 막대 영역(세로 홈과 손잡이)을 찾아 손잡이의 위치 비율을 읽습니다. 비율은 0(맨 위)에서 1(맨 아래)입니다.
  - 손잡이는 밝은 세로 막대이고 홈은 어둡습니다. 열 방향 밝기 프로필로 손잡이의 위·아래 끝을 찾습니다. 위치는 화면 비율에 맞게 `xFromRightEdge`나 `isWide` 규칙을 따릅니다(0012).
- 탐색 순서
  1. 현재 화면에서 찾습니다(지금과 같음).
  2. 손잡이가 **맨 아래**면 아래쪽 탐색을 건너뛰고 위쪽만 합니다. **맨 위**면 위쪽 탐색을 건너뜁니다.
  3. 스크롤할 때마다 손잡이를 다시 읽고, 끝에 닿으면 그 방향 탐색을 바로 멈추고 다음 방향으로 넘어갑니다. 끝에 닿은 그 화면에서도 찾기는 한 번 합니다.
  4. 14번 상한은 안전장치로 남깁니다.
- 손잡이를 읽지 못하면(막대가 없는 화면, 판독 실패) 지금 방식대로 동작합니다.

## D-2. 보조 판단: 화면이 안 움직이면 끝
- 스크롤 전후 목록 영역 이미지가 거의 같으면(움직임 없음) 그 방향은 끝으로 봅니다. 스크롤 막대를 읽지 못하는 경우에도 낭비를 막는 장치입니다.
- 둘 다 끝을 가리킬 때만 쓰는 게 아니라, **둘 중 하나라도 끝을 확실히 가리키면** 그 방향을 멈춥니다. 막대 판독이 끝이라고 했는데 화면이 움직였다면 막대 판독을 믿지 않습니다(로그를 남김).

## 로그
- `WeeklyRoute` 태그에 스크롤마다 `scrollbar=0.00–1.00 | unknown`, `moved=true/false`, 방향 전환과 건너뛴 이유를 남깁니다.

## 검증
- 기존 소유자 캡처의 홈·목록 화면에서 손잡이 위치를 판독하는 기기 QA 케이스를 넣습니다. JP·KR, 16:9와 와이드를 포함합니다.
  - 캡처: `build/orchestration/inputs/0009/02,03,12,24,25,35–38`, `inputs/0012-wide/23,24`, `docs/reference-images/{Jp,Kr}/weekly-route/`
  - 맨 위·중간·맨 아래 사례가 모자라면 기획자에게 필요한 화면을 요청합니다. 지금은 게임 점검 중이라, 요청 화면은 점검 후 소유자가 찍습니다.
- 단위 테스트를 넣습니다.
  - 맨 아래 시작 → 위쪽만 탐색
  - 맨 위 시작 → 아래쪽만 탐색
  - 중간 시작 → 아래 끝 도달 후 위로 전환
  - 막대 판독 실패 → 기존 동작
  - 화면이 움직이지 않으면 멈춤
- 기존 weeklyRoute 기기 QA는 전부 통과해야 합니다.
