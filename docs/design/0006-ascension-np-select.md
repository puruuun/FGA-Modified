# 0006 재림구분기능 (보구 이름으로 서포트 구분)

- 상태: 구현 대기
- 선행: 0002(기기 검사), 0003(버전 파일)
- 버전: 베타 **1.3.0-beta.1** (`1003001`). 정규판 값은 그대로 둡니다.
- 예상 규모: 이미지 종류 1개 추가, 선택 조건 1개 추가, 서포트 이미지 메이커와 이름 지정 화면 확장, 설정 UI, 기기 검사 케이스

## 1. 배경

서포트 목록의 각 행에는 서번트 이름 아래에 **보구 줄**(카드 아이콘 + 보구 이름 + `Lv.N`)이 있습니다. 일부 서번트는 재림 단계에 따라 보구 이름이나 카드 종류가 바뀝니다. 예를 들어 メリュジーヌ는 「今は知らず、無垢なる湖光」(Arts)와 「誰も知らぬ、無垢なる鼓動」(Buster)로 나뉩니다. 재림에 따라 스킬도 달라지므로, 소유자는 **특정 재림의 서포트만 고르는 기능**을 원합니다.

현재 서포트 이미지 메이커(`SupportImageMaker`)는 서번트, 예장, 친구 이름만 잘라 저장합니다. 선호 서포트 조건도 이 세 가지뿐입니다.

**레이아웃 차이.** 행이 **그랜드 서번트**이면 왼쪽에 예장 3칸 열(`概念礼装`)이 붙어서 보구 줄이 오른쪽으로 밀립니다(1920 폭 기준 보구 칸 시작이 약 580px). 일반 행은 보구 칸이 약 360px에서 시작합니다. FGA는 이미 행마다 그랜드 여부를 판별합니다(`SupportSelectionGrandChecker`, `SupportImageMaker.isGrandServant`). 보구 레벨 판독기(`SupportNpLevelReader`)는 두 레이아웃을 모두 덮는 가로 띠(`SupportNpLayout.nameRegion`) 안에서 `Lv.` 위치를 찾는 방식으로 이미 양쪽에서 동작합니다.

소유자 화면에서 확인한 점: 같은 보구(オルガマリー 「すでに過ぎし人理の終」)가 그랜드 행과 일반 행에서 **같은 글자 크기와 폭**으로 표시됩니다.

## 2. 목표 / 비목표

**목표**
- 서포트 이미지 메이커가 각 행의 **보구 이름 이미지**도 잘라 저장하고, 이름 지정 화면에서 다른 이미지와 같은 방식으로 이름을 붙여 저장할 수 있게 합니다.
- 선호 서포트 설정에 **"재림 구분 (보구 이름)"** 목록을 추가합니다. 서번트 조건을 통과한 후보 중, 선택한 보구 이미지가 그 행의 보구 줄에 있는 후보만 통과합니다.
- 그랜드 행과 일반 행, 친구 코멘트가 있는 행과 없는 행 모두에서 동작합니다.
- JP·KR 모두 동작합니다. 이미지는 사용자가 자기 서버 화면에서 만듭니다.

**비목표**
- 문자 인식(OCR). 이미지 매칭만 씁니다.
- 보구 이름이 같은 재림의 구분. 이 방법의 한계로, 설정 화면 안내에 적습니다.
- 내장 보구 이미지 제공, 원본 FGA 가져오기 대상 추가, 서번트 번호 이미지 생성기와의 연동.
- 보구 레벨 조건 변경. 기존 보구 레벨 판독은 그대로 둡니다.

## 3. 결정 사항

- **D-1. 판독은 "넓게 찾기" 방식입니다.** 보구 줄이 나올 수 있는 가로 띠 전체에서 보구 이미지를 템플릿 매칭으로 찾습니다. 레이아웃을 판별해 위치를 옮기는 방식은 쓰지 않습니다. 매칭은 띠 안에서 가장 잘 맞는 자리의 점수만 보므로, 띠 안에 예장 그림 등 다른 요소가 있어도 결과에 영향이 없습니다.
  - 띠의 세로 범위는 `SupportNpLayout.nameRegion`과 같습니다. 친구 코멘트 유무를 이미 포함하는 범위입니다.
  - 가로 범위는 `nameRegion`을 왼쪽으로 넓혀 **두 레이아웃의 카드 아이콘이 모두 들어오게** 합니다. 정확한 값은 [`docs/agents/coordinates.md`](../agents/coordinates.md)를 지켜 fixture로 정하고, 상수 이름과 근거를 `SupportNpLayout`에 주석으로 남깁니다.
- **D-2. 보구 이미지는 "카드 아이콘부터 `Lv.` 바로 앞까지"입니다.** `Lv.N`과 보구 강화 표시(▲)는 넣지 않습니다. 같은 재림인데 보구 레벨만 달라도 이미지가 달라지기 때문입니다.
  - 오른쪽 끝: 기존 `Images.SupportNpLevelPrefix` / `SupportNpLevelPrefixGold`(서버별, JP는 기본 서버 대체 포함)로 `Lv.` 위치를 찾고, 그 왼쪽 몇 px까지 자릅니다. `SupportNpLevelReader`가 템플릿을 고르는 방식을 그대로 재사용합니다.
  - 왼쪽 끝: 행이 그랜드인지(`isGrandServant`)에 따라 카드 아이콘 왼쪽 위치 상수 두 개 중 하나를 씁니다.
  - 위아래: `Lv.` 매칭 영역의 높이를 기준으로 글자가 잘리지 않을 만큼만 여백을 둡니다. 파란 보구 칸 바깥(예장 그림, 서번트 이름 줄)은 포함하지 않습니다.
  - `Lv.`를 찾지 못한 행은 보구 이미지를 저장하지 않고 넘어갑니다(서번트·예장 이미지는 지금처럼 저장).
- **D-3. 이미지 종류와 저장 위치.** `SupportImageKind.NoblePhantasm`을 추가하고, 저장 폴더는 서포트 이미지 폴더 아래 `np/`입니다. 한 항목에 여러 장을 둘 수 있게 서번트·예장과 같은 하위 폴더 규칙(`이름/파일.png`)을 지원합니다. 레이아웃별로 이미지가 다르게 보이는 경우를 대비한 것입니다.
- **D-4. 설정.** `ISupportPreferences.preferredNoblePhantasms: List<String>`, 저장 키 `support_pref_np_list`(stringSet). 비어 있으면 조건을 적용하지 않습니다(항상 통과).
- **D-5. 판정 순서.** `PreferredSupportSelection.isMatch`에서 **서번트 → 보구(재림) → 점수 → 예장 → 친구** 순서로 검사합니다. 보구 매칭은 비용이 작고, 뒤의 점수 OCR을 줄여 줍니다.
  - 선택 기록: 행마다 `ScriptLog.SupportNoblePhantasm(matched, 최고 점수)`를 남깁니다(태그 `FGA.SupportNp`, INFO). 진단과 실기 확인에 씁니다.
  - `SupportSelectionPreferredNotSet` 판정에는 보구 목록도 "설정됨"으로 포함합니다.
- **D-6. 유사도.** 상수 `NP_NAME_SIMILARITY = 0.85`에서 시작합니다. fixture 결과로 조정하되 **0.80 아래로 내리지 않습니다.** 낮춰야만 통과한다면 이미지 자르는 방식을 의심하고 보고합니다.
- **D-7. 가로 압축 대비.** 긴 보구 이름이 좁은 그랜드 행에서 가로로 눌려 표시될 가능성이 있습니다. 1차 구현은 **배율 1.0만** 씁니다. fixture에서 같은 보구가 레이아웃에 따라 맞지 않는 사례가 나오면, 그때 가로 배율 `[1.0, 0.95, 0.9, 0.85]` 검색을 추가하고 그 근거를 보고합니다. 사용자는 D-3의 여러 장 저장으로도 대응할 수 있습니다.
- **D-8. UI 문구(한국어 기준).** 기능 이름 "재림 구분 (보구 이름)". 안내: "서포트 이미지 메이커로 만든 보구 이름 이미지로 재림을 구분합니다. 재림이 달라도 보구 이름과 카드가 같으면 구분할 수 없습니다."

- 단위 테스트(`scripts/src/test`): 목록이 비면 통과, 하나라도 맞으면 통과, 모두 낮으면 탈락, 판정 순서(보구가 탈락하면 점수 판독기를 부르지 않음), `SupportSelectionPreferredNotSet` 갱신.

  - 보구 이미지 템플릿은 fixture 화면에서 D-2 규칙으로 잘라 만들고, 자른 좌표를 케이스 파일에 남깁니다(이미지 메이커와 같은 규칙을 쓰는지 확인하는 의미).

## 8. 수정 — 서번트 이름 줄까지 포함 (2026-10-18, 소유자 요청 → 1.3.0-beta.2)

### 배경
소유자 실기 확인: 보구 이름이 같아도 재림이 다른 경우가 있습니다. メリュジーヌ의 예는 다음과 같습니다.

| 재림 | 서번트 줄 | 보구 줄 |
|---|---|---|
| 1차 | 妖精騎士ランスロット | 今は知らず、無垢なる湖光 (Arts) |
| 2차 | メリュジーヌ | 今は知らず、無垢なる湖光 (Arts) |
| 3차 | メリュジーヌ | 誰も知らぬ、無垢なる鼓動 (Buster) |

1→2차는 서번트 표시 이름만, 2→3차는 보구만 바뀝니다. 그래서 **서번트 줄과 보구 줄을 한 장으로 묶은 이미지**여야 세 재림을 모두 구분할 수 있습니다.

### 결정 (D-2, D-1을 아래로 대체)
- **D-9. 이미지 범위: 파란 패널의 "서번트 줄 + 보구 줄" 두 줄 블록.**
  - 가로: 기존과 같이 카드 아이콘 왼쪽(그랜드/일반 상수)부터 보구 줄 `Lv.` 바로 앞까지. 서번트 줄도 같은 가로 범위로 자릅니다(서번트 이름이 이 폭보다 길면 잘린 채로 저장. 같은 재림이면 항상 같게 잘리므로 문제없음).
  - 세로: 서번트 줄 글자 위쪽부터 보구 줄 글자 아래쪽까지. 서번트 줄의 위치는 보구 줄 `Lv.` 위치에서 **위로 한 줄 간격**(상수 `NAME_LINE_OFFSET`, fixture로 측정)입니다. 두 줄은 같은 패널 안에서 함께 움직이므로, 친구 코멘트 유무나 그랜드 여부에 따라 간격이 바뀌지 않습니다. fixture로 이 가정을 확인합니다.
  - 패널 바깥(친구 이름·코멘트·예장 그림)은 넣지 않습니다.
- **D-10. 검색 띠를 위로 한 줄 넓힙니다.** `noblePhantasmBand`의 세로 범위를 서번트 줄까지 덮도록 늘립니다(위로 `NAME_LINE_OFFSET` + 여백). 가로 범위는 그대로입니다.
- **D-11. 이전 이미지와의 호환.** 1.3.0-beta.1에서 만든 보구 줄만의 이미지도 넓어진 띠 안에서 그대로 찾을 수 있으므로 동작은 유지됩니다. 이름 지정 화면과 안내에는 "보구만 있는 이미지는 1·2차처럼 보구가 같은 재림을 구분하지 못하니 다시 만드세요"라고 적습니다. 저장 폴더와 설정 키는 바꾸지 않습니다.
- **D-12. UI 이름**: "재림 구분 (서번트 이름 + 보구)". 안내 문구도 맞춰 고칩니다. 妖精騎士ランスロット/メリュジーヌ 예시는 이제 서번트 선호 없이도 구분되지만, 다른 서번트와 겹치지 않도록 서번트 선호와 함께 쓰기를 계속 권장합니다.

## 9. 수정 — 서버 접두어, 문구 정리, 레이아웃 확인 (2026-10-18, 소유자 요청 → 1.3.0-beta.3)

- **D-13. 재림 이미지 이름에 서버 접두어를 붙입니다.** 이름 지정 화면에서 사용자가 `멜뤼진`만 입력하면, 저장 이름은 그 시점의 게임 서버(`prefs.gameServer`, 자동 감지 포함)에 따라 `JP) 멜뤼진` / `KR) 멜뤼진`이 됩니다. 사용자가 이미 `JP) …`처럼 접두어를 쓴 경우에는 중복해서 붙이지 않습니다. 선호 설정 목록에도 이 이름이 그대로 보입니다. 접두어는 표시용이며 판정 시 서버로 걸러 내지는 않습니다. 대상은 **재림(NoblePhantasm) 이미지만**입니다(서번트·예장·친구 이미지는 서버 공통 그림이고 기존 설정과 호환을 지키기 위해 그대로 둡니다).
- **D-14. 같은 이름으로 다시 저장하면 같은 항목에 이미지가 추가됩니다.** 덮어쓰지 않고 `JP) 멜뤼진/` 폴더 안에 새 파일로 넣습니다(D-3의 여러 장 규칙). 판정은 그 안의 이미지 중 하나라도 맞으면 통과입니다.
- **D-15. 문구 삭제.**
  - 선호 설정의 재림 구분 안내(`p_battle_config_support_pref_nps_hint`)에서 "보구 이름만 있는 예전 … 함께 고르세요." 부분을 삭제하고 첫 문장만 남깁니다(en/ko/ja 모두).
  - 서포트 이미지 메이커 이름 지정 화면 안내(`support_img_namer_np_hint`)를 삭제합니다(문자열과 표시 모두. en/ko/ja).
- **D-16. 그랜드 행(예장 3칸으로 오른쪽으로 밀린 행)과 일반 행에 같은 이미지가 쓰이는지 확인합니다.** 설계상 이미지는 파란 패널 안쪽만 자르므로 한 장으로 양쪽에 맞아야 합니다. 소유자가 보낸 화면 `build/orchestration/inputs/0006-r3/*.webp`(블루스택 창 캡처, 상단 창 테두리 포함)와 지금 블루스택 화면 캡처로:
  1. 일반 행의 카드 아이콘 위치 `NORMAL_ICON_X`를 실측합니다(지금까지 추정값 528).
  2. 일반 행에서 D-9 규칙으로 자른 블록과 그랜드 행에서 자른 블록의 크기·배경이 같은지 비교합니다. 같은 서번트·재림이 양쪽에 다 있는 화면이 없으면, 일반 행에서 자른 블록이 그랜드 행 띠에서(반대도) 같은 서번트 블록과 0.85 이상으로 맞을 조건(크기, 패널 배경, 왼쪽 여백)이 같은지 근거를 보고합니다.

### D-17. 레이아웃별 글자 눌림 검증과 자르기 시작점 (2026-10-18, D-16 보강)
소유자 지적: 그랜드 행은 패널이 좁아서 글자가 눌려 보입니다. 비교 화면 `build/orchestration/inputs/0006-r3/14-owner-compare.png`를 보면, 위(그랜드) 행의 `サーヴァント` 라벨이 아래(일반) 행보다 확실히 좁고, 라벨과 이름 사이 간격도 다릅니다. 보구 이름 글자는 비슷한 폭으로 보입니다.

**같은 서번트·같은 재림이 두 레이아웃에 모두 있는 쌍**: `4-grand-olga.webp`(그랜드, オルガマリー・アニムスフィア / すでに過ぎし人理の終 Lv.5)와 `8.webp`(일반, 같은 서번트 / 같은 보구 Lv.2).

검증 순서:
1. 두 화면을 같은 배율(게임 영역 720p)로 맞춘 뒤, 다음 폭을 px로 잽니다: `サーヴァント` 라벨, 서번트 이름 글자열, `宝具` 라벨, 카드 아이콘, 보구 이름 글자열, 아이콘 끝에서 글자 시작까지의 간격.
2. 자르기 두 가지를 비교합니다.
   - (가) 지금 방식: 카드 아이콘 왼쪽부터 `Lv.` 앞까지(서번트 줄은 라벨 끝부분이 섞임)
   - (나) **글자 시작부터**: 아이콘 오른쪽 끝(= 서번트 이름·보구 이름 글자가 시작하는 x)부터 `Lv.` 앞까지. 라벨과 아이콘은 넣지 않습니다.
   - 각 방식으로 그랜드 쪽에서 자른 이미지를 일반 행 띠에서, 일반 쪽에서 자른 이미지를 그랜드 행 띠에서 찾았을 때의 **교차 유사도**를 보고합니다. 자기 화면 유사도와 다른 서번트 최고값도 함께 적습니다.
3. 판정:
   - **이름·보구 글자 자체의 폭이 같으면(720p 기준 ±1px)**, 차이는 라벨과 간격뿐입니다. → 자르기를 (나)로 바꾸고, 교차 유사도가 0.95 이상이면 **한 장으로 충분**합니다. 안내는 추가하지 않습니다.
   - **글자 자체가 눌려 있으면(폭 차이 2px 이상, 또는 (나)의 교차 유사도 < 0.90)**: 한 장으로 두 레이아웃을 커버하려고 가로 배율 검색을 넣지 **않습니다**(다른 재림을 잘못 맞힐 위험이 커짐). 대신 레이아웃별로 따로 저장합니다. D-14(같은 이름은 한 항목에 묶임)를 그대로 쓰고, 위키 안내와 이름 지정 화면에 **짧은 한 줄**을 넣습니다: "그랜드 서번트 행과 일반 행은 글자 폭이 달라 각각 저장해야 합니다(같은 이름으로 저장하면 하나로 묶입니다)."
   - 그 사이(0.90~0.95)면 (나)로 바꾸되 위키에만 "인식이 안 되면 두 화면에서 각각 저장" 안내를 넣고, 수치를 보고합니다.
4. (나)로 바꾸면 기존 1.3.0-beta.1·2 이미지(아이콘 포함)도 넓은 띠 검색으로 계속 맞는지 확인합니다. 맞지 않으면 그 사실을 보고하고, 소유자에게 이미지를 다시 만들도록 위키에 적습니다.
