# 0013 소유자 창 캡처 점수 판독 감사

- 상태: **라벨·정규화·QA 준비 완료, 기기 측정 차단 — 감사 미완료**.
- 기준: 1.6.2-beta.1 제품 리더 `aefa6bcb`, 작업 시작 main `bc74a419`.
- 입력: `build/orchestration/inputs/0013-score/owner-window/162.webp`부터 `196.webp`까지 35장.
- 직접 판독하고 점수 확대 크롭과 다시 대조한 완전 노출 행: **70행**. 화면 상하에서 일부가 잘린 행은 제외했습니다.
- JP 40행, KR 30행. 일반 점수 50행, 복합 점수 20행. 중복 서포트·동일 점수도 서로 다른 캡처 행으로 셉니다.
- 제품 코드·이미지 템플릿·판독 임계값·버전은 변경하지 않았습니다.

## 입력에서 확인한 화면 종류

**35장 모두 일반 스킬 화면입니다.** `고유 스킬` 또는 `固有スキル` 아래 레벨 아이콘이 3개씩 있습니다. 그 위의 5개 아이콘은 커맨드 카드입니다. 어펜드 아이콘 5개와 레벨·잠금이 나열된 화면은 없습니다. 따라서 어펜드 레벨 라벨과 어펜드 정확도는 이 입력으로 측정할 수 없습니다.

현재 `SupportSkillLevelReader.read(bounds, append)`의 반환형은 `List<Boolean>`이며 각 슬롯이 10인지 여부만 반환합니다. 9·4·잠금의 구분이나 실제 숫자 레벨은 제공하지 않습니다. 어펜드 표본이 확보되면 실제 레벨 라벨에서 `level == 10` 배열을 만들고 제품 배열과 비교하며, `matches(listOf(true,true,false,false,false), detected)`로 `10/10/x/x/x` 조건을 검증해야 합니다.

## 정규화와 라벨

[labels.json](../reference-images/support-score-audit/labels.json)에 각 원본의 크기·게임 크롭 사각형·정규화 크기와 행별 서버·행 번호·720p Y·화면 종류·점수 표시·두 숫자를 기록했습니다. `rowIndex`는 완전 노출 행 사이의 1 기반 번호이고, `screenRowIndex`는 잘린 행까지 포함한 화면상의 번호입니다.

좌표는 `[left, top, right, bottom)`입니다. 창 상단 바와 오른쪽 툴바를 제거했고, 1832×1164 입력은 위아래 장식 레터박스도 제거했습니다. 색상 게임 프레임을 OpenCV `INTER_AREA`로 높이 720, 너비 `floor(cropWidth × 720 / cropHeight)`로 정규화했습니다. QA는 이 PNG를 흑백으로 읽습니다. 확대·선명화·합성 숫자는 사용하지 않았습니다. 창에서 이미 리스케일된 이미지이므로 실제 MediaProjection 캡처의 정확도로 일반화할 수 없습니다.

## 기기 기준 측정 시도와 차단 근거

허용된 `127.0.0.1:5555`만 대상으로 삼았습니다. 다른 기기에 명령을 보내거나 게임을 조작하지 않았습니다. SDK adb는 `C:/Users/rl/AppData/Local/Android/Sdk/platform-tools/adb.exe`입니다.

- `127.0.0.1:5555` 연결 시도: TCP 연결 거부(10061).
- BlueStacks 설정에서 `Pie64`의 ADB 포트가 5555임을 확인했으나 실행 중인 `HD-Player`가 없었습니다.
- 해당 인스턴스 실행은 OS의 접근 거부로 실패했습니다. 실행 환경 제한을 우회하지 않았습니다.
- 전체 단위 테스트 명령 `gradlew.bat :app:testCiUnitTest :prefs:testCiUnitTest :scripts:test :libautomata:test`: **통과**(JDK 21, ANDROID_HOME 명시).
- `-PfgaDeviceTests=true :app:assembleDeviceTest :app:assembleDeviceTestAndroidTest`: **통과**. 측정용 APK만 로컬 빌드했으며 릴리스·버전 변경은 없습니다.
- `tools/device-qa/run.py --serial 127.0.0.1:5555 --suite support --cases build/score-audit-baseline.json`: **설치 단계에서 실패** — `device '127.0.0.1:5555' not found`. 기기 리더 호출은 0건입니다.

이 연결 실패는 판독기의 unknown이 아닙니다. **성공·오독·unknown 건수는 아직 미측정입니다. 오독 0건이라는 결론을 내릴 수 없습니다.**

## 오독 전체 목록

**미측정**. 행별로 class·grand·display 원시 결과가 없어 목록을 만들지 않았습니다. 빈 목록을 오독 0건으로 해석하면 안 됩니다.

## unknown 전체 목록과 크롭

**미측정**. 리더를 호출하지 못했으므로 unknown 사례를 식별하거나 그 사례의 크롭을 저장할 수 없습니다. 측정 후 각 unknown 행의 정규화 점수 크롭을 이 보고서와 같은 디렉터리의 `0013-score-audit-crops/` 아래 저장하고 모두 링크해야 합니다.

## QA 케이스와 재개 절차

[support-score-audit.json](../reference-images/cases/support-score-audit.json)은 기존 `support` 하네스로 실행하는 70개 행별 케이스입니다. class·grand·display·Normal 화면을 정답과 비교합니다. QA 코드에는 `display` 기대값 비교만 추가했습니다. 모든 케이스는 **측정 대기/기기 미연결** 사유로 일시 skip했습니다. 이는 현재 실패 행으로 분류한 것이 아니며, 모두 skip한 실행을 기준 측정 성공으로 보고하지 않습니다.

1. 지정된 BlueStacks가 연결되면 케이스에서 skip을 제거하고, 기대 숫자·display만 제거한 임시 복사본으로 최초 기준 실행을 합니다. 원시 결과가 실패 assert로 유실되지 않도록 하기 위함입니다. 원본 라벨은 그대로 유지합니다.
2. 실제 class·grand·display를 70행 라벨에 대응시키고, 모든 오독과 unknown을 표로 나열합니다. 행별 크롭을 저장합니다.
3. 정답 케이스는 활성화하고 실제 실패 케이스만 원인과 실제 반환값을 적어 skip합니다. 전체 QA를 다시 실행합니다.
4. 서버·화면·표시·원본 크기별 성공률을 채우고, 실패 패턴을 정리합니다. 어펜드는 별도 소유자 표본이 필요합니다.

## 판정

측정 자료 준비는 끝났으나 기기 기준 측정과 실패 패턴 분석은 완료되지 않았습니다. 제품 리더를 수정하거나 임계값을 조정할 근거는 아직 산출하지 않았습니다. 연결 복구 뒤 같은 70행을 측정해야 합니다.
