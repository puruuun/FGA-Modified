# 0012 와이드 화면 대응 (2026-10-21 소유자 요청)

- 상태: 구현 완료 (2b182cbd, 베타 1.6.1-beta.1). 좌표 전수 조사와 실측값은 [0012-widescreen-audit.md](0012-widescreen-audit.md). 21:9 캡처가 없는 화면은 현재 코드 경로를 그대로 두었고 소유자 캡처를 기다립니다.
- 버전: 1.6.1-beta.1 / 1006101부터
- 소유자 보고: 블루스택 1680×720(21:9)에서 이 포크가 추가한 기능 가운데 **화면 비율에 따라 위치가 바뀌는 화면**의 기능이 동작하지 않습니다. 원본 FGA 기능은 대체로 동작합니다.
- 캡처(21:9, 블루스택 창 2000×880, 위 약 38px·오른쪽 약 38px가 창 테두리): `build/orchestration/inputs/0012-wide/01–14`
  - 01 홈(JP), 02 카멜롯 지도, 03 후유키 지도, 04 관위대관전 퀘스트 목록, 05 서포트 선택(랜서, 그랜드), 06 파티 확인(아이템 자동 사용), 07 연속 출격 창(티포트), 08 인연 결과, 09 서포트(MIX, +62, 어펜드 표시), 10 서포트(+62/+16, 보구 Lv), 11 서포트(어펜드 표시), 12 스킬 강화, 13 아이템 자동 사용 설정창, 14 영기변환(FP 판매) 격자

## 1. FGO와 원본 FGA의 와이드 규칙 (따르기로 함)
- `FgoGameAreaManager`
  - 18:9 이하: 게임 16:9 고정, 남는 부분 테두리
  - 18:9 초과 ~ 21:9: 게임이 화면 폭을 채움(`isWide`)
  - 21:9 초과: 게임 영역 21:9(1440 기준 3360×1440), 좌우 테두리
- 좌표는 1440 높이 기준입니다. X는 기준점(왼쪽, `xFromCenter`, `xFromRight`)에 붙여 적고, 와이드에서 생기는 안전 여백은 `isWide`로 와이드용 값을 따로 둡니다. 여백은 비율과 무관하게 일정하다고 봅니다(원본 FGA의 가정, 소유자 결정: 별도 비율 측정 없이 따름).
- 요소마다 붙은 곳이 다릅니다.
  - 왼쪽: 뒤로·닫기 버튼, 서번트 카드, FP 판매 왼쪽 버튼
  - 가운데: 서포트 목록, 결과창, 확인창
  - 오른쪽: 제목, 홈 메뉴 배너, 퀘스트 판, MENU
- 확인한 예(캡처 05): 戻る 버튼이 16:9보다 약 170(1440 기준) 안쪽에 있습니다. 원본 `SupportScreenLocations.headerOffset` 171과 같습니다.

## 2. 원인
- 포크가 추가한 좌표는 16:9 캡처에서 재서 대부분 `xFromCenter`만 썼고, 와이드용 값이 없습니다.
- 16:9에서는 기준점이 달라도 결과가 같아 드러나지 않았습니다. 와이드에서는 왼쪽·오른쪽에 붙은 요소를 가운데 기준으로 찾으므로 빗나갑니다.
  - 예 14: 영기변환 격자가 화면 가운데보다 왼쪽에 있습니다.
  - 예 12: 스킬 강화 화면에서 서번트 카드와 스킬 패널이 서로 다른 쪽으로 움직였습니다.

## D-1. 좌표 전수 조사
- 포크가 추가하거나 바꾼 좌표를 모두 표로 만듭니다.
  - 대상: `locations/`의 `BondLocations`, `FpSellLocations`, `FPLocations`(배너 복귀 부분), `QuestItemLocations`, `QuestPanelLocations`, `SkillLevelLocations`, `Support*Layout`, `WeeklyRouteLocations`, `SupportScreenLocations`의 포크 변경분
  - 모듈 안의 직접 좌표(`WeeklyRouteDriver`, `QuestPanelReader`, `MapView`, `WeeklyRouteScreens`, `WeeklyRepeatDialog`, `SkillLevelScreens`, `FpSellReader`, `FpBannerReturn`, `ServantTracker` 등)
- 표에는 각 좌표의 **붙은 곳**(왼쪽/가운데/오른쪽/화면에서 찾은 기준), 와이드 값의 유무, 21:9 캡처에서 확인한 결과를 적습니다. `docs/design/0012-widescreen-audit.md`에 둡니다.
- 직접 좌표는 이 기회에 `locations/`로 옮깁니다(`docs/agents/coordinates.md` 규칙).

## D-2. 고치는 방법
- **A. 기준점과 와이드 값**
  - 버튼·제목 같은 단일 요소는 원본 방식(`xFromCenter`/`xFromRight`/왼쪽 + `isWide`)으로 적습니다.
  - 와이드 값은 21:9 캡처에서 잽니다. 같은 쪽에 붙은 요소는 같은 여백을 써야 합니다. 여백 상수를 한곳(예: `IScriptAreaTransforms`의 `wideInsetLeft/Right` 또는 확장 함수)에 두고 재사용합니다.
- **B. 화면에서 찾은 기준**
  - 격자·패널처럼 덩어리로 움직이는 화면은 그 화면의 고정 그림을 먼저 찾고, 그 위치에서 상대 좌표로 계산합니다.
  - 대상 후보: 영기변환 격자(첫 칸 또는 왼쪽 버튼 열), 스킬·어펜드 슬롯(보유 스킬 띠), 지도 화면 UI 금지 구역(터미널 버튼, MENU)
  - 서포트 판독(줄 경계)과 퀘스트 판(Free Quest 표시)은 이미 이 방식입니다. 와이드에서 기준 찾기가 되는지만 확인합니다.
- 16:9 동작은 바뀌면 안 됩니다. 기존 기기 QA 케이스가 그대로 통과해야 합니다.

## D-3. 검수
- 기기 QA는 이미 프레임 비율을 그대로 씁니다(`FixtureApi.width720`). 캡처 01–14에서 블루스택 창 테두리를 잘라 높이 720으로 맞춘 **와이드 프레임 케이스**를 기능별로 추가합니다(약 1678×720).
- 캡처에 없는 화면은 목록으로 정리해 기획자에게 넘깁니다. 기획자가 소유자에게 21:9 캡처를 요청합니다.
  - 예상: 스킬 확인창, 어펜드 화면, FP 소환 화면·판매 한계 안내, 홈 메인 레코드·메인 인터루드 목록, 지도에서 퀘스트 판이 열린 화면, KR 화면들
- 마지막으로 소유자가 21:9와 다른 비율 하나(예: 1600×720, 20:9)에서 아래 체크리스트를 실행합니다.

## 소유자 QA 체크리스트 (블루스택 21:9 → 20:9)
- 공통: 베타 앱, 로그 수집은 기획자가 켭니다. 실패하면 그 화면을 캡처해 주세요.
- 1. 전투 (카드 개수 시작·두 조건·직접 지정·첫 턴 셔플)
  - 카드 개수 선택 모드를 켠 전투 설정으로 1회 돌립니다.
  - 확인: 커맨드 카드 판독, 조건 충족 시 시작, 직접 지정 턴의 카드 탭 위치
- 2. 서포트 선택
  - 클래스 스코어 +62 / 그랜드 +16, 보구 레벨, 어펜드 스킬 판독, 재림 구분을 각각 켜고 1회씩 돌립니다.
  - 확인: 조건에 맞는 서포트를 고르는지. 어펜드는 스킬 표시 전환·복구 버튼이 눌리는지.
- 3. 티포트·스톰포드
  - 실행 창에서 체크한 뒤 1회 돌립니다.
  - 확인: 파티 확인 화면 아이템 ON/OFF가 맞게 바뀌는지, 연속 출격 창에서 맞는지
- 4. 인연 추적
  - 인연 추적과 최대 인연 정지를 켜고 1회 돌립니다.
  - 확인: 결과 화면 인연 수치 기록, 실행 요약
- 5. FP 자동 판매 (시험 모드 켬)
  - 확인: 서번트 한계 안내 → 판매 화면 이동, 칸 선택, 판매 뒤 소환 화면 복귀(왼쪽 배너 넘기기), 다시 소환
- 6. 스킬·어펜드 자동 강화
  - 스킬 한 칸, 어펜드 한 칸, 목표 = 현재 + 1로 실행합니다.
  - 확인: 칸 선택, 강화 버튼, 확인창 레벨 판독, 취소 버튼
- 7. 주간 미션 루트 (탐색 시험)
  - 장 단위로 후유키와 헤이안쿄(메인 인터루드)를 고릅니다.
  - 확인: 메인 레코드·메인 인터루드 목록에서 장 찾기, 지도 축소·맞추기, 지점 탭, 판 판독, 판 닫기, 터미널로 나가기
- 8. 주간 미션 루트 (실제 실행)
  - 짧은 경로 하나를 출격까지 실행합니다.
  - 확인: 판 탭 → 서포트 → 전투 → 연속 출격 창 닫기 → 다음 퀘스트

## 하지 않는 것
- 21:9보다 넓은 화면은 원본 FGA처럼 21:9로 보고 테두리를 무시합니다. 따로 대응하지 않습니다.
- 18:9 이하는 16:9로 처리됩니다. 지금과 같습니다.

### D-4. 1.6.1-beta.2
- 위 캡처로 beta.1에서 "캡처 필요"로 남긴 화면의 와이드 값을 잽니다. 단일 요소는 `WIDE_EDGE_INSET` 등 공통 여백을 쓰고, 덩어리는 화면 기준을 씁니다.
  - 대상: 스킬 확인창·결과, FP 소환 화면과 배너 화살표, 공방 메뉴, 판매 확인·완료창, 한계 안내창, 메인 레코드·메인 인터루드 목록, 지도의 퀘스트 판·지점 이름표, KR 화면

- 16:9와 beta.1의 21:9 케이스는 모두 그대로 통과해야 합니다.
