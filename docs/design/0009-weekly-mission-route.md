# 0009 주간 미션 최단 루트 자동화

- 상태: 설계 (소유자 확인 대기)
- 버전: 베타 **1.6.0-beta.1** (`1006001`)
- 대상 서버: **JP 먼저**, KR은 JP 확인 뒤 같은 구성으로 추가합니다. 계산은 서버별로 따로 합니다.
- 기본 팀: 구현 Codex gpt-6.1-sol medium(한도 시 Sonnet 5.5 medium). 실제 게임 확인은 소유자가 합니다.

## 1. 배경

FGO에는 매주 월요일 0시(JST)에 바뀌는 **주간 미션(ウィークリーミッション)**이 있습니다. 예: 「선」 속성 서번트 3기 처치, 적 40체 처치. 보상은 성정석입니다.

Chaldea 앱은 메인 스토리 프리 퀘스트의 적 구성으로 "최소 AP로 모든 미션을 채우는 퀘스트별 횟수"를 정수 계획법으로 계산합니다. 소유자는 이 계산 결과대로 FGA가 퀘스트를 **찾아가서 돌기**를 원합니다.

- Chaldea는 **AGPL-3.0**입니다. 코드와 데이터 가공 결과를 복사하지 않습니다. 같은 문제를 Atlas Academy 공개 데이터로 **새로 구현**합니다.
- Atlas 데이터(직접 확인함):
  - `https://api.atlasacademy.io/export/{JP,KR}/nice_master_mission.json`: 기간과 미션 조건
  - `nice/{region}/war/{id}`: 장(war)의 지도 이미지·크기, 지점(spot) 좌표·이름, 퀘스트(이름, AP, 종류 `free`), 적 구성. 예: 후유키 지도 1920×1240, X-E (1618, 766)
  - 장 배너 이미지(메인 레코드 목록 버튼), 예: `questboard_cap100.png`

## 2. 목표 / 비목표

**목표**
1. **루트 계산**: 현재 서버의 이번 주 주간 미션 가운데 계산 가능한 것(적 처치·퀘스트 클리어)을 채우는 최소 AP 루트를 계산합니다. 루트는 "장 → 지점 → 퀘스트 × 횟수" 목록입니다.
2. **자동 실행**: 메인 화면에서 시작해 루트의 퀘스트를 차례로 찾아 들어가고, 정한 횟수만큼 기존 FGA 전투(소유자가 고른 광역 연사 전투 설정)로 돈 뒤 다음 퀘스트로 넘어갑니다. 끝나면 종료합니다.

**비목표 (이번 범위 아님)**
- 게임 안 주간 미션 화면의 진행도 읽기. 이미 일부를 채운 경우 등은 소유자가 시작 전 루트 확인 창에서 조정합니다.
- 드롭 미션("젬·피스 n개 획득" 등) 보충. Chaldea처럼 계산에서 빼고 **"수동"**으로 표시합니다.
- 이벤트 퀘스트, 일회성 퀘스트, 미션 퀘스트(편성 조건)
- 월요일 0시 자동 시작

## 3. 결정 사항

### D-1. 시작과 UI (소유자 결정)
- 실행 버튼 → 스크립트 고르는 창에 **"주간 미션 클리어"** 선택지를 둡니다.
- 시작 화면은 **메인 화면**(칼데아 게이트·메인 레코드 버튼이 있는 첫 화면)입니다.
- 시작하면 이번 주 미션을 내려받아 계산하고, **루트 확인 창**을 띄웁니다. 창 내용:
  - 퀘스트별 장·지점·퀘스트 이름·AP·횟수, 총 AP
  - 계산에서 뺀 미션("수동")
  - 사용할 전투 설정 선택
  - 퀘스트별 횟수 조정(0~), 확인/취소
- 주간 미션 자체는 게임 안에서 자동으로 주어지므로 받는 동작은 없습니다. 앱은 계산에 쓸 미션 **데이터만** Atlas에서 내려받습니다(인터넷 필요). 마지막으로 받은 데이터는 캐시해, 같은 주에는 다시 받지 않아도 됩니다.

### D-2. 계산 (Chaldea 방식을 새로 구현)
- 후보 퀘스트: 서버별 **메인 레코드 1·1.5·2의 프리 퀘스트**(Atlas `type == free`, 메인 스토리 war). 일회성·미션·이벤트 퀘스트는 제외합니다.
  - 소유자 계정에서 아직 열리지 않은 장은 제외할 수 있도록 루트 확인 창에서 장 단위로 끄는 옵션을 둡니다. 기본은 모두 켬입니다.
- 미션 조건 → 퀘스트 1회당 기여량:
  - 적 특성(trait), 적 클래스, 서번트 클래스, 특정 적, 퀘스트 클리어, 퀘스트 특성을 지원합니다.
  - 적은 enemy deck만 셉니다. "바트 중 소환된 적 제외" 문구가 있는 미션은 추가 소환 적을 뺍니다.
  - 드롭 조건 등 지원하지 않는 조건의 미션은 "수동"으로 분리합니다.
- 최소화: `Σ AP × 횟수`, 제약: 각 미션 `Σ 기여 × 횟수 ≥ 목표`, 횟수는 0 이상의 정수입니다.
  - 문제가 작아(퀘스트 수백 × 미션 10 내외) 앱 안의 순수 Kotlin 정수 계획법(분기 한정 + 단체법, 또는 동등한 방법)으로 풉니다.
  - 라이브러리를 쓰면 라이선스(AGPL·GPL 금지)를 확인하고 `gradle/libs.versions.toml`에 추가합니다.
- 결과 정렬: 같은 장을 묶고, 장 순서는 메인 레코드 목록 순서를 따릅니다. 이동을 줄이기 위해서입니다.
- 계산은 `scripts` 모듈의 순수 JVM 코드로 두고 단위 테스트합니다. 고정한 Atlas 샘플 JSON으로 결과를 검증합니다.

### D-3. 화면 이동: 메인 → 장
1. 메인 화면에서 아래로 스크롤해 **메인 레코드 1 / 1.5 / 2** 버튼을 찾아 탭합니다(서버별 템플릿).
2. 장 목록에서 **Atlas 장 배너 이미지**와 맞는 버튼을 찾을 때까지 스크롤합니다(상한 있음). 배너는 런타임에 받아 캐시하고 720p 기준으로 크기를 맞춥니다. 못 찾으면 그 퀘스트를 "찾지 못함"으로 건너뜁니다.
3. 장 버튼 탭 → 지도 화면(왼쪽 위 `ターミナル`, 오른쪽 위 장 제목)

### D-4. 지도 탐색 (설계자 측정)
- 지도는 Atlas 지도 원본(예: 1920×1240)을 **확대해 보여 줍니다.**
  - 기본 배율은 후유키에서 약 1.9배입니다(06~09 화면, 이름표 두 개 사이 거리로 측정).
  - 최대 축소 시 약 1.0배입니다(11 화면). 지도 전체가 거의 한 화면에 들어옵니다.
  - 들어갈 때 보이는 위치는 매번 다릅니다(소유자).
- **위치 추정**: 화면의 지점 이름표(가로 띠 안 글자)를 OCR하거나 템플릿으로 읽고, Atlas 지점 이름과 맞춥니다. 그 지점의 화면 위치와 Atlas 좌표로 "화면 원점의 지도 좌표"를 구합니다.
  - 이름표가 둘 이상 보이면 배율도 그 자리에서 다시 잽니다. 가로·세로를 따로 잽니다. 오를레앙 확대 화면(19)에서는 가로·세로 비율이 달라 보였습니다.
- **이동**: 목표 지점까지 화면 거리를 계산해 `scroll`(관성 없는 스와이프)로 옮기고, 다시 이름표를 읽어 확인합니다. 화면 중앙 근처에 오면 지점 아이콘을 탭합니다. 이동 횟수는 상한을 둡니다.
- **축소 우선 검토**: 지도를 최대로 축소하면 대부분의 장은 이동 없이 바로 탭할 수 있습니다. 축소에는 두 손가락 핀치 제스처가 필요하고, 지금 `GestureService`에는 없습니다. 구현자는 다음을 비교해 보고합니다.
  - (a) 축소 없이 이동만
  - (b) 핀치 축소 추가 (`GestureService`에 다중 손가락 제스처 추가, Android 7 접근성 API 범위)

  설계자는 (a)를 기본으로 하고 (b)는 선택으로 둡니다.
- 지점 이름표는 서버별 글꼴이 다릅니다. 이름 대조는 Atlas 이름을 기준으로 하고, 판독 방식은 기기 QA 사례로 검증합니다.

### D-5. 지점 → 퀘스트
- 지점을 탭하면 오른쪽에 **퀘스트 판**이 뜹니다(01, 10 화면). 프리 퀘스트 판에는 `Free Quest` 표시, 퀘스트 이름, AP가 나옵니다.
  - 일회성 퀘스트(미션 퀘스트 등)가 함께 보일 수 있습니다. 10 화면에서는 위가 미션 퀘스트, 아래가 프리 퀘스트였습니다.
- 퀘스트 이름(OCR)과 AP가 루트의 퀘스트와 맞는 판만 탭합니다. 맞는 판이 없으면 그 퀘스트를 건너뜁니다.

### D-6. 반복 실행과 다음 퀘스트
- 퀘스트 판을 탭한 뒤의 서포트 선택·전투·결과·연속 출격은 **기존 FGA 전투 스크립트를 그대로** 씁니다. 횟수는 루트 횟수로 `실행 횟수 제한`을 내부 설정합니다.
- AP 부족 처리(사과 사용·대기·정지)는 **기존 FGA AP 설정**을 따릅니다(소유자 결정).
- 반복이 끝나면 게임은 **퀘스트 판이 있는 지도 화면**으로 돌아옵니다(소유자 확인).
- 다음 퀘스트가 같은 장이면 지도 탐색부터, 다른 장이면 `ターミナル`/`閉じる`로 장 목록·메인 화면으로 돌아가 D-3부터 반복합니다.
- 전투가 패배·철수 등으로 끝나면 기존 FGA 동작대로 정지하고, 남은 루트를 종료 요약에 표시합니다.

### D-7. 종료 요약
- 퀘스트별 계획 횟수 / 실제 횟수 / 상태(완료, 찾지 못함, 중단)와 "수동" 미션 목록을 보여 줍니다.
- 로그 태그는 `WeeklyRoute`입니다. 단계마다 한 줄씩 남기고, 베타 로그 허용 목록에 넣습니다.

## 4. 단계
- **1단계 (먼저 구현)**: D-1 UI + D-2 계산 + 루트 확인 창. 확인을 누르면 **현재 열려 있는 퀘스트 판**에서 첫 퀘스트만 돌게 해, 계산과 반복이 맞는지 먼저 봅니다.
- **2단계**: D-3~D-6 자동 이동과 연속 실행

1단계와 2단계는 같은 베타 계열에서 나눠 내고, 소유자 확인 뒤 다음 단계로 갑니다.

## 5. 검증
- 단위 테스트
  - 계산기: 고정 Atlas 샘플로 알려진 최적해, 지원 안 하는 미션의 "수동" 분리
  - 위치 추정: 이름표 좌표 → 원점·배율 계산, 06~09·11·19 화면 수치
  - 이동 반복 상한
- 기기 QA(새 suite `weeklyRoute`)
  - 메인 레코드 버튼, 장 배너 찾기(04·05·13~18)
  - 지도 화면 판별
  - 이름표 판독과 지점 이름 대조(06~09·11·19)
  - 퀘스트 판 판별, 프리/일회성 구분(01·10)
- **검증하지 않는 범위**: 실제 게임 실행(소유자), KR 화면(다음 단계)

## 6. 위험과 대응
- **계산 데이터 차이**: Atlas와 게임의 적 구성이 다르면 미션이 덜 찹니다. 종료 요약에 계획 대비 실제를 남기고, 주간 미션 화면 확인은 소유자가 합니다.
- **지도 판독 실패**: 이름표를 못 읽으면 반대 방향으로 한 번 크게 이동해 다시 읽습니다. 그래도 실패하면 그 퀘스트를 건너뜁니다. 엉뚱한 지점을 탭하지 않도록, 퀘스트 판의 이름·AP 대조(D-5)를 마지막 관문으로 둡니다.
- **원치 않는 퀘스트 진입**: 퀘스트 판 이름·AP가 맞지 않으면 절대 탭하지 않습니다. 미션 퀘스트(편성 조건)는 탭하지 않습니다.
- **AP·사과**: 기존 설정을 따르므로 새 위험은 없습니다. 루트 확인 창에 총 AP를 표시합니다.

- 지점이 탭 금지 구역에 **30px 이내로** 걸렸고 맵이 더 움직이지 않으면, 아이콘의 보이는 부분(지점 좌표에서 구역 반대 방향으로 최대 30px)을 탭합니다. 그 점이 구역 밖이고 화면 안이어야 합니다.
- 지점 탭 뒤 판이 뜨지 않으면 탭 직후 화면을 진단 PNG로 저장하고, 1초 뒤 같은 점을 한 번 더 탭합니다. 그래도 없으면 `no_panel`입니다.
- 카멜롯 두 지점이 왜 판을 띄우지 않았는지 이 PNG로 확인합니다.

### 검증
- 소유자 beta.8 실패 PNG 36장(1280×720)을 기기 QA 케이스로 추가합니다.
  - 이름 `null` 29건은 D-29로 Match가 되어야 합니다.
  - 이름을 읽었는데 판정에 실패한 3건은 원인을 밝혀 기대값을 정합니다.
- 거짓 Match 확인
  - 지점 이름이 다른 프레임이나 퀘스트가 둘 이상인 지점에서는 이름 `null`이 Match가 되면 안 됩니다.
  - 기존 케이스 중 다른 퀘스트 판은 계속 Mismatch여야 합니다.
- 신 합성 지도를 오프라인으로 맞춰 봅니다. `png/30` 프레임에서 점수와 지점 위치(咸陽, 大坪峪 등의 라벨과 일치)를 확인합니다.

### 구현 메모 (1.6.0-beta.9)
- **D-29:** 퀘스트 이름 투표에 원본 그레이스케일 4배 판독을 더하고 글자 영역만 잘라 읽습니다. 지점 이름표는 같은 장의 Atlas 지점 이름으로만 투표합니다(`WarInfo.spots`). 가운데 점 대시 변형(`ー－−-`)을 한 글자로 접고 이름표 윤곽선 기호는 양 끝에서 지웁니다. `by=quest-name` / `by=spot-name+cells`는 `QuestPanelMatch.matchBy`가 정합니다.
- **짧은 이름 null의 원인:** beta.8은 이름 띠를 글자 너비+8px로 자르고 2배·3배 이진화(0.6) 두 번만 읽은 뒤 신뢰도 45 이상 두 표가 같은 사전 이름에 모여야 인정했습니다. 저장 프레임 32장에서 두 판독 모두 45 미만이 4장, 한 판독만 45 이상이 8장이라 구조적으로 표가 모자랐고, 나머지 20장도 9장만 한 이름에 모였습니다. 이진화가 가는 획(획수가 많은 한자)을 끊는 것이 원인이며, 원본 그레이스케일 4배 판독은 같은 프레임에서 신뢰도 66~94가 나옵니다.
- **읽었는데 실패한 3건:** 93000312, 93020309는 실패가 아니라 **성공**입니다. 한 지점에 프리 퀘스트가 둘 이상이라 위 판이 다른 퀘스트(静かな入り江, 名もなき霊峰)로 읽혀 `NameMismatch`가 한 번 찍힌 뒤 아래 판이 Match였습니다(CSV는 success). 93031011은 소유자가 시험을 멈춰서 `not_run`이며, 판 이름이 `null`로 읽힌 29건 중 하나의 증상입니다.
- **D-31 (설계와 다름):** 신(303)의 바탕 레이어 `gimmick_030301`(depth −1100)과 `gimmick_030306`이 Atlas 정적 서버에 **없습니다**(JP·NA·KR·CN·TW 모두 404). 있는 레이어는 요새 그림·안개·밧줄 조각뿐이라 합성으로 기준 지도를 만들 수 없습니다. 레이어의 `x,y`는 중심 좌표, `scale`은 1000분율이 맞습니다(안개 512×360 × 4 = 지도 2048×1440). 대신 **지도 크기와 지점 좌표만으로** 위치를 정합니다(`PlaceholderMap`): 최대 축소에서 지도는 화면 너비에 맞고(배율 1280/2048 = 0.625, 원점 x=0), 지도는 가장자리에서 멈추므로 위 또는 아래 끝까지 끌면 원점 y가 0 또는 −180으로 정해집니다. 프레임 30에서 지점 10곳이 `0.625×(x,y)`의 12px 안에 있음을 단위 테스트로 확인했습니다. 실기기 동작은 미검증입니다. 잘못 눌러도 다른 지점의 판이 열려 이름 검사에서 실패하므로 전투는 시작되지 않습니다.
- **D-32:** 배너 그림(450×134), 크롭 영역, 목록 탐색 범위(아래로 14회 + 위로 14회)는 다른 장과 같고 배너도 정상 다운로드됩니다. 따라서 코드에서 원인을 확정하지 못했습니다. Atlas의 307 장에만 `effectDisappearBanner`·`isWarIconCenter` 플래그가 있어 게임의 목록 버튼이 Atlas 그림과 다를 가능성이 있습니다. beta.9는 못 찾으면 목록 상·하단 화면을 진단 PNG로 저장하고 근접 점수를 로그합니다. **소유자 캡처가 필요합니다:** 메인 레코드 2 목록에서 올림포스와 아발론 르 페 사이(헤이안쿄 버튼이 있어야 할 곳)가 보이는 화면.
