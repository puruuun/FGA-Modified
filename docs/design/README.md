구현 agent가 이 폴더의 문서 하나를 받아 그대로 구현할 수 있도록 작성한 설계서입니다.

## 문서 형식

각 설계서는 다음 순서를 따릅니다.

1. **배경**: 현재 상태와 문제. 근거가 되는 파일과 줄 번호를 적습니다.
2. **목표 / 비목표**: 이번에 하지 않는 것을 명시합니다.
3. **결정 사항**: 설계자가 이미 내린 결정과 이유. 구현 중 바꾸지 않습니다. 바꿔야 한다면 구현을 멈추고 보고합니다.
4. **변경 내용**: 파일 단위 작업 목록.
5. **완료 기준**: 검사 가능한 조건만 적습니다.
6. **검증 방법**: 단위 테스트, CI, 기기(블루스택) 확인, 그리고 **검증하지 않는 범위**.
7. **위험과 대응**.

## 구현 agent 공통 규칙

- 설계서의 "결정 사항"과 다른 방법이 더 낫다고 판단되면, 구현하지 말고 이유와 함께 보고합니다.
- 설계서에 없는 기능, 리팩터링, 의존성 추가는 하지 않습니다.
- 작업이 끝나면 설계서의 완료 기준을 항목별로 통과/미통과로 보고합니다. 측정값은 숫자로 적습니다.
- 커밋, 푸시, 작성자 규칙은 `AGENTS.md`의 Delivery 절을 따릅니다.
- 끝난 설계서는 위 표의 상태를 `완료 (커밋 해시)`로 갱신합니다.
