# JP D-2 학습 자료

소유자의 네이티브 BlueStacks 캡처 12장을 직접 대조한 점수 칸 35개입니다. `labels.json`에 원본 해상도·SHA-256·행 위치·정답·숫자 영역을 기록했습니다. 1920×1080 02의 세 번째 점수 칸은 하단이 잘려 제외했습니다. 상단 목록 경계에서도 점수 칸 자체가 완전히 보이는 표본은 포함했습니다.

원본은 창 테두리가 없는 게임 영역입니다. OpenCV `INTER_AREA`로 높이 720, 종횡비 유지, 너비 정수 내림으로 정규화했습니다. `scores/`는 각 프레임에서 제품 `SupportScoreLayout`으로 자른 60×30 영역입니다. QA는 이 픽셀을 표준 720p 캔버스의 같은 판독 영역에 배치합니다.

`support-score-audit/`의 110행은 평가 전용입니다. 그 이미지로 템플릿을 자르지 않았고, 임계값 결정에도 사용하지 않았습니다. 구현 오류 진단에는 홀드아웃의 분할 상태와 OCR 근거를 살펴봤습니다.

## 생성과 판정

```powershell
python tools/device-qa/build_score_d2_templates.py --generate
```

생성기는 이 폴더만 읽습니다. 원본과 Gaussian sigma 0.4·0.7 변형을 사용합니다. 잉크를 4배 선형 확대하고 밝기 110 초과 및 21×21 국소 평균보다 5 초과인 획을 남깁니다. 연결 성분의 기준선으로 패널·제목을 제거한 뒤 잉크 열을 분리합니다. 짧게 끊어진 획은 합친 폭이 한 글자 높이의 0.85 이내일 때만 합칩니다. 슬래시는 높이·기울기로 찾으며, 좌우 숫자 위치를 고정하지 않습니다.

플러스 뒤 두 글자를 각각 16×32 셀로 높이 정규화하고 잉크의 정규화 상관도(NCC)를 비교합니다. 해상도 1920×1080·2340×1080·2560×1440의 표본을 별도로 보존하고 전체 세트에서 최적 일치를 찾습니다. 앱의 720p 이미지에서는 원본 캡처 해상도를 추정하지 않습니다.

양성 62·16과 오답 후보는 같은 학습 글꼴 풀에서 조합합니다. 실제 두 자리 표본도 보존합니다. 62의 근접 오답은 52/63/68/82/57/51, 16은 10/11/12/13/15/18/19입니다. 없는 9는 같은 글꼴의 6을 180도 회전해 구성했습니다. 결과는 `scripts/src/main/resources/support-score-d2.tsv.gz`에 들어갑니다.

최종 기준은 **NCC ≥ 0.90, 최상위 오답보다 ≥ 0.03 높은 마진**입니다. 학습 프레임 한 장을 완전히 제외하고 양성·음성 글꼴 풀까지 다시 만드는 검증에서, 원본 양성 28필드의 최저 유사도는 class 0.928074 / grand 0.947513, 최저 마진은 0.055819 / 0.034870입니다. 블러 변형을 포함한 학습 음성의 최상위 양성 유사도는 0.800164 미만이고 마진은 모두 음수입니다. 수치는 `calibration.json`에 보존합니다.

확실한 한 자리 블록은 최대 점수가 아닙니다. 빈 잉크·세 개 이상의 분리 조각처럼 자릿수를 셀 수 없는 경우는 unknown입니다. 슬래시가 보이지 않는다는 이유만으로 그랜드의 부재나 일반 표시를 확정하지 않습니다. OCR·기존 템플릿과의 충돌, 잘림, 범위 초과 등 D-1 차단이 새 양성보다 우선합니다. KR에는 이 경로를 적용하지 않습니다.
