## 변경 사항 — 설계 0009 1단계 (§8, §9 D-11 반영)

- **계산기** (`scripts/.../weekly/`): Atlas Academy 공개 데이터만 쓰는 순수 Kotlin 정수 계획 풀이기입니다. 분기 한정법과 LP 완화(쌍대 단체법, 직접 구현)로 `Σ AP × 횟수`를 최소화하며 최적이라고 증명하지 못하면 실패합니다. Chaldea 코드는 쓰지 않았고 새 라이브러리도 추가하지 않았습니다.
- **지원 조건**(실제 Atlas 자료로 확인한 `missionCondType`): 2 적 특성(하나라도), 13 적 특성(모두, 서번트 속성 미션), 14 적 클래스, 15 서번트 클래스, 24·31 퀘스트 클리어(퀘스트 지정 / 아무 퀘스트), 퀘스트 특성 조건(`targetQuestIndividualities`). 특정 적(1)은 현재 주간 미션에 사용례가 없어 자료로 확인하지 못했습니다(아래 한계). 소환된 적은 enemy deck만 세어 제외합니다. 나머지(예: 12 드롭 획득)는 "수동"입니다. "모든 미션 클리어" 메타 미션은 경로와 수동 목록에서 뺍니다.
- **일회성 free 퀘스트 제외**: `afterClear == repeatLast`인 퀘스트만 후보입니다(후유키 `危険地帯`는 `close`라 제외, 테스트 있음). 믹틀란(**war 311**)은 후보에서 항상 제외합니다(테스트 있음). 307(헤이안쿄)은 일반 장입니다.
- **KR(D-11)**: KR 퀘스트 목록(이름·AP)에 같은 퀘스트 ID의 JP 적 구성을 씁니다. JP에 없거나 AP가 다른 퀘스트는 빼고 로그를 남깁니다(이번 주는 0개).
- **UI**: 스크립트 시작 창(재생 버튼)의 왼쪽 아래에 **주간 미션 클리어** 버튼(JP·KR, 전투 화면 감지 때). 누르면 데이터를 내려받아 **경로 확인 창**을 띄웁니다: 미션 목록, 수동 미션, 퀘스트별 장·지점·이름·AP·횟수(조정 가능), 총 AP, 장별 켜기/끄기(끄면 재계산), 믹틀란 제외 표시, KR 데이터 안내, 전투 설정 선택.
- **실행**: 확인하면 경로의 첫 퀘스트를 열려 있는 퀘스트 판에서 실행합니다. 퀘스트 판의 **Free Quest 표시**, **AP 숫자(OCR)**, **이름 글자 길이**가 모두 맞을 때만 기존 FGA 전투가 정한 횟수만큼 돕니다. 하나라도 틀리면 아무것도 누르지 않고 정지합니다. AP·사과는 기존 FGA 설정을 따릅니다.
- **로그**: 태그 `WeeklyRoute`, 베타에서도 INFO 허용(`FpSell`·`SkillLevel`과 같음, 단위 테스트 있음).
- **한국어 설명서**: [`wiki/scripts/Weekly-Mission-Route-KR.md`](../../../wiki/scripts/Weekly-Mission-Route-KR.md), README 표에 추가.
- **데이터 크기 대응**: 전쟁 목록이 25MB라 JSON 트리를 만들지 않고 스트림으로 읽고, `gzip`으로 받습니다(1.5MB). 원본은 계산 뒤 지우고 서버·주별 작은 결과만 캐시합니다.

## 확인하지 못한 것과 한계

- **이름 확인은 OCR이 아닙니다.** 앱의 Tesseract 데이터는 영어(`eng`)뿐이라 일본어·한국어 퀘스트 이름을 읽을 수 없습니다. 이름 글자의 가로 폭으로 글자 수를 추정해 비교합니다(JP 18.3px/글자, KR 16.5px/글자, 허용 ±1.5칸 또는 20%). 폭이 다른 퀘스트는 걸러내지만 같은 폭의 다른 퀘스트는 걸러내지 못하고, AP와 Free 표시가 나머지를 보완합니다. 일본어·한국어 `traineddata`(Apache-2.0) 추가는 별도 결정이 필요합니다.
