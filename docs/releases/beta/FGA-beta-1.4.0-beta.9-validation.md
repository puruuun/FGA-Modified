## 원인 및 변경

소유자 beta.8 로그는 378칸 선택→결정→왼쪽 취소 성공 후 2.371초 만에 `bannerReturn reason=workshop`으로 끝난다. 정지 화면은 0/999인 판매 화면이다. 닫기 버튼의 탐지 실패를 가정해 템플릿을 바꾸지 않았다. 전환 중 무시된 탭을 기다리고 한 번만 재시도한다.

대기 값은 `scripts/.../modules/FpSellTiming.kt` 한 곳에 모았다. 칸 선택 루프는 지연 없이 직접 탭하며, 스와이프/재기준 설정 뒤 0.7초도 그대로다. 선택·잠금·제외·판독·스크롤 거리 로직은 바꾸지 않았다. 자동 판매 OFF의 초기 확인/반복/연출 속도는 이전과 같다. 시험 모드 기본 ON과 실제 변환 미탭도 유지했다.

| 적용 위치 | beta.8 → beta.9 |
|---|---|

§17의 0.8→1.3초는 일반 예시이며 beta.8에는 해당 고정 대기 사용 지점이 없다. 이미 조건부 3초 확인으로 바뀐 MENU/소환 메뉴에 과거의 0.8초 지연을 새로 만들지 않았다.

판매 화면 닫기와 MENU/소환 메뉴는 매 시도마다 1초 안정화→최대 약 2초 템플릿 찾기→한 번 탭→다음 화면 3초 확인 순서다. 최대 두 번 탭하고, 닫기 실패는 `workshop`으로 정지한다. 재탭 전에도 템플릿을 다시 찾아야 한다. FP 소환·결정·취소·변환과 판매 완료 닫기는 이 재시도 경로를 쓰지 않는다. 단계별 stop 및 final-summary 한 번 출력은 유지했다.

## 로컬 테스트

JDK `21.0.12.101`, ANDROID_HOME 환경변수만 사용했다.

```text
./gradlew :app:testCiUnitTest :prefs:testCiUnitTest :scripts:test :libautomata:test :app:compileCiKotlin
BUILD SUCCESSFUL
```

app 177 + prefs 24 + scripts 293 = **494개 통과**, 실패·오류·skip 0. libautomata는 테스트 소스 없음. beta.8보다 8개 증가했다.

- 버튼 찾기보다 1초 안정화가 먼저 적용되는 순서, 기존 2초 탐색 및 3초 다음 화면 확인을 검증했다.
- 첫 닫기 탭이 무시된 모형에서 한 번만 재탭해 공방 진입에 성공하고, 둘 다 실패하면 총 2탭 뒤 workshop으로 정지하는지 확인했다.
- 두 칸 선택 회귀에서 칸 사이 추가 대기 0, 두 스크롤 대기 각각 0.7초를 확인했다. 단계 앞뒤 1초, 화살표 뒤 1.2초, FP 재소환 뒤 1초도 확인했다.
- 실제 소환 진입점의 대기 순서는 자동 판매 ON에서 `[0.8, 1.0, 0.8, 3.5]`, OFF에서 기존 `[0.3, 0.5, 0.3, 3.0]`이다.
- 판매 확인창 누락 시 0.5초 폴링 40회 후 정지한다. 보호 버튼 재탭 금지·시험 모드 변환 탭 0회·요약 한 번 회귀도 통과했다.
