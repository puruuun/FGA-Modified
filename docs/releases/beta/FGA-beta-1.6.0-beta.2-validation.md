## 변경 사항 — 설계 0009 2단계 (§8 D-8~D-10, §9 D-11)

- **전체 경로 실행**: 확인 창의 OK 뒤 메인 화면에서 시작해 장 순서(메인 레코드 1 → 1.5 → 2 / KR은 메인 화면 목록)대로 모든 퀘스트를 돕니다. 같은 장은 패널만 닫고 계속, 다른 장은 `ターミナル`/`터미널` → 장 목록 → (필요하면 `閉じる`/`닫기`로 메인 화면) 순서입니다. 순서 규칙은 상태 머신(`WeeklyRouteMachine`)으로 단위 테스트합니다.
- **장 버튼 찾기**: Atlas 장 배너를 런타임에 받아 캐시하고 720p(배율 1.24)로 맞춰 색상 상관으로 찾습니다. 못 찾으면 그 장의 퀘스트를 "찾지 못함"으로 건너뜁니다. 메인 레코드 1 / 1.5 / 2 버튼은 서버별 템플릿입니다.
- **핀치 줌아웃**: `GestureService.pinch`(libautomata)를 추가하고 앱에서 접근성 `dispatchGesture`의 두 스트로크(API 24+)로 구현했습니다(`PinchGesture` 계획 빌더 단위 테스트). 장에 들어갈 때마다 최소 배율로 줄입니다.
- **지도 맞추기**: 줄인 Atlas 지도 이미지와 화면 전체를 맞춰 가로·세로 배율과 위치를 따로 구합니다(코어스→파인 상관 + 패치 인라이어 검증). 목표 지점이 화면 밖이거나 고정 UI에 가려지면 관성 없는 `scroll`로 이동해 다시 맞춥니다(상한 4회). 이 패스에서 가로 드래그의 시작·끝점이 하단 초상화·선물 상자 위에 놓일 수 있던 문제를 드래그 경로 안전 영역 클램프로 고쳤습니다(양방향 단위 테스트).
- **지도가 여럿인 장**: 지점의 `mapId`로 지도를 고릅니다. 맞는 지도가 없으면(다른 지도 거부 QA 4건) 그 장을 건너뜁니다. 믹틀란(311)은 계속 제외합니다.
- **퀘스트 판**: Free Quest 표시 + AP + 이름(일본어·한국어 Tesseract 데이터로 읽어 해당 서버의 전체 프리 퀘스트 이름 중 하나로만 일치할 때 인정, 같은 폭의 다른 이름은 통과 못함)이 모두 맞는 판만 탭합니다. 미션 퀘스트·일회성 판은 절대 탭하지 않습니다(슬롯 0~2 확인).
- **반복·종료**: 기존 전투 흐름이 퀘스트별 횟수만큼 돌고(AP·사과는 기존 설정), 그 외 정지(AP 부족·패배·직접 정지)는 경로를 끝내고 요약에 표시합니다. 종료 요약: 퀘스트별 계획/실제 횟수/상태(완료·찾지 못함·중단·실행 안 함)와 수동 미션. 로그 태그 `WeeklyRoute`, 단계마다 한 줄.
