## 원인과 수정

| 원인 | 수정 |
|---|---|
| 읽은 행보다 긴 고정 840px 스와이프, 아래 라벨 검색 경계 | 라벨 검색을 격자 끝까지 확장하고 실제 라벨이 안에 있으면 아래 행도 평가. 평가한 행 수−1행 이내, 최대 560px. 한 행뿐이면 최대 한 행 이동. 이미 선택된 칸은 건너뜀. |
| 그림 때문에 빈 별 슬롯이 0.41~0.45로 올라 1★을 미확인 처리 | 서번트는 프레임 색으로 동·은·금 등급부터 판독. 동색은 둘째/첫째 별 점수 비율, 은색은 3★, 금색은 첫 네 별과 확실히 빈 다섯째를 확인해야 4★. 불명확한 경우 null. 경험치 카드는 기존 방식 유지. |
| 고정 267px 열 간격의 누적 오차로 7열 선택 띠가 실제 프레임 밖에 위치 | 각 라벨 중심에서 칸 위치를 역산하고 양쪽 8px 범위에서 바깥→프레임 밝기 경계를 찾음. 클래스·번호 배지 사이 두 띠의 실제 가장자리 색만 사용. |
| 47번의 파란 디버그 표시, 48번의 화면 어둡게 처리 | 가려진 한 띠 대신 독립된 다른 프레임 띠를 사용. 밝기 대신 색 비율로 청록을 구분하며 둘 다 불명확하면 null. 선택 거리 임계값 25/45는 유지. |

색상 분류는 녹색 채널을 245로 정규화한다. 동색·금색은 색 비율 범위, 은색은 밝고 중립적인 색을 요구하며 어두운 회색을 등급으로 인정하지 않는다. 동색은 첫째 별 0.55 이상에서 둘째/첫째 비율 0.65 이하이면 1★, 둘째도 0.55 이상이고 비율 0.80 이상이면 2★다. 중간은 null이다. 금색은 첫 네 슬롯 0.55 이상, 다섯째 0.50 이하일 때만 4★이며 5★는 선택 대상이 될 수 없다. 선택된 청록 칸은 등급을 요구하지 않고 다시 탭하지 않는다. 기존 선택 칸의 별 기대값은 진단용 회색 판독으로 회귀 검사하며, 실제 후보 결정은 새 색상 등급 판독을 사용한다.

스크롤은 사용자 swipeMultiplier로 길어지지 않는 별도 경로를 사용한다. Android 8 이상은 정확한 하나의 경로로 이동한 뒤 끝점에서 400ms 누른 채 멈춰 관성을 억제한다. 기존 미세 단계 스와이프의 정수 반올림 누적도 사용하지 않는다. Android 7은 2초 이상의 느린 드래그를 사용한다. 일반 전투 스와이프 경로는 유지한다. `rows=[...]`와 `swipe=`/`distance=`를 쪽마다, `tier=`를 칸마다 로그에 남긴다.
