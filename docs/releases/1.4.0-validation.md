## 변경과 안전

**판매 화면에 보이는 서번트·경험치 카드·포우 카드 중 잠금이 아닌 칸을 모두 선택해 판매합니다. 시작 전에 판매 화면의 필터 설정을 꼭 확인하세요.**

- 자동 판매 기본 꺼짐. 잠금·제외·이미 선택·빈 슬롯·불명확한 선택 상태는 고르지 않는다. 종류·별 수·NEW!로 제한하지 않는다.
- **시험 모드는 베타 전용**. 베타는 스위치와 기본 ON을 유지한다. 정규판은 시험 스위치·설명을 숨기며 저장된 설정을 읽지 않고 실제 판매한다.
- 정규판에도 실제 판매 허용 조건(KR/JP와 잠금 템플릿)을 적용한다. 불허 시 버튼을 누르기 전에 판매 없이 정지하며 시험 모드로 바꾸지 않는다. 실제 판매에서 잠금 판별 불가는 선택하지 않는다.
- 두 빌드 모두 필터 경고는 `bodyLarge`·`FontWeight.Bold`·`colorScheme.error`로 표시한다.
- 재소환은 `confirmation` 워터마크 확인 후 원래 확인 위치를 딱 한 번 누른다. 가득 참이 우선이며 확인창이나 가득 참이 약 2초 내 확인되지 않으면 `ResummonConfirmFailed`로 정지한다. KR52 템플릿을 추가했고 JP FP 사용 확인창의 실제 양성 프레임은 제공되지 않았다.
- 판매 버튼 뒤 2초 추가, 변환 뒤 0.3초 추가를 `FpSellTiming`에 모았다. 선택 루프와 FP 소환 대기는 그대로다.
- 판매 직후 다시 가득 차면 반복 판매하고 선택 수가 0이면 `InventoryFullNothingToSell`로 정지한다. 별도의 판매 직후 가득 참 정지는 없다.

## 정규판 UI·빌드 정책 확인

- 앱 `BuildConfig.BUILD_TYPE`의 `ci`/`release`에서만 정규판 정책을 주입한다. `beta`/`deviceTest`는 베타 정책이다.
- 컴파일된 `AppProvidesModule.provideFpSellStableBuild`의 javap 결과: ci는 `iconst_1`(true), beta는 `iconst_0`(false). 앱 단위 테스트에서 BuildConfig와 정책 일치 확인.
- 런처는 이 정책이 false일 때만 시험 스위치·시험 설명을 만든다. 빨간 굵은 경고는 조건 밖에 있다. 옵션 테스트는 정규판에서 저장된 `fpSellDryRun` getter를 0번 읽음을 확인한다.
- stable APK의 패키지·버전·이름·ABI·서명과 새 워터마크 자산 포함을 검사했다. 공통 문자열 리소스는 APK에 남을 수 있으며, 숨김은 런처의 조건으로 적용한다.
- **게임이나 실제 앱 UI를 실행해 확인하지 않았다.** 이 항목은 소스·컴파일 결과·단위 테스트 및 APK 정적 검사 범위이다.
