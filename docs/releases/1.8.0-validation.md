## 1.8.0-beta.48 실기기 확인 (2026-11-17)

- **설치:** 태블릿 HA29GCWH(Android 16), 블루스택(Android 9), MuMu(Android 15, 루트), MuMu(Android 12, 루트)에 설치했습니다. 서명 인증서 `563754b1…dbe8f8`.
- **루트 수집, 앱별 규칙을 지원하는 기기(MuMu Android 15):** 수집이 정상으로 켜졌습니다(소유자 확인). #485의 사전 검사가 지원 기기를 막지 않습니다.
- **루트 수집, 지원하지 않는 기기(MuMu Android 12, 커널에 `xt_owner` 없음):** `iptables -C … -m owner`가 종료 코드 2를 내는 것을 측정했고, beta.48은 이 경우 새 안내를 표시합니다.
- **외부 앱 프록시(AdGuard):** 태블릿에서 게임 접속 불가였던 원인(프록시 터널 스레드의 크래시, #479)을 beta.47에서 고쳤습니다.
- **셀룰러:** 휴대폰 핫스팟으로 연결해 로그 수집과 게임 접속이 정상임을 확인했습니다(소유자 확인).
- **수동 QA:** 소유자가 1.8.0 기능을 다시 확인했고, 이 기록에 적은 문제(#479, #480, #485) 외에는 정상이었습니다.

## 장시간 실행 점검

- **코드 점검(Sonnet, 읽기 전용):** 장시간 실행에서 끝없이 커지는 상주 메모리, 소켓·스레드 누수, 스크립트 스레드를 멈추게 하는 경로를 찾지 못했습니다.
  - 전투 로그는 종류별 최대 200개이고, 요약만 메모리에 둡니다.
  - battle inbox는 최대 16개입니다.
  - 연결마다 타임아웃이 있고, 소켓은 끝나면 닫힙니다.
- **경미한 항목(조치하지 않음):**
  - 큰 응답 하나가 순간적으로 최대 32MB 버퍼를 씁니다. `largeHeap`이 켜져 있고, 메모리가 부족하면 그 응답만 버립니다.
  - 계정 상태 파일을 저장할 때마다 전체를 다시 씁니다(2초 디바운스).
  - 실행 중 수집이 멈추면 인연 추적을 켠 전투마다 최대 3초 기다립니다.
- **실측(태블릿, beta.47, 5분 간격):** 전체 메모리 300~450MB 사이였고, 차이는 대부분 FGA 화면이 떠 있을 때의 그래픽 메모리입니다. Java 힙 사용은 약 33MB(한도 512MB), 스레드 61~65개로 일정했고, 프로세스 재시작은 없었습니다.
