## 바뀐 것

beta.17:

- 서포트 목록 필터의 칩과 패널이 전투 설정 목록이 나오는 시작창 모두에 나온다 (전투, 서포트 이미지 메이커, 주간 미션 경로). 패널의 "이 기능 사용" 스위치를 없애고 시작창의 토글 하나로만 켜고 끈다 (PR #728)

beta.19:

- 대시보드 "도감·기록" 탭에 퀘스트 기록 블록(클리어·도전 횟수), "선물함·상점" 탭에 상점 블록 (#730, PR #731, #732, #737). 이름 표는 자기 서버 것만 내려받고 스크립트가 도는 동안에는 내려받거나 다시 만들지 않는다
- 두 블록의 화면 정리 (PR #742): 퀘스트 칩 "90+·90++", "막간·강화", "스토리"와 행의 레벨 표기를 없앰. 검색은 제목 오른쪽 아이콘을 눌러 연다. 상점의 "구매 가능한 것만" 스위치를 없애고 블록 이름을 "상점"으로
- 계정 상태의 `cache.updated` 병합이 행 수에 비례한다 (#733, PR #735). 저장되는 내용은 같다. `userShop` 4,687행 응답에서 562 ms → 1 ms 미만
- 서포트 목록 필터가 빈 친구 목록을 보내지 않는다 (#740, PR #741). 조건에 맞는 친구가 없으면 판정 대상 중 첫 친구 한 명을 제자리에 남기고, 그 친구의 채워진 일반·이벤트 칸을 서버의 빈 칸 형태로 바꾸고 관위 목록을 비운다. 결과 줄은 그대로 "N명 중 0명 표시"다
- PR #723은 #736으로 되돌렸다가 #739로 다시 넣었다. beta.19의 동작은 beta.16·17과 같다

구현과 검증의 모델, 회차별 지적은 각 PR의 "Planner record" 댓글에 있다.

## 먹통 조사 (2026-11-26, 오너의 태블릿)

- 현상: 필터 결과가 0명이면 게임의 서포트 선택 화면이 버튼에 반응하지 않는다. 화면과 애니메이션, 버튼의 눌림 표시는 그대로이고 동작만 없다. 게임을 다시 켜야 풀린다
- 오너가 반복해 확인한 조건: KR과 JP 모두, 관위 조건이 있든 없든, PR #723을 뺀 beta.18에서도 0명이면 생긴다. 한 명이라도 남으면 생기지 않는다
- 그때 필터가 보낸 것은 `followerInfo: []`로, 서버가 보내지 않는 형태다
- 조사 중 틀렸던 추정: 화면을 덮는 FGA 창(창 목록에 없음), 응답 길이·연결 어긋남(코드와 실제 프록시 경로 시험에서 없음), PR #723(뺀 빌드에서도 재현)
- 오너 결정: 0명일 때 빈 목록을 보내지 않는다. 먼저 "친구 한 명을 남기고 칸을 비우는" 쪽을 써 본다. 그래도 먹통이면 "아무도 맞지 않을 때 응답을 받은 그대로 넘긴다"로 바꾼다. "관위 데이터가 없는 목록에는 관위 조건을 적용하지 않는다"는 넣지 않는다

## 확인한 것

- 검증: PR #731, #732, #735, #741은 검증자 2명(서로 다른 모델). #741은 지적 3건(바뀌지 않은 응답의 재직렬화 등)을 반영한 뒤 변경분을 다시 검증해 통과. PR #728, #737, #742는 화면 배치라 플래너가 diff와 화면 캡처로 읽음
- 각 PR은 올리기 전 전체 단위 테스트를 돌렸고 `Main CI gate`와 `lint`가 통과했다
- 오너가 태블릿에서 본 것: beta.17의 필터 칩과 토글, 대시보드 두 블록의 화면(정리 요청 전), 필터 결과가 1명 이상일 때 관위 조건과 #723이 정상 동작
- 이 구간에는 `tools/device-qa/run.py` 기기 QA를 돌리지 않았다. 자동 전투의 화면 판독과 탭 코드는 바뀌지 않았다

## 확인하지 않은 것 (오너가 기기에서)

- **필터 결과 0명일 때 beta.19에서 게임 버튼이 반응하는지, 화면에 무엇이 보이는지 (KR, JP).** 칸이 모두 빈 친구 한 명만 있는 목록은 기기에서 본 적이 없다
- 대시보드 퀘스트 기록·상점 블록의 정리된 화면과 검색 아이콘 (가로·세로), 일본어 문구
- 큰 응답(상점, 로그인) 뒤 계정 상태 반영이 빨라졌는지
- beta.16 기록의 남은 항목: 체인 우선순위를 켠 실제 전투, 부호 보정으로 답한 줄, BlueStacks·MuMu 설치와 기기 QA

## 알려진 문제

- 수집을 게임보다 늦게 시작하면 게임을 다시 켜야 수집과 필터가 동작한다. 오너 결정으로 그대로 둔다
- 브레이브 체인 목록이 웨이브 수보다 짧게 저장된 설정 (#724)
- 클래스 스코어 +62: KR 응답에는 실더·룰러가 어느 보드에도 없어 이 클래스는 항상 맞지 않는다. 게임 표시와의 일치는 확인되지 않았다
- KR 응답에는 관위 항목이 없어 "관위 서번트" 조건은 KR에서 아무도 맞지 않는다 (이제 친구 한 명의 빈 줄이 남는다)
- 필터 진단 기록 (#738)은 로컬 브랜치에 보류 중이다
- `PickerDownloadTest`가 전체 실행에서 한 번 실패했다가 다시 돌리면 통과했다. 원인은 조사하지 않았다
