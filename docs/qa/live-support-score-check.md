# 실전 확인 절차: 서포트 점수 판독

- 대상 설계: [0005](../design/0005-support-score-accuracy.md) A0단계, 이후 A단계 표본 수집
- 수행: **QA agent 두 개**가 동시에 진행합니다. 구현 agent와는 다른 agent입니다.

| 역할 | 기기 | adb 시리얼 | 게임 서버 (패키지) | 결과 폴더 |
|---|---|---|---|---|
| **QA-JP** | 블루스택 (PC) | `emulator-5554` | JP (`com.aniplex.fategrandorder`) | `build/live-qa/jp-bluestacks/<YYYYMMDD-HHMMSS>/` |
| **QA-KR** | 소유자 태블릿 Lenovo Legion Y700 (2025), 모델 TB322FC, 3040×1904, density 440 | `HA29GCWH` | KR (`com.netmarble.fgok`) | `build/live-qa/kr-tablet/<YYYYMMDD-HHMMSS>/` |

두 기기 모두 소유자의 실제 게임 계정이 로그인되어 있습니다. **3절 "금지 행동"을 어기는 조작은 어떤 이유로도 하지 않습니다.** 판단이 애매하면 멈추고 소유자에게 묻습니다.

## 1. 두 agent 공통 규칙

- **자기 기기만 조작합니다.** 모든 adb 명령에 `-s <자기 시리얼>`을 붙입니다. `-s` 없는 adb 명령(`adb shell`, `adb install` 등)은 쓰지 않습니다. 다른 agent의 기기는 `adb devices`로 목록을 보는 것 외에는 건드리지 않습니다.
- **adb 서버를 건드리지 않습니다.** `adb kill-server`, `adb start-server`, `adb disconnect`, `adb usb`, `adb tcpip`, `adb reconnect`는 쓰지 않습니다. 두 agent가 같은 adb 서버를 함께 쓰기 때문에, 한쪽이 서버를 끄면 다른 쪽 작업이 끊깁니다. 연결이 끊기면 멈추고 소유자에게 알립니다.
- adb는 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe` 하나만 씁니다. 다른 adb(`C:\platform-tools`, 블루스택 `HD-Adb.exe`)를 쓰면 버전이 달라 서버가 재시작됩니다.
- **구현 agent는 QA가 끝날 때까지 두 기기를 쓰지 않습니다.** 소유자가 순서를 관리합니다.
- 결과는 자기 결과 폴더에만 씁니다. `build/`는 git에서 제외되어 있습니다. **커밋과 푸시는 하지 않습니다.**
- 끝나면 바꾼 설정을 모두 원래대로 되돌리고, 되돌린 목록을 보고합니다.

## 2. 시작 전 확인

**공통**
- `adb -s <시리얼> shell getprop ro.product.model`, `wm size`, `wm density`의 결과를 적습니다.
- FGA 앱의 패키지와 버전을 적습니다: `adb -s <시리얼> shell dumpsys package <패키지> | findstr versionName`
  - 베타는 `io.github.fate_grand_automata.beta`, 정규판은 `io.github.fate_grand_automata.cardcount`입니다.
  - 소유자가 확인한 버전은 1.2.1-beta.4입니다. 다른 버전이면 그대로 적고 진행하되, 앱을 설치하거나 바꾸지는 않습니다.
- FGA 설정 중 AP 회복(Refill)이 꺼져 있는지, 실행 횟수 제한이 1인지 확인합니다. 아니면 바꾸고, 바꾼 사실을 적습니다.

**QA-KR (태블릿)**
- `adb devices -l`에서 태블릿을 찾아 시리얼을 정합니다. 블루스택(`emulator-5554`)이 아닌 기기입니다.
- 목록에 태블릿이 없으면 **멈추고** 소유자에게 다음을 요청합니다. 무선 디버깅 페어링이나 `adb connect`를 agent가 직접 하지 않습니다.
  1. USB 케이블이 충전 전용이 아닌 데이터 케이블인지, 태블릿의 USB 모드가 "파일 전송"인지
  2. 태블릿 화면에 뜨는 "USB 디버깅을 허용하시겠습니까?"에서 허용을 눌렀는지
  3. 무선 디버깅을 쓰는 경우, 소유자가 직접 페어링하고 `IP:포트`를 알려 주기
- 2026-10-18 설계자 확인: `HA29GCWH`로 연결됨. 태블릿의 FGA는 정규판 `io.github.fate_grand_automata.cardcount` 1.2.1입니다(베타 미설치). 원본 FGA(`io.github.fate_grand_automata`)도 설치되어 있으니 **헷갈리지 말고 cardcount를 씁니다.**

## 3. 금지 행동

**두 기기 공통**
- 성정석, 황금·은·동 사과 등 **AP 회복 재화 사용**, 상점 구매, 과금 화면 진입
- 소환(가챠), 서번트·예장 강화·영기재림·판매·보관고 정리
- 친구 추가·삭제·신청 수락, 프로필·계정 설정 변경, 인계 코드 관련 화면
- 4절의 허용 퀘스트가 아닌 퀘스트 시작
- 게임이나 FGA의 데이터 삭제, 앱 설치·제거
- FGA 설정 중 이 절차에 적힌 항목 외의 변경

**태블릿 추가 금지 (QA-KR)**
- `wm size`, `wm density`, `settings put`, `setprop` 등 기기 설정 변경. 해상도는 **읽기만** 합니다.
- 재부팅, 개발자 옵션·접근성·권한 설정 변경, 화면 잠금 해제 시도
- 태블릿의 사진·파일 열람. 스크린샷은 `adb exec-out screencap -p`로만 PC에 저장합니다.

## 4. 허용 퀘스트 (2026-10-18 소유자 지정)

- **메인 레코드 → 특이점 F 후유키 → 미확인 좌표 X-A (AP 3).** JP는 같은 퀘스트(未確認座標X-A)입니다.
- **자연 회복 AP만** 씁니다. AP가 3보다 적으면 퀘스트는 실행하지 않고, 5절의 "퀘스트 시작 전에 멈추는" 실험만 합니다.
- 실험 하나당 최대 1회 실행합니다.
- 이 퀘스트의 서포트 화면이 실험에 맞지 않으면(+62·+16 서포트가 안 나오는 등) 다른 퀘스트로 바꾸지 말고 보고합니다.

## 5. 실험

### 공통 진행 방식
- 보구 레벨 필터는 소유자 설정 그대로 둡니다. 점수 필터만 실험마다 지정한 대로 켭니다.
- 서포트 화면에서 FGA를 실행합니다. 점수 필터가 실패하면 FGA가 새로고침을 반복하므로 **퀘스트를 시작하지 않고도** 표본이 쌓입니다. 후보 30개 이상이 모이거나 5분이 지나면 FGA를 멈춥니다.
- FGA가 서포트를 골라 편성 화면으로 넘어가면, 4절의 허용 퀘스트인 경우에만 진행합니다. 그 외에는 "퀘스트 시작" 전에 FGA를 멈추고 서포트 화면으로 돌아옵니다.

### 로그와 스크린샷 수집
```bash
adb -s <시리얼> logcat -c
adb -s <시리얼> logcat -v time -s FGA.SupportScore:I
```
- 실험마다 로그를 따로 파일로 저장합니다. 각 줄의 `Support Class/Grand: X/Y, required: a/b, display: D, matched: M`을 집계합니다.
- 실험마다 서포트 화면 스크린샷을 2장 이상 저장합니다(`adb -s <시리얼> exec-out screencap -p > <파일>.png`). 이 원본은 결과 폴더에만 두고, 보고서에 넣는 이미지는 **점수 영역만 잘라서** 넣습니다. 친구 이름이 보이면 안 됩니다.

### QA-JP (블루스택) — 화면 조건을 바꿔 가며 원인을 가립니다

| 번호 | 블루스택 해상도 | 점수 필터 | 목적 |
|---|---|---|---|
| J1 | 1920×1080 (16:9, 현재 값) | +16만 | 기준선 |
| J2 | 1920×1080 | +62만 | 기준선 |
| J3 | 1920×1200 (16:10) | +16만 | 비율만 변경 (H-1) |
| J4 | 1920×1200 | +62만 | 비율만 변경 |
| J5 | 3040×1904 (16:10), 안 되면 2560×1600 | +16만 | 비율 + 축소 배율 (H-1 + H-2) |
| J6 | J5와 같음 | +62만 | 비율 + 축소 배율 |

- 해상도는 블루스택 설정 → 디스플레이 → 사용자 지정에서 바꿉니다. 블루스택을 재시작해야 할 수 있습니다. 블루스택 설정 변경은 QA-JP에게만 허용됩니다.
- 해상도를 바꿀 때마다 `adb -s emulator-5554 shell wm size`로 실제 적용 값을 확인하고 적습니다. 재시작 후 시리얼이 바뀌면 새 시리얼을 적습니다.
- 16:10에서는 게임 화면 위아래에 검은 여백이 생기는지 스크린샷으로 확인합니다(H-1 판단 근거).
- 끝나면 **1920×1080, density 240으로 되돌립니다.**

### QA-KR (태블릿) — 실제 기기 그대로 재현합니다

| 번호 | 점수 필터 | 목적 |
|---|---|---|
| K1 | +16만 | 실기기 재현 |
| K2 | +62만 | 실기기 재현 |
| K3 | +62와 +16 둘 다 | 소유자가 실패를 본 조합 |
| K4 | 둘 다 끔 | 대조군. 정상적으로 고르는지 확인 |

- 태블릿 화면 설정은 바꾸지 않습니다(3절).
- 스크린샷으로 게임 화면에 위아래 검은 여백이 있는지, 게임 화면의 실제 크기가 얼마인지 적습니다. 원본 스크린샷이 고해상도이므로 **점수 영역을 원본 해상도로 잘라 낸 이미지**도 실험마다 3장 남깁니다(H-2 판단 근거: 원본에서는 숫자가 또렷한지).

## 6. 보고 형식

각 QA agent가 따로 보고합니다.

```
기기 | 모델 | wm size | density | FGA 버전
실험 | 해상도 | 필터 | 후보 수 | Class 읽힘 | Grand 읽힘 | unknown/unknown | matched=true | 화면상 실제로 맞는 후보 수
```

- "화면상 실제로 맞는 후보 수"는 스크린샷을 보고 셉니다. 확신이 없으면 "판단 불가"로 적습니다.
- 대표 점수 영역 이미지: 실험마다 성공 1장, 실패 2장
- 레터박스(위아래 검은 여백) 유무와 게임 화면 실제 크기
- 결론 한 줄
  - QA-JP: 0005 A0 판정표의 어느 줄인지
  - QA-KR: 실기기에서 재현됐는지, 원본 해상도 crop에서 숫자가 사람 눈에 또렷한지
- 하지 못한 실험과 그 이유, 되돌린 설정 목록, 사용한 AP와 퀘스트 실행 횟수

## 7. 이후 (A단계 베타가 나온 뒤)

- 같은 실험을 진단 저장을 켠 상태로 반복합니다. 진단 폴더를 PC로 옮겨 자기 결과 폴더의 `diagnostics/`에 둡니다. 태블릿에서 파일을 꺼낼 때는 진단 폴더만 `adb pull`합니다.
- 라벨은 소유자가 붙입니다. QA agent는 라벨 도구로 **제안 라벨**만 붙일 수 있고, `labels.proposed.json`에 따로 저장합니다.
