# 실전 확인 절차: 서포트 점수 판독 (블루스택)

- 대상 설계: [0005](../design/0005-support-score-accuracy.md) A0단계, 이후 A단계 표본 수집
- 수행: **QA agent**. 구현 agent와는 다른 agent가 맡습니다.
- 결과물: `build/live-qa/<YYYYMMDD-HHMMSS>/`의 로그와 스크린샷, 그리고 아래 보고 형식의 보고서

이 절차서는 소유자의 실제 게임 계정이 로그인된 블루스택을 다룹니다. **"금지 행동"을 어기는 조작은 어떤 이유로도 하지 않습니다.** 판단이 애매하면 멈추고 소유자에게 묻습니다.

## 1. 시작 전 확인

- **블루스택 사용권:** 구현 agent가 같은 블루스택 인스턴스를 쓰고 있지 않은지 소유자에게 확인받은 뒤 시작합니다. 두 agent가 동시에 adb로 같은 인스턴스를 조작하면 설치나 기기 검사가 깨집니다.
- adb는 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe` 하나만 씁니다. `adb devices`로 연결된 기기를 확인하고, 시리얼(기본 `127.0.0.1:5555`)을 보고서에 적습니다.
- 설치된 FGA 앱의 패키지와 버전을 적습니다. `adb shell dumpsys package <패키지> | findstr versionName`을 쓰고, 베타는 `io.github.fate_grand_automata.beta`입니다.
- 현재 블루스택 해상도와 DPI를 적습니다(`adb shell wm size`, `adb shell wm density`).

## 2. 금지 행동

- 성정석, 황금 사과·은 사과·동 사과 등 **AP 회복 아이템 사용**, 상점 구매, 과금 화면 진입
- 소환(가챠), 서번트·예장 강화·영기재림·판매·보관고 정리
- 친구 추가·삭제·신청 수락, 프로필·계정 설정 변경, 인계 코드 관련 화면
- 퀘스트 시작. 단, 소유자가 미리 지정한 퀘스트만 예외로 허용합니다(5절).
- 게임이나 FGA의 데이터 삭제, 앱 제거, 블루스택 인스턴스 초기화
- FGA 설정 중 이 절차에 적힌 항목 외의 변경. 바꾼 항목은 끝나고 원래 값으로 되돌립니다.

## 3. 로그 수집 방법

```bash
adb -s 127.0.0.1:5555 logcat -c
adb -s 127.0.0.1:5555 logcat -v time -s FGA.SupportScore:I
```

- 실험마다 로그를 따로 파일로 저장합니다.
- 각 줄의 `Support Class/Grand: X/Y, required: a/b, display: D, matched: M`을 집계합니다.
- 실험마다 서포트 화면 스크린샷을 1장 이상 남깁니다(`adb exec-out screencap -p`). 보고서에 넣는 이미지는 **친구 이름 영역을 가리거나 점수 영역만 잘라서** 넣습니다.

## 4. 실험 (A0)

모든 실험의 공통 조건:
- FGA 서포트 설정: 보구 레벨 필터는 소유자 설정 그대로 둡니다.
- 점수 필터는 실험마다 지정한 대로 켭니다.
- 서포트 화면에서 FGA를 실행합니다. 점수 필터가 실패하면 FGA가 계속 새로고침하므로, **퀘스트를 시작하지 않고도** 표본이 쌓입니다. 후보 30개 이상 또는 5분이 지나면 FGA를 멈춥니다.
- FGA가 서포트를 골라 편성 화면으로 넘어가면, **"퀘스트 시작"을 누르기 전에** FGA를 멈추고 뒤로 가서 서포트 화면으로 돌아옵니다. 멈추기 어려우면 5절의 지정 퀘스트에서만 실험합니다.

소유자 기기는 **Lenovo Legion Y700 (2025)** 태블릿입니다. 공개 사양은 3040×1904(16:10)입니다.

| 번호 | 블루스택 해상도 | 서버 | 점수 필터 | 목적 |
|---|---|---|---|---|
| E1 | 1920×1080 (16:9) | KR | +16만 | 기준선 |
| E2 | 1920×1080 (16:9) | KR | +62만 | 기준선 |
| E3 | 1920×1200 (16:10) | KR | +16만 | 비율만 변경 (H-1) |
| E4 | 1920×1200 (16:10) | KR | +62만 | 비율만 변경 |
| E5 | 3040×1904 (16:10), 안 되면 2560×1600 | KR | +16만 | 비율 + 축소 배율 (H-1 + H-2) |
| E6 | E5와 같음 | KR | +62만 | 비율 + 축소 배율 |
| E7~E12 | E1~E6과 같음 | JP | | JP가 설치·로그인된 경우만 |

- 해상도는 블루스택 설정 → 디스플레이 → 사용자 지정에서 바꿉니다. 블루스택을 재시작해야 할 수 있습니다. 실험이 끝나면 **원래 해상도로 되돌립니다.**
- 실험마다 `adb shell wm size`의 결과를 적습니다. 블루스택이 요청한 해상도를 실제로 적용했는지 확인하기 위해서입니다.
- 16:10에서는 게임 화면 위아래에 검은 여백이 생기는지 스크린샷으로 확인하고 적습니다(H-1 판단 근거).
- 선택 실험 E13: 소유자가 태블릿의 USB 디버깅을 켜고 PC에 연결해 주면, 태블릿에서 같은 로그를 수집합니다. 금지 행동은 태블릿에도 똑같이 적용합니다. `adb shell wm size` 결과도 적습니다.

## 5. 퀘스트 허용 범위 (소유자가 채움)

2026-10-18 소유자 지정:

- 허용 퀘스트: **메인 레코드 → 1부 서장 특이점 F 염상오염도시 후유키 → 미확인 좌표 X-A** (AP 3)
- 허용 AP: **자연 회복 AP만.** 황금·은·동 사과, 성정석 등 AP 회복 재화는 **사용 금지**입니다. FGA의 AP 회복(Refill) 설정은 꺼진 상태인지 확인하고 시작합니다.
- AP가 3보다 적으면 퀘스트를 실행하지 않고, 서포트 화면 실험(퀘스트 시작 전에 멈추는 방식)만 합니다.
- 최대 실행 횟수: 실험 하나당 1회. FGA 실행 횟수 제한을 1로 둡니다.
- 위 퀘스트의 서포트 화면이 실험에 맞지 않으면(+62·+16 서포트가 없는 등) 다른 퀘스트로 바꾸지 말고 보고합니다.

## 6. 보고 형식

```
실험 | 해상도 | 서버 | 필터 | 후보 수 | Class 읽힘 | Grand 읽힘 | unknown/unknown | matched=true | 화면상 실제로 맞는 후보 수
```

- "화면상 실제로 맞는 후보 수"는 스크린샷을 보고 셉니다. 확신이 없으면 "판단 불가"로 적습니다.
- 대표 점수 영역 이미지: 실험마다 성공 1장, 실패 2장
- 결론 한 줄: 0005 A0 판정표의 어느 줄에 해당하는지
- 하지 못한 실험과 그 이유
- 되돌린 설정 목록(해상도, FGA 설정)

## 7. 이후 (A단계 베타가 나온 뒤)

- 같은 실험을 진단 저장을 켠 상태로 반복합니다. 진단 폴더를 PC로 옮겨 `build/live-qa/<시각>/diagnostics/`에 둡니다.
- 라벨은 소유자가 붙입니다. QA agent는 라벨 도구로 **제안 라벨**만 붙일 수 있고, 제안 라벨은 `labels.proposed.json`에 따로 저장합니다.
