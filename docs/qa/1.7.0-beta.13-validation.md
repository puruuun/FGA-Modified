# 1.7.0-beta.13 검증 기록

## 변경
1. **#121 FP 배너 위치 1~7:** 라디오 두 개를 숫자 스테퍼(1~7, 기본 1)로 바꿨습니다. 범위는 `FpBannerReturn.POSITIONS` 한 곳에 있고 UI도 같은 값을 씁니다. 저장 키 `fpBannerPosition`(Int)은 그대로입니다. 자세한 내용은 `1.7.0-beta.13-fp-banner-position-7.md`.
2. **#122 목록 끝 상자의 와이드 기준점:** beta.6(#90)이 와이드 화면에서 화면 중앙에 맞춘 상자(`FpSellLocations.bottomScrollbarRegion`, `WeeklyRouteLocations.topScrollbarRegion`/`bottomScrollbarRegion`)를 모든 비율에서 `xFromRightEdge()`(오른쪽 끝 - 여백 171)로 되돌렸습니다. 레일은 18:9~21:9에서 오른쪽 끝 기준으로 움직이므로, 중앙 기준 상자는 2340x1080에서 1440p로 약 84~156 px 빗나갔습니다.
   - 2340x1080(스크립트 영역 3120x1440): FP 아래 상자 x=2395..2467(레일 중심 2432), 주간 상자 x=2867..2941(레일 중심 약 2904). 상자 크기와 임계값(주간 0.60, FP 0.72)은 그대로이고, 폭을 넓히지 않았습니다.
   - 21:9 프레임(1680x720)에서도 점수가 같거나 비슷합니다(주간 3 px 차이는 상자 폭 안).
   - 21:9보다 넓은 프레임(2560x1080)은 기기의 `FgoGameAreaManager`(`isUltraWide`)처럼 가운데 21:9로 잘라서 잽니다. `ScrollbarFixtureTest`의 `score()`와 `tools/device-qa/scroll_scores.py`가 같은 자르기를 합니다. `FgoGameAreaManager`는 건드리지 않았습니다.
   - 기기 QA 하니스(`app/src/androidTest`의 `FixtureApi`)는 `FgoGameAreaManager`를 거치지 않고 프레임 폭 그대로 영역을 만들지만, 저장소 안 고정 프레임은 모두 21:9 이하(최대 1680x720)라서 손대지 않았습니다.
   - 자르지 않는 쪽의 부정 사례로 KR 2340x1080 FP 목록 맨 위 프레임을 1560x720 무손실 WebP로 추가했습니다(`docs/reference-images/Kr/fp-sell/list-top-2340.webp`, `fpSell.json`, `ScrollbarFixtureTest`).
   - 안 한 것: #122에 적힌 정지 화면 보조 장치(stationary-page backstop)는 이 베타 범위 밖이라 넣지 않았습니다.

## 소유자 확인
- FP 배너 위치 1, 2, 3 이상: 맞는 위치에서 판매 후 같은 배너에서 소환이 이어지고, 틀린 값이면 소환하지 않고 멈추는지.
- BlueStacks 2340x1080에서 FP 자동 판매가 `no-new-taps`가 아니라 `reason=scrollbar-end`로 목록 끝에서 멈추는지.
- 주간 목록 탐색이 2340x1080, 2560x1080, 태블릿에서 위와 아래 끝에서 모두 멈추는지.
