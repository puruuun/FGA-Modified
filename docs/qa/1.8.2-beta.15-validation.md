## 바뀐 것

beta.14:
- 서포트 목록 필터가 남긴 친구의 관위 칸(`userSvtGrandHash`)을 받은 그대로 둠 (#706, PR #709). beta.11~13은 맞지 않는 관위 칸을 서버가 보내지 않는 빈 형태로 바꿨다
- 시작창 필터 패널 (#708, PR #711): 체크박스, "가져오기" 아래 스크립트/프로필 버튼, 패널 열림 상태 기억, 결과 줄 "필터 결과: N명 중 M명 표시", 아이템 자동 사용 안내문 삭제, 전투 설정의 서번트 선호 화면을 #685 이전 모습으로 되돌림
- 기기 QA 실행기가 adb 연결 실패를 다시 시도하고, 돌지 못한 스위트를 이름으로 알리며 종료 코드 2로 끝남 (#703, PR #707)
- CI: `test-and-build`의 Gradle 캐시를 main이 채움 (#701, PR #712). PR #715와 #716의 `test-and-build`가 main에서 저장한 항목을 복원한 것을 로그로 확인

beta.15:
- 서포트 목록 필터의 관위 조건 (#704, PR #714): 관위 서번트, 그랜드 스코어 +16, 인연예장 효과, 일반·보상 예장 모두 일치. KR과 JP에 같은 규칙. KR은 관위 목록이 비어 있어 관위 조건을 켜면 아무도 남지 않음
- 제3자 고지 검사기의 빌드 파일 판독 보강 (#680, PR #713)

구현과 검증의 모델, 회차별 지적은 각 PR의 "Planner record" 댓글에 있다.

## 확인한 것

- 단위 테스트: PR #714 head에서 전체 4,295개(app 2,120, prefs 71, scripts 2,104), 실패 0. 검증자가 따로 실행
- PR #714: 검증자 2명(서로 다른 모델). 첫 회차는 둘 다 반려(+16이 친구의 해방 클래스 목록으로 관위 보드를 찾음, 인연예장 효과의 예상 밖 값을 기본 효과로 읽음), 수정 뒤 둘 다 통과
- PR #709: 검증자 2명 통과. PR #711: 검증자 1명 통과 뒤 문자열·안내문 변경은 플래너가 읽음. PR #712, #713: 검증자 1명 통과(#713은 첫 회차 반려 뒤 통과)
- 이 두 베타에서 기기 QA 스위트는 돌리지 않았다. 화면 판독, 탭, 좌표, 템플릿을 바꾼 PR이 없다

## 확인하지 않은 것 (오너가 기기에서)

- 태블릿의 새 필터 패널: beta.12에서 버튼 글자가 눌려 보이던 것의 원인은 확인하지 못했다. 열린 채 복원된 패널의 창 폭, 프로필 이름 입력 창
- JP: 관위 서번트·+16·인연예장 효과·모두 일치 조건을 켰을 때 게임 화면의 표시와 필터 결과가 같은지. `equipTarget2`가 인연예장이고 `equipTarget2SkillChange` 1이 NP 충전이라는 것, +16이 관위 보드 16칸이라는 것은 응답 구조와 Atlas Academy 공개 데이터에서 얻은 것이고 기기에서 확인하지 않았다
- JP: 일반 칸이 모두 빈 칸이고 관위 칸만 남은 친구를 골라 출격하는 흐름
- OpenCV 5.1.0의 실제 화면 캡처와 주간 미션 경로 (beta.12부터 이어진 항목)

## 알려진 문제

- 클래스 스코어 +62는 친구의 해방 클래스 목록으로 보드를 찾는다(main 그대로). KR 응답에는 실더·룰러가 어느 보드에도 없어 이 클래스는 +62 조건에서 항상 맞지 않는다. 게임이 그 클래스에 +62를 표시하는지 확인되지 않았다
- 플래너의 스크래치패드를 하위 에이전트가 함께 쓰는 탓에 플래너의 보조 스크립트가 지워진 일이 있었다. 저장소와 빌드에는 영향이 없다
