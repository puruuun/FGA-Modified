# 1.6.2-beta.7 / 1006207 검증

설계 0017 D-1/D-2. `feat/weekly-list-scrollbar`에서 PR로 전달하며 병합은 기획자가 합니다. 이번 시험 APK는 요청에 따라 Main CI가 통과한 PR 브랜치 HEAD에서 `:app:assembleBeta`로 빌드합니다. APK 검증·해시·설치 및 CI 링크는 PR 검증 기록에 남깁니다. GitHub Release는 만들지 않습니다.

## 구현과 판정

- 720p 레일의 중심 8열, y=95..589 밝기 프로필에서 밝은 손잡이의 연속 구간을 찾습니다. 레일·손잡이가 불명확하면 `unknown`입니다. 1440p 좌표는 `WeeklyRouteLocations.listScrollbar`에 두고 `xFromRightEdge`로 0012의 와이드 여백 171을 적용합니다.
- 위치는 손잡이가 이동할 수 있는 거리로 정규화한 0..1입니다. 끝 8px는 테두리·뾰족한 손잡이 끝의 오차를 허용합니다. QA 허용 오차는 0.025입니다.
- 현재 화면부터 검색하고 이미 확인한 끝 방향을 건너뜁니다. 각 스크롤 후 최종 화면을 한 번 검색합니다. 손잡이가 끝이면 종료하되, D-2에 따라 목록이 움직였으면 해당 끝 판독을 불신하고 한 번 더 확인합니다. 목록이 그대로면 즉시 방향을 종료합니다. 어느 판단도 없으면 방향별 최대 14회를 유지합니다.
- 이동 비교는 인물·헤더·MENU·레일을 제외한 배너 열의 회색 픽셀입니다. 12단계보다 큰 변화가 1%를 넘으면 이동으로 봅니다. 압축·작은 밝기 차이는 무시합니다. 실제 스크롤 전후 신규 캡처는 점검으로 확보하지 못했으며 이동 판정은 합성 단위 테스트로 검증했습니다.
- `WeeklyRoute`에 스크롤마다 `scrollbar=0.00..1.00|unknown`, `moved=true/false|unknown`, 방향 시작·전환·종료·건너뛰기 사유와 끝 판독 불신을 기록합니다.
