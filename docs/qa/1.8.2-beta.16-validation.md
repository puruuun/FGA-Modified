## 바뀐 것

- 시작창 필터 패널 (PR #719): "스크립트"·"프로필" 버튼을 "모두 초기화"와 같은 크기로. 서포트 필터 칩과 패널은 전투 설정을 골라 출발하는 시작창에서만 나온다. 다른 시작창은 저장된 패널 열림 상태와 상관없이 필터가 생기기 전 모습이다
- 체인 우선순위 공개 (#721, PR #722): `ChainPriorityAvailability.SHOWN = true`. 매뉴얼은 카드 우선순위 페이지(한·영·일)의 한 절로 들어갔다. 전투 설정 요약의 체인 순서는 해당 웨이브 카드 목록 아래 별도 줄로 나온다
- 서포트 목록 필터가 남긴 친구의 관위 목록에서 조건에 맞지 않는 항목을 뺀다 (#720, PR #723). 빈 칸 형태로 바꾸지 않고 목록에서 제거한다. 조건에 맞아 남는 일반·이벤트 칸과 `userSvtId`가 같은 관위 항목은 맞지 않아도 받은 그대로 둔다
- Rust 4차 (PR #725): 서포트 스코어 엔진이 부호가 잘못 읽힌 줄을 답한다. 응답 형식 `FSC2`(플래그 필드), 진단 `engine.signCorrected`, 스캔 로그 `rust.signCorrected`

구현과 검증의 모델, 회차별 지적은 각 PR의 "Planner record" 댓글에 있다.

## 동작이 달라지는 설정 (체인 우선순위 공개)

- 체인 우선순위를 건드리지 않은 설정은 beta.15와 같은 탭·판독·대기·카드 선택이다. 기록된 선택과 trace를 비교하는 테스트가 운영 스위치 값으로 돈다
- 브레이브 체인이 "항상"으로 저장돼 있고 그 항목의 체인 우선순위가 꺼진 설정은 beta.15에서 "없음"처럼, 이제 "보구랑 같이"처럼 동작하고 서번트 카드 확인이 켜진다 (#654의 오너 결정 4). 지금 있는 설정에서는 원본 FGA에서 가져온 경우에만 생긴다. 이 빌드부터는 앱 안에서도 생긴다(체인 우선순위를 켜고 "항상"을 고른 뒤 끔)
- beta.12~15에서 원본 FGA의 체인 우선순위 켜진 설정을 가져왔다면, 이제 실제로 체인 우선순위로 싸운다

## 확인하지 않은 것 (오너가 기기에서)

- 체인 우선순위를 켠 실제 전투: 선택형 스킬, 변신, 서포트 교체가 있는 경우. 21:9 화면의 보구 타입 판독은 캡처가 없다
- JP: 관위 조건을 켰을 때 남은 친구에게 맞는 관위 서번트만 보이고 다른 클래스 탭에 그 친구가 나오지 않는지, 골라서 출격되는지. 관위 목록이 빈 목록이 된 친구, 예장 조건만 걸어 보호 규칙이 적용된 친구
- 부호 보정으로 답한 줄이 실사용에서 맞는 값인지 (진단의 `engine.signCorrected`). KR과 다른 기기에서는 측정이 없다
- BlueStacks, MuMu에서의 기기 QA와 설치
- beta.15 기록의 남은 항목: 필터 관위 조건(+16, 인연예장 효과)의 화면 일치, OpenCV 5.1.0의 실제 캡처와 주간 미션 경로

## 알려진 문제

- 브레이브 체인 목록이 웨이브 수보다 짧게 저장된 설정에서 전투는 마지막 값을 반복하고 카드 우선순위 화면은 모자란 웨이브를 "없음"으로 읽어 저장한다 (#724, 이전부터 있던 문제)
- 클래스 스코어 +62는 친구의 해방 클래스 목록으로 보드를 찾는다. KR 응답에는 실더·룰러가 어느 보드에도 없어 이 클래스는 +62 조건에서 항상 맞지 않는다. 게임이 그 클래스에 +62를 표시하는지 확인되지 않았다
- 시작창의 고정 비율 패널 분기와 두 시작창의 `sidePanel` 인자는 이제 도달하지 않는 코드로 남아 있다
