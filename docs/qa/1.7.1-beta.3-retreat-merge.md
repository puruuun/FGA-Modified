# 1.7.1-beta.3 퇴각 후 재시작 통합 검증 기록 (#135)

기기와 게임은 조작하지 않았습니다. 단위 테스트와 컴파일만 확인했고, 실기기 확인은 소유자가 베타에서 합니다.

## 변경 요약

- 전투 설정의 스위치 하나("퇴각 후 재시작")로 전멸 퇴각과 N턴 도달 퇴각을 함께 다룹니다. 꺼짐이면 전멸 시 `WithdrawDisabled`로 정지, 켜짐 N = 0이면 전멸 퇴각만, N ≥ 1이면 둘 다 합니다.
- N은 0~99, 기본값 0입니다. 한국·일본 서버 밖에서는 N이 0으로 동작하고 입력이 0으로 잠깁니다.
- 전멸 퇴각은 기존 탭 순서를 그대로 쓰되, 턴 제한 퇴각처럼 `abandonRun()`으로 초기화합니다. 주회로 세지 않고, 퇴각 횟수와 연속 횟수에 더하며, 연속 횟수를 되돌리지 않습니다.
- 전역 "퇴각 활성화"를 UI와 스크립트 인터페이스에서 제거했습니다. 저장된 `withdraw_enabled`는 일회성 이전에만 읽습니다 (`retreat_merge_migrated` 플래그).
- 종료 화면은 "퇴각 N회 (전멸 a회, 턴 제한 b회)" 한 줄입니다. 설정 창에서 초기화 버튼을 없앴습니다.
- 원본 FGA 가져오기(`OriginalFgaImporter`)는 전역 설정을 가져오지 않고 전투 설정 파일만 가져오며, 이 기능의 키가 없으므로 가져온 설정은 꺼짐입니다. 수정할 매핑이 없습니다.

## 소유자 실기기 확인 (BlueStacks 한국/일본)

1. N = 0에서 파티 전멸: 퇴각 후 퀘스트가 다시 시작되고 주회가 늘지 않음.
2. N ≥ 1에서 N턴 전에 전멸: 전멸 퇴각으로 처리되고 다시 시작됨.
3. "3회 연속 퇴각 시 정지": 전멸과 턴 제한을 섞어 3회 연속이면 정지.
4. 종료 화면 "퇴각 N회 (전멸 a회, 턴 제한 b회)" 한 줄.
5. 1.7.1-beta.2에서 "퇴각 활성화"를 켜 둔 채 업데이트: 꺼져 있던 전투 설정이 "전멸 시 퇴각"(켜짐, N = 0)으로 바뀜.
6. 다른 서버 설정 창에서 N 입력이 0으로 잠김.
7. 전투 설정을 열었을 때 설정 줄 이름과 값 ("퇴각 후 재시작", "꺼짐" / "전멸 시 퇴각" / "N턴 도달 시 퇴각").

전체 기기 QA는 전투 흐름(`AutoBattle`, `Withdraw`, `Battle`)이 바뀌었으므로 모든 스위트를 실행해야 합니다.
