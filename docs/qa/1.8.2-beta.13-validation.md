## 확인한 것

- 이 표가 세 기기, 두 버전 모두에서 같다
- 케이스 이름으로 맞춘 통과 여부도 전부 같다
- `weeklyRoute`의 `mapMotion` 12케이스(SIFT `featureMatches`와 `MapLocalizer.fit`)는 기기 3대 모두에서 matches, inliers, rms, origin, scale이 4.11과 5.1.0에서 같은 값이다
- skip은 BlueStacks의 `/sdcard`에만 있는 옛 케이스 파일(support 21, questItems 8)과 빌드에 넣지 않는 ort·tract-threads 기능(ocrProbe 8)이다
- main을 합친 최종 커밋(463c643f)에서 세 기기로 npType, support, cardSwap, hakunoShuffle, weeklyRoute, noblePhantasm, nativeProbe를 다시 돌려 모두 통과

실행 중 adb 클라이언트가 서버에 연결하지 못하는 시간 초과(10060)가 여러 번 났다. PC가 다른 빌드로 바쁠 때였고 서버 프로세스는 그대로였다. 돌지 못한 스위트는 다시 돌렸다. 테스트 실패로 다시 돌린 것은 없다. 도구 보완은 #703.

### 체인 우선순위 (PR #693)

- `npType` 13케이스: 세 기기 모두 13/13
- 상세 창의 보구 색: KR 버스터 0.975~0.997, 아츠 0.997, 퀵 0.999. JP 버스터 0.989, 아츠 0.993, 퀵 0.997. 다른 색은 0.18 이하
- 배너가 덮인 화면: 어떤 색도 0.10을 넘지 않고, 남은 턴 숫자를 KR 전용 영역으로 "3"과 "1", JP는 업스트림 영역으로 "1"로 읽음
- 보구 카드 초상 비교: 자기 카드 0.947~0.967, 다른 카드 0.49~0.58. PC 측정에서는 한 쌍이 0.73이었다. 기준 0.80은 오너 결정으로 업스트림 값 그대로 둔다
- 끈 상태가 main과 같다는 것은 단위 테스트의 고정 기록(카드 선택, 탭·판독·대기·로그)으로 확인했다. 기기에서 따로 확인하지 않았다

### 서포트 목록 필터 (PR #690, #696)

- 기기 QA 스위트 없음. 단위 테스트와 프록시 수준 테스트로 확인: 요청 바이트 불변, 기능 스위치나 토글이 꺼지면 응답 바이트 동일, 맞는 칸은 원본 객체 그대로
- JP와 KR의 `follower/list` 구조를 MuMu의 진단 파일로 읽음(값 없이 구조와 분포만): JP에도 `userClassBoardInfo`가 있고 보드 8·9의 클래스 번호를 확인. `dispLimitCount`는 0~3과 11 이상

## 확인하지 않은 것 (오너 확인 필요)

- 서포트 목록 필터 새 방식: 기능 스위치, 시작창 패널에서 조건 가져오기, 토글 후 목록 갱신으로 걸러지는지, 스크립트를 돌려도 유지되는지, 끄면 풀리는지
- 프로필 이름 대화상자: 빈 이름이면 확인이 꺼지는지, 추가 뒤 편집 화면으로 가는지, 이름 바꾸기, 삭제, 앱 재시작 뒤에도 그대로인지. 자동 테스트로 실제 대화상자를 조작하지 못했다
- 재림 모습 조건의 값 대응(0~3은 1·2·3·최종 단계, 11 이상은 영의)
- OpenCV 5.1.0의 실제 화면 캡처 경로(MediaProjection, 루트 캡처)와 실제 주간 미션 지도 드래그·확대. 스위트는 저장된 이미지를 쓰고, SIFT 케이스의 두 번째 프레임은 합성이다
- 체인 우선순위: 21:9 화면, 실제 게임에서 끈 설정과 켠 설정
- macOS BlueStacks Air: 확인할 기기가 없다. 5.1.0은 `HWCAP_SVE`와 `HWCAP2_SVE2`가 둘 다 있을 때만 SVE2 경로를 탄다. 오너가 받아들인 위험
