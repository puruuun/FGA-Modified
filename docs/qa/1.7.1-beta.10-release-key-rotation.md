# 1.7.1-beta.10 개인 서명 키로 교체 (#128)

## 변경

정식판(`…cardcount`)과 베타(`…beta`) APK의 서명을 공개 디버그 키(`fgadebug`)에서 오너 개인 키로 바꿨습니다. APK 서명 v3 키 교체(lineage)를 써서, 앱을 지우지 않고 업데이트만 하면 됩니다.

- **서명 방식:**
  - `assembleCi`와 `assembleBeta`가 끝나면 `signCiRotated` / `signBetaRotated`가 APK를 그 자리에서 다시 서명합니다. 넣는 서명은 다음과 같습니다.
    - v2: `fgadebug`
    - v3: 오너 키
    - `--lineage app/signing/fga-lineage.bin --rotation-min-sdk-version 28`
  - 키 위치와 비밀번호는 `%USERPROFILE%\.fga-signing\signing.properties`에서 읽습니다. 비밀번호는 환경 변수로만 apksigner에 넘겨서 명령 줄과 로그에 나오지 않습니다.
  - 키나 연결 파일이 없거나 서명이 실패하면 빌드를 멈추고 디버그 서명 APK를 지웁니다.
  - CI(`CI=true`)와 `-PfgaDebugSigning=true` 빌드는 디버그 서명만 하는 시험용입니다. 이 APK는 교체된 앱 위에 설치되지 않습니다.
- **연결 파일:** `app/signing/fga-lineage.bin`. 오너가 직접 만들었고, `fgadebug` → `CN=puruuun, O=FGA-Modified` 순서로 인증서 2개가 들어 있습니다. 되돌리기(rollback) 기능은 꺼져 있습니다.
- **새 인증서 SHA-256:** `563754b164de0d4209191f728ebb26644d53b0fbc0a47d5c8eb6a327b5dbe8f8`
- **워크플로:** `stable.yml`과 `beta.yml`을 지웠습니다. 정식판과 베타는 이 PC에서 빌드하고 서명합니다.
- **문서:** `docs/agents/releases-and-versioning.md`에 "Release signing" 절을 추가했습니다.
- **Android 버전별 동작:**
  - Android 9 이상은 업데이트 뒤 새 키 서명만 받습니다.
  - Android 7~8은 v2(`fgadebug`) 서명을 그대로 받으므로 재설치가 필요 없습니다. 대신 보호도 받지 못합니다.

## BlueStacks 업데이트 실험 (`127.0.0.1:5555`, 게임 조작 없음)

| 단계 | 결과 |
| --- | --- |
| 1.7.1-beta.9(`fgadebug`) 위에 회전 서명 beta.10 `install -r` | **성공.** `firstInstallTime` 2026-10-15 그대로라 지우지 않고 업데이트됐습니다. 접근성 서비스 목록에 beta가 그대로 있습니다. `PackageSignatures version:3`, past signatures 2개. |
| 그 위에 `fgadebug`로만 서명한 같은 버전 APK 설치 | **거부.** `INSTALL_FAILED_UPDATE_INCOMPATIBLE: … signatures do not match previously installed version` |
| 회전 서명 APK 재설치 | 성공. 정상 업데이트 경로입니다. |

- **정식판 패키지(`…cardcount`, 1.7.0) 실험:** 지금 하지 않았습니다. 아직 배포 전인 코드를 1.7.0 이름으로 오너의 정식 앱에 덮어쓰지 않기 위해서입니다. 정식판 1.7.1을 빌드한 뒤 GitHub Release를 게시하기 전에, BlueStacks의 1.7.0 위에 설치해서 같은 순서(업데이트 성공, `fgadebug` 전용 APK 거부)로 확인합니다.
- **알게 된 점:** 회전 서명 빌드 직후 `-PfgaDebugSigning=true`로 다시 빌드하면, AGP가 패키징을 건너뛰어 이미 회전 서명된 APK가 남습니다. 동작은 더 안전한 쪽이지만, 디버그 전용 APK가 필요하면 `app-*.apk`를 지우고 빌드해야 합니다.
