- 저장 화면의 제품 `CESelection.check` 경로로 내장 Foreign God·Chaldea Teatime, 최대 해방 켬, 양쪽 슬롯 일치 켬을 검사한다. 1행 NP=true / Default=false / Ignore=true, 부분적으로 보이는 3행은 Grand 라벨과 Default 아이콘을 확인하고 NP=false를 요구한다. 점수·영역·진단 로그는 support QA JSON 및 요약에 남긴다.

| 기기 판독 | NP 점수 | Default 점수 | 결과 |
|---|---:|---:|---|
| 1행 스카사하 | 0.739172 | 0.220356 | NP=true, Default=false, Ignore=true |

QA는 기존 프레임 처리 공식대로 2560×1080을 **1706×720**으로 축소하고 supportOffset.x=563(1440p)을 쓴다. 이슈의 호스트 측정은 1707×720이므로 점수가 다르다. 1행 NP의 기기 점수는 기존 0.80 미만이고 새 0.60 이상이다. 진단의 일반/보상 슬롯 점수는 0.9674/0.9823, 최대 해방은 모두 true다.

진단 한 줄의 형태(영역은 1440p): `FGA.SupportCe grand={present=true best=0.9249@Region(...)} normal={ce=Foreign God best=0.9674@Region(...) mlb=true} reward={ce=Chaldea Teatime best=0.9823@Region(...) mlb=true} mlbRequired=true bothSlots=true bond={setting=NP best=0.7392@Region(x=919,y=580,width=34,height=20) search=Region(x=911,y=550,width=53,height=67) np=0.7392@Region(...) default=0.2204@Region(...) threshold=0.6 matched=true} decision=true`.

## #25 친구 신청

- 옵션 끔: 기존 거절 동작은 `AutoBattleFriendRequestTest`가 실제 `AutoBattle.script()` 경로에서 확인한다. 옵션 켬·Preferred의 전송→1초 대기→새 화면 재검사 및 필요 시 거절도 단위 테스트 대상이다. 게임에서는 실행하지 않았다.
- JP 16:9: 로컬 참고 이미지 `build/orchestration/inputs/friend-request/jp/y_62443032c25dc.jpg`(1280×720)에서 `Location(680,1200).xFromCenter()` → `(980,600)`이 「フレンド申請する」 버튼(대략 x=787–1115, y=580–650) 안에 들어간다. KR·JP 와이드 실화면은 없어 **미검증**. 16:9·와이드의 좌우 대칭 좌표 공식은 기존 `WideScreenLocationsTest`로 확인한다.
- `friend-request sent=… fallbackReject=…`: 호출과 값은 기존 단위 테스트로 검사한다. **기기 logcat 출력은 미검증**이며 현재 `ScriptMessages`의 무태그 INFO 호출은 베타의 `FgaTree` 허용 태그에 포함되지 않아 필터링될 수 있다. 이번 #23 수정 범위에서 #25 로깅 동작은 변경하지 않았다.
- 상대 친구 목록 가득 참 팝업: 캡처가 없어 **미검증**.
