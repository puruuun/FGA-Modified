## 바뀐 것

- 카드 우선순위 화면이 웨이브 수보다 짧게 저장된 브레이브 체인과 카드 재배치 목록을 전투와 같은 함수(`PerEntrySettings.at`)로 읽는다 (#724, PR #745). 이전에는 모자란 웨이브를 "없음"·꺼짐으로 보여 주고 저장했다. 전투 쪽 코드는 바뀌지 않았다
- 그 밖은 beta.19와 같다
- 필터 진단 기록 (#738)은 원인이 밝혀져 하지 않기로 하고 닫았다 (오너)

- support와 questItems의 skip은 원본 범위가 맞지 않는 샘플로 이전 기록과 같은 수다. nativeProbe의 skip 2개는 암호 프로브, ocrProbe의 skip 8개는 ONNX Runtime과 tract 스레드 프로브로, 이 빌드에 넣지 않은 시험용 기능이다
- 단위 테스트: PR #745 head에서 전체 4,412개(app 2,203, prefs 71, scripts 2,138), 실패 0. 검증자 1명이 통과시켰고 두 가드 테스트가 수정 없이는 실패함을 확인했다
- 오너가 태블릿 beta.19에서 본 것: 필터 결과가 0명일 때 게임이 멈추지 않는다 (#741의 "친구 한 명을 남기고 칸을 비움"). 그래서 "받은 그대로 넘기기" 대안은 쓰지 않는다
- 서포트 스코어 엔진의 실사용 진단 (Rust 플래너가 태블릿의 진단 기록을 읽음): KR beta.19 실행에서 엔진이 읽은 `+62` 3줄이 모두 맞음. JP는 beta.16~19에서 7줄이 더 쌓여 모두 맞음. 누적 44줄, 틀린 값 0, 기존 판독기로 넘어간 경우 0. KR 표본은 3줄로 작다
- KR의 실더·룰러는 클래스 스코어가 게임에 아직 열리지 않아 `+62` 조건에 맞지 않는 것이 정상이다 (오너). 필터는 응답의 해방 클래스 목록을 읽으므로 게임에 열리면 코드 변경 없이 맞게 된다

## 확인하지 않은 것 (오너가 기기에서)

- 체인 우선순위를 켠 실제 전투 (KR, JP). 21:9 화면의 보구 타입 판독은 캡처가 없다
- 대시보드 퀘스트 기록·상점 블록의 일본어 문구
- 정규판 형태(`assembleCi -Pfga.native=true`)의 로컬 빌드는 릴리스 때 만든다. CI의 `engine-apk` 작업은 이 형태를 디버그 서명으로 만들어 `apk_check.py stable`을 통과시켰다

## 알려진 문제

- 저장된 브레이브 체인·카드 재배치 목록이 카드 우선순위 항목 수보다 길면, 화면에서 저장할 때 잘린다 (이전부터 있던 동작, PR #745 검증자 지적). 앱 화면은 항상 같은 길이로 저장하므로 가져온 설정이나 직접 고친 설정에서만 생긴다
- 네이티브 판독에 시간 제한이 없다 (#673). 지금까지 어떤 실행에서도 멈춘 적이 없다
- `PickerDownloadTest`가 전체 실행에서 가끔 실패한다 (#746). 계정 상태의 두 읽기 경로가 배열이 아닌 표를 다르게 다룬다 (#747)
- beta.19 기록의 나머지 알려진 문제(수집 시작 시점, KR에 관위 항목 없음)는 그대로다
