# 1.8.1 — NP Level on Long NP Names, Faster Skill Leveling & Root Capture Fix

This is stable release **1.8.1 / 3102**. It updates over 1.8.0 without uninstalling. Includes all changes from `1.8.1-beta.1~2`.

## Changed Features

- **Support NP level (JP)**: `Lv.N` is now read on lines where a long NP name squeezes the text horizontally. Supports such as Lord Logress and Solomon, which were skipped as "level unknown", can be selected. Lines that were read before are read the same way. [Guide](../scripts/Support-NP-Level-EN.md)
- **Skill and append skill auto leveling**: the skill icon is no longer tapped again when the same slot is leveled several times in a row. The tap is skipped only while the slot is shown as selected; moving to another slot, or an unclear selection, taps as before. Each enhancement is about one second faster. [Guide](../scripts/Auto-Skill-Level-EN.md)
- **Master skill menu wait setting**: the wait after the master skill button is tapped can be set from 300 to 3000 ms under **Fine-Tune → Wait**. The default stays at 1500 ms, as before. It applies to master skills and Order Change. [Guide](../scripts/Modified-Features-EN.md)
- **Log: friend points at login**: friend points received at login (for other players borrowing your supports) are recorded in the outside-script changes under the source **Login**. The log filter has a **Login** source too. [Guide](../scripts/Gains-Tracker-EN.md)
- **Chaldea file export**: the file holds only what Chaldea reads. The raw login response and the tables Chaldea does not use are left out, so the file is smaller, and the login record table that was missing is now included. [Guide](../scripts/Gains-Tracker-EN.md)
- **Manual**: a new page, [Log Collection Setup](../scripts/Log-Collection-Setup-EN.md), covers the first-time steps on one page, and the per-beta change history was removed from the feature pages.

## Fixed Issues

- **Root capture**: on a device with both the stable and the beta app installed, one app removed the other's capture rules, so the screen said "rules applied" while nothing was collected ([#493](https://github.com/puruuun/FGA-Modified/issues/493)). Each app now handles only its own rules, and when another FGA app is collecting with root, it shows a message and does not start. [Guide](../scripts/Capture-Root-EN.md)
- **Log collection**: an error such as running out of memory could stop the collection threads silently ([#483](https://github.com/puruuun/FGA-Modified/issues/483)). The error is now logged and collection ends cleanly.
- **Chaldea auto sync** ([#357](https://github.com/puruuun/FGA-Modified/issues/357), [#364](https://github.com/puruuun/FGA-Modified/issues/364))
  - When a write was interrupted and Chaldea is running, FGA keeps checking and recovers the file once Chaldea is closed.
  - A failure while the switch is being turned on no longer leaves the feature half enabled; it is reported as a failure.
  - Turning the switch off clears a pending permission request and a waiting root check at once.
- **Log file compatibility**: a source this version does not know is read as **Other**, so a later version that adds a source cannot make the whole log unreadable here ([#519](https://github.com/puruuun/FGA-Modified/issues/519)).

## Known Limitations

- **Support NP level**: reading squeezed lines is verified on JP only. The screen that squeezes the line is not on KR yet.
- **Root capture with 1.8.0 or older**: versions up to 1.8.0 do not check for another app. If an older app starts root capture while 1.8.1 is collecting, the two overlap for up to about a minute, then 1.8.1 stops with the message. With both apps on 1.8.1 or later, the second one is stopped at start.
- **Downgrading**: after a **Login** entry was recorded, a version up to 1.8.0 cannot read the outside-script log and starts with an empty list (the file stays on the device).
- The known limitations of 1.8.0 (Android 10+ and JP root for log collection, external proxy apps, split-screen touch) still apply. [1.8.0 release notes](1.8.0-EN.md)
