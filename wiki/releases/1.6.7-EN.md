# 1.6.7 — Missing-Card Priority Fallback & Fixes for Notice/Formation Stops

This is stable release **1.6.7 / 3094**. Retains the existing modified build package ID and signing.

- **Direct cards: fall back to priority when cards are missing** (`1.6.7-beta.1`)
  - Added a **"Fill missing cards by priority"** checkbox to the Direct cards dialog. Turning it on prepends `?` before that attack (e.g., `&?b4a`).
  - Secures the specified card colors from all slots first, and fills only the missing slots using the current card and Servant priorities. For example, for `B → NP1 → A`, with 1 Arts and 4 Quick cards, it attacks with `Q → NP1 → A`.
  - When off, it stops without tapping cards as before. [Guide](../scripts/Direct-Cards-EN.md).
- **Fixed stopping on Rank Up Quest unlock notice dialogs** (`1.6.7-beta.2`)
  - After clearing a Rank Up Quest, the Close button on the `"… has been unlocked!"` (`"…이(가) 개방되었습니다!"`) dialog was mistaken for the Storm Pod depleted dialog, returning to the quest list and stopping.
  - Now it simply taps the bottom-center Close button after battle and continues.
  - When Storm Pods run out, it stops at the insufficient-item dialog shown when tapping the next quest. The final run is counted only once.
- **Fixed stopping on the party formation screen after support selection** (`1.6.7-beta.2`)
  - On some devices, failing to recognize the party formation screen title caused it to stop without tapping Start Quest.
  - Removed title recognition and switched to fixed waits like original FGA: `support → 4s → party select → 1s → Storm Pod / Teapot → 1s → Start Quest`.
  - Starting the script directly from the party formation screen has been removed. Start from the quest list or support screen instead. [Guide](../scripts/Quest-Items-EN.md).
- Verification
  - On a tablet, the owner verified stopping when Storm Pods run out, run counting, the new launch sequence, and missing-card priority fallback.
  - The Rank Up Quest unlock notice dialog fix is based on a reported screen and could not be triggered again on a live device.
