**KR(한국)·JP(일본) 서버에 한정해 테스트했습니다. 다른 서버의 동작은 확인하지 않았습니다.**

## 추가·수정된 기능

<a id="card-start"></a>

### 1. 일반 카드 개수로 커맨드 시작

**커맨드 카드 개수 선택 모드** 토글을 켜고, 전투 시작 시 전열 1-3번 중 대상 서번트와 필요한 일반 카드 수(1-5장)를 지정합니다. 설정값 **이상**이 나오면 예약된 커맨드를 처음부터 시작합니다. 보구와 스턴 등으로 사용할 수 없는 일반 카드는 개수에서 제외합니다.

조건이 부족하면 스킬·보구·자동 사용을 보류하고 일반 공격으로 턴을 넘기며 다시 검사합니다. 최대 대기 턴도 설정할 수 있고, 0은 무제한입니다. 토글을 끄면 기존 기본 모드로 동작하며 작성한 설정은 보존됩니다.

<a id="dual-conditions"></a>

### 2. 두 서번트 조건과 우선 선택

두 번째 대상 서번트와 별도의 필요 카드 수를 추가할 수 있습니다. 두 조건은 같은 손패로 확인합니다.

| 첫 번째 조건 | 두 번째 조건 | 실행 |
|---|---|---|
| 충족 | 미달 | 첫 번째 설정 |
| 미달 | 충족 | 두 번째 설정 |
| 충족 | 충족 | 첫 번째 설정 우선 |
| 미달 | 미달 | 대기 공격 후 다음 턴 검사 |

하나를 선택한 뒤에는 해당 전투가 끝날 때까지 고정합니다. 다음 주회에서는 다시 조건을 검사합니다. 두 번째 대상에서 **사용 안 함**을 선택하면 단일 조건으로 동작합니다.

<a id="separate-settings"></a>

### 3. 조건별 커맨드와 카드 선택 설정

첫 번째·두 번째 설정에 각각 다른 **커맨드, 카드 우선순위, 서번트 우선순위 사용 여부와 순서, 브레이브 체인, 카드 재정렬**을 저장할 수 있습니다.

기본 설정과 첫 번째 설정은 같은 값을 사용하며 화면에 한 번만 표시합니다. 두 번째 설정은 그 아래에 추가됩니다. 복사·내보내기·가져오기에도 두 설정이 함께 포함됩니다.

<a id="command-timing"></a>

### 4. 기다린 만큼 커맨드 실행 위치 이동

실제 조건 충족 위치를 커맨드의 1웨이브 1턴으로 잡습니다. 예를 들어 실제 2웨이브 3턴에 시작하면 커맨드 1웨이브 2턴은 실제 2웨이브 4턴에, 커맨드 2웨이브 1턴은 실제 3웨이브 1턴에 실행합니다.

시작 후에는 카드 개수 조건을 다시 적용하지 않고 기존 커맨드를 계속 실행합니다. 기다리는 동안 웨이브가 바뀌어도 대기를 유지합니다.

<a id="shared-automatic-use"></a>

### 5. 스팸 모드와 카드 셔플을 공통 관리

**스킬·보구 자동 사용(스팸 모드)**과 **카드 셔플**은 조건별로 나누지 않고 기존 설정 한 곳에서 관리합니다. 어느 서번트 조건으로 시작하든 같은 설정을 사용합니다.

기존 첫 번째 설정의 자동 사용·셔플 값을 유지합니다. 이전 버전의 두 번째 자동 사용·셔플 값은 사용하지 않습니다. 파티·서버·서포트·자동 적 지정도 공통입니다.

<a id="first-turn-shuffle"></a>

### 6. 첫 턴 조건 부족 시 셔플 후 재검사

**카드 셔플 → 사용 조건 → 첫 턴 커맨드 시작 조건 불만족** 옵션을 추가했습니다.

1. 첫 웨이브 첫 턴에 시작 조건을 검사합니다.
2. 조건을 만족하면 즉시 해당 커맨드를 시작합니다.
3. 모두 부족하면 마스터 3번 스킬로 셔플을 한 번 시도합니다.
4. 새 손패로 두 조건을 다시 검사합니다.
5. 충족하면 같은 턴에 커맨드를 시작하고, 여전히 부족하면 새 카드로 일반 공격한 뒤 다음 턴으로 넘깁니다.

재검사에서도 두 조건이 동시에 충족되면 첫 번째 설정이 우선입니다. 셔플 자체는 대기 턴 수에 포함하지 않습니다. 전투 첫 턴에 최대 한 번만 시도하고 이후 턴·웨이브와 커맨드 시작 이후에는 반복하지 않습니다. 다음 주회에서는 다시 사용할 수 있습니다.

이 옵션은 카드 개수 선택 모드에서 사용하며, 마스터 3번 스킬이 카드 셔플인 마술예장을 장착해야 합니다. 기존 **없음 / 효과있는 카드 없음 / 보구와 맞는 카드 없음** 옵션도 유지됩니다.

<a id="recognition-and-target-loss"></a>

### 7. 설정 화면 정리와 예외 처리

- 모드 선택을 켜기·끄기 토글로 바꿨습니다.
- 기본 설정과 첫 번째 설정의 중복 표시를 제거했습니다.
- 시작 조건 박스에는 토글·대상·필요 카드 수·최대 대기 턴만 표시합니다.
- 같은 서번트를 두 조건에 지정하면 시작을 중단합니다.
- 한 대상이 전열에서 이탈하면 남아 있는 조건으로 기다리고, 대상이 모두 없으면 중단합니다.
- 카드 인식이 불명확하면 같은 손패에서 최대 세 번 확인한 뒤 공격 없이 중단합니다. 셔플 후에도 같은 처리를 적용합니다.

<a id="support-append"></a>

### 8. 서포트 어펜드 스킬 판독

**서포트 선택 → 서번트 선호**의 기존 일반 스킬 최대 레벨 설정 아래에 **어펜드 스킬 판독** 토글과 5개 `10 / x` 조건을 추가했습니다. `10`으로 지정한 슬롯이 모두 레벨 10인 서포트를 선택하며, `x`는 검사하지 않습니다. 잠긴 슬롯은 레벨 10으로 판정하지 않습니다.

기존 일반 스킬 등 선호 조건을 먼저 확인하고, 상단 스킬 전환 버튼을 한 번 눌러 어펜드 5개를 새 화면으로 검사합니다. 검사 후 버튼을 두 번 눌러 일반 표시로 복구합니다. 통과하면 해당 후보를 선택하고 불통과하면 다른 후보를 찾습니다. 전환·복구 확인에 실패하면 선택하지 않고 중단합니다.

기본값은 꺼짐이며 모든 슬롯이 `x`이면 화면 전환을 생략합니다. 설정은 복사·내보내기·가져오기에 포함됩니다. 자세한 설정과 제공된 한국·일본 화면의 검증 결과는 [어펜드 스킬 안내](Support-Append-Skills-KR.md)를 확인하세요.

### 9. 클래스 스코어 +62·그랜드 스코어 +16 판독

**서포트 선택 → 서번트 선호**에서 두 토글을 각각 켤 수 있습니다. `/` 앞은 클래스, 뒤는 그랜드입니다. 두 토글을 켜면 항상 적용되는 조건을 모두 만족해야 합니다. 조건 조합 선택은 제거했으며 이전 버전의 조합 설정은 사용하지 않습니다.

| 설정 | 일반 클래스 표시 (`+62`, `+0` 등) | 특수 클래스/그랜드 표시 |
|---|---|---|
| 클래스만 켬 | 클래스 +62 | 클래스 +62 |
| 그랜드만 켬 | 탈락 | 그랜드 +16 |
| 둘 다 켬 | 탈락 | 클래스 +62와 그랜드 +16 모두 |
| 둘 다 끔 | 스코어 조건 없음 | 스코어 조건 없음 |

그랜드 조건을 켜면 `/+16`이 실제로 표시돼야 통과합니다. 따라서 둘 다 켠 상태에서 일반 `+62`는 탈락합니다. 클래스만 켜면 일반 `+62`와 특수 `+62/+16` 모두 통과합니다. 특수 `+0/+16`은 그랜드만 켰을 때 통과하며 두 토글을 켜면 탈락합니다. 이 동작은 1.0.2-beta.3부터 적용하며, 이전 버전의 일반 표시에서 그랜드를 무시하던 규칙을 대체합니다.

스코어 검사는 보구·일반 조건과 함께 **어펜드 검사 전에** 실행합니다. 다른 선호 조건과 어펜드 조건은 모두 통과해야 합니다. 서번트·예장 이미지 없이 스코어 조건만 사용할 수도 있습니다. [설정 및 검증 범위](Support-Score-62-KR.md).

### 10. 해당 턴의 공격 순서 직접 지정

**커맨드 편집 → 공격 → 보구 전 공격 카드 옆 일반 카드 직접 지정** 버튼에서 세 장의 일반 카드·보구 순서를 설정합니다. 버스터·아츠·퀵은 상성을 구분하지 않으며, `&a4b`처럼 아츠 → 전열 1번 보구 → 버스터를 한 명령으로 저장합니다.

직접 지정한 턴은 브레이브 체인 선택·카드 재정렬·추가 보구 자동 사용을 적용하지 않습니다. 기본값은 필요한 일반 카드가 없으면 클릭 전에 중단합니다. **1.6.7-beta.1**부터 해당 공격의 **카드 부족 시 우선순위로 대체**를 체크하면 존재하는 지정 색을 먼저 모두 확보하고, 부족한 일반 카드 자리만 현재 웨이브·선택된 실행 설정의 카드·서번트 우선순위로 채웁니다(`&?b4a`). 판독 실패·불완전 손패·사용 가능 카드 부족·빈 보구 전열은 여전히 클릭 전에 중단합니다. 기본 방식의 턴은 그대로 실행합니다. **이 기능은 정규 버전 0.4.0에서 제공**하며 설정·문법·확인 범위는 [직접 지정 안내](Direct-Cards-KR.md)를 확인하세요.

### 11. 서포트 보구 레벨 판독 — 0.5.1

**서포트 선택 → 서번트 선호 → 보구 레벨 판독**을 켜고 **최소 보구 레벨**을 1~5 중 선택합니다. 예를 들어 Lv.3을 설정하면 보구 Lv.3·4·5가 통과합니다. 처음에는 꺼져 있고 최소 레벨의 초기 선택은 Lv.5입니다.

보구명 영역에서 `Lv.` 위치를 찾고 그 옆 숫자를 기존 Tesseract로 읽습니다. 보구명 길이나 숫자의 가로 위치가 달라도 검색하며, 판독 실패·낮은 신뢰도·기준 미달이면 다음 서포트를 찾습니다. 새 OCR 엔진이나 서버는 추가하지 않았습니다.

**스코어·보구 레벨을 포함한 모든 일반 선별 조건 → 어펜드 스킬 검사 → 서포트 선택** 순서로 동작합니다. 앞선 조건이 실패한 후보에서는 어펜드 확인을 위한 스킬 전환을 생략합니다. 보구·스코어·어펜드를 함께 켜면 모든 조건을 통과해야 합니다. [설정 및 검증 범위](Support-NP-Level-KR.md).

0.5.1에서는 기존 판독이 실패할 때만 여러 크기의 `Lv.`를 재탐색하고, 전처리를 바꿔 같은 숫자를 다시 확인합니다. 신뢰도가 높은 두 결과 이상이 일치해야 재검사에 통과하며, 다른 레벨이 함께 나오면 후보를 건너뜁니다. 긴 보구명에서 작아진 글자와 화면 축소 차이로 누락됐던 사례를 개선했습니다.

제공된 한국·일본 이미지 **16장의 보구 표시 44개 모두 일치해 제공 이미지 기준 100%**입니다. 실제 Lv.1~5를 포함하며, 두 정규화 방식의 88회 판독·최소 레벨 비교 440회·숫자가 없는 영역 176회 검사도 통과했습니다. 상단 일부 행 11개는 위치를 수동 지정했습니다. 데스크톱 이미지 검증 결과이며 실제 Android/FGO 자동 선택이나 모든 화면에서의 100% 정확도를 보장하지 않습니다.

### 12. 티포트·스톰포드 자동 ON/OFF — 0.7.0

**재생 버튼 → 실행 창**의 **AP 회복과 제한 사이**에 **스톰포드 사용 / 티포트 사용**을 추가했습니다. 체크하면 ON, 해제하면 OFF로 맞춥니다. 두 선택은 서버별로 기억하며 개별 전투 설정에 속하지 않습니다.

서포트 선택과 파티 선택 후 퀘스트 시작 전에 검사합니다. 직접 전환형과 설정창형을 구분하고, 설정창의 왼쪽 스톰포드·오른쪽 티포트를 각각 맞춘 뒤 닫습니다. 자동 설정 기능은 기본 켜짐입니다. **더 많은 옵션 → 추가기능 → 티포트·스톰포드 자동 설정 사용**을 켠 경우에만 실행 창의 선택을 적용합니다. 이전에 직접 저장한 사용·무시 선택은 유지합니다.

제공된 한국·일본 게임 화면 **9/9장**과 확대 ON 버튼의 판독이 통과했습니다. 실제 Android/FGO 조작은 아직 확인하지 않았습니다. 게임의 빠른 연속 주회가 파티 확인 화면을 생략하면 유지된 설정을 그대로 사용합니다. [자세한 동작 및 검증](Quest-Items-KR.md).

### 13. 인연포인트 누적·MAX 정지 — 0.9.2

**스크립트 수정 → 커맨드 시작 조건과 카드 셔플 사이의 인연포인트**에서 설정합니다. 결과창 왼쪽부터 캐릭터 1~5별 기본값+보너스를 퀘스트당 한 번 합산하고, 종료 화면에 합계·집계 횟수·누락 횟수를 표시합니다. 이름을 위에, 체크박스를 아래에 둔 가로 배치에서 **MAX 정지를 무시할 캐릭터**를 체크합니다. 2번을 체크하면 2번 MAX는 무시하고 계속 진행합니다. 체크하지 않은 캐릭터의 MAX가 확인되면 그 퀘스트 결과창에서 정지하여 다음 퀘스트를 시작하지 않습니다.

시작 전 편성·서포트 위치 판독을 제거했습니다. 결과창 칸 번호를 그대로 사용하며, 사용자가 편성 및 결과 순서를 조율합니다. 설정은 스크립트별로 저장·복사·내보내기합니다. 0.8.0의 실행 창 설정은 자동 이전하지 않으므로 사용할 스크립트에서 다시 켜세요.

일반 인연 결과창을 감지하면 1.2초 기다리고 새 화면에서 판독합니다. 이 시간은 앱 대기 배율로 줄어들지 않습니다. 레벨업 창의 가려진 증가량·MAX는 읽지 않습니다. 도달 레벨 10 이상과 결과 칸을 확정하면 정지 조건에 적용하고, 불확실하면 다음 퀘스트의 일반 MAX로 재확인합니다. 보석과 NEXT는 읽지 않습니다. [설정과 검증 범위](Bond-Tracking-KR.md).

### 14. 앱 화면 정리

홈에는 설치된 수정판 버전의 **Build: 1.0.0** 버튼만 표시하며 수정판 릴리스로 연결됩니다. 레포지토리·문제해결·Discord·기부 버튼을 제거했습니다. 인연 기능 아래 서버 안내·긴 설명과 어펜드 스킬 선택의 최대 레벨 제목도 제거했습니다. **더 많은 옵션 → 고급 옆의 추가기능**에서 기본 켜짐인 티포트·스톰포드 자동 설정을 켤 수 있습니다.

### 15. GitHub 업데이트 확인

**더 많은 옵션 → 추가기능 → 업데이트 확인**을 켜면 앱 실행 시 FGA-Modified의 최신 정규 릴리스를 설치 버전과 비교합니다. 새 버전의 ARM APK 업로드가 완료되어 있으면 현재·새 버전을 표시하고, **릴리스 열기**로 해당 GitHub 페이지를 엽니다. 사전 릴리스는 제외하고 네트워크 오류 시 기존 앱을 계속 사용합니다. 앱이 꺼진 상태의 검사·알림이나 자동 APK 설치는 하지 않습니다.

## 와이드 화면(21:9) 안내 — 1.6.1-beta.1

- 확인하지 못한 화면은 기존 동작을 그대로 둡니다: 스킬·어펜드 확인창과 어펜드 화면, FP 소환 화면·서번트 한계 경고, 홈의 메인 레코드·메인 인터루드 목록, 지도에서 퀘스트 판을 연 화면, KR 서버 화면. 이 화면에서 멈추면 그 화면을 캡처해 알려 주세요.
- 18:9보다 좁은 화면은 이전과 같고, 21:9보다 넓은 화면은 원본 FGA처럼 21:9로 계산합니다.

## 1.6.7-beta.2 — 전투 뒤 하단 중앙 닫기 처리

강화 퀘스트 등 전투 뒤 “개방되었습니다!” 안내가 하단 중앙 **닫기** 버튼으로 표시되면 닫고 퀘스트 목록으로 돌아가 계속 진행합니다. 모든 서버에서 동일하게 적용하며, 이 안내만으로 주회 제한 종료를 하지 않습니다. 완료한 전투는 다음 목록 방문에서 한 번만 집계합니다.

스톰포드가 소진되면 안내를 닫고 목록의 맨 위 퀘스트를 다시 선택했을 때 기존의 2.5초 대기 뒤 소모품 부족 창을 확인하고 종료합니다. 종료 횟수에는 마지막으로 완료한 전투가 한 번만 포함됩니다. 판독 영역·닫기 이미지는 변경하지 않았습니다.

두 제보는 재현하지 못했으며 소유자 결정에 따라 흐름을 단순화했습니다. 소유자가 다음 기능 수정과 함께 실제 게임에서 강화 퀘스트 안내·스톰포드 소진·새 출발 대기를 확인할 예정입니다.
