# 인연포인트 누적·MAX 정지 — 1.0.0

**정규판 1.6.0부터 실행 창에서 설정합니다.** 더 많은 옵션 → 추가기능 → **인연 추적 기능 사용**은 기본 켜짐입니다. 끄면 실행 창의 인연 블록을 숨기고 추적·MAX 정지를 생략합니다. 전투 설정별 저장 값은 유지하며, 다시 켜면 기존 선택을 사용합니다.

**재생 버튼 → 전투 실행 창 → 아이템 자동 사용 아래의 인연포인트**에서 설정합니다. 왼쪽에서 전투 설정을 고른 뒤 추적·MAX 정지·무시할 캐릭터 칸을 선택하고 **확인**을 누르면 그 전투 설정에 저장됩니다. 취소하면 인연 설정 변경은 저장하지 않습니다. 설정을 편집하는 화면의 인연 항목은 제거했습니다. 한국·일본 서버를 지원하며 기존 저장 키와 값, 복사·내보내기·가져오기는 유지됩니다. 추적과 MAX 정지의 기본값은 꺼짐입니다.

- **인연포인트 획득량 추적**: 퀘스트 종료 후 결과창의 왼쪽부터 **캐릭터 1·2·3·4·5**로 기본값과 보너스를 합산합니다. `+4,748(+2,660)`은 `7,408`입니다.
- **인연 MAX 확인 시 정지**: 체크하지 않은 캐릭터의 MAX를 확인하면 해당 퀘스트 인연 결과 화면에서 정지하고 다음 퀘스트를 시작하지 않습니다.
- **MAX 정지를 무시할 캐릭터**: 가로로 배치된 캐릭터 이름 아래 체크박스를 선택합니다. **2번을 체크하면 2번의 MAX를 무시하고 계속 진행**합니다. 새 설정의 기본값은 모두 체크 해제입니다. 이 선택은 획득량 집계를 끄지 않습니다.

0.9.0의 기존 정지 동작은 유지합니다. 이전에 정지 대상으로 선택했던 캐릭터는 새 예외 화면에서 체크 해제로 표시됩니다. 인연 기능 아래의 서버 안내·긴 설명은 UI에서 제거했습니다.

**시작 전 편성 화면을 읽거나 서포트 위치와 연결하지 않습니다.** 번호는 원래 파티의 1~6번이 아니라 결과창의 다섯 칸입니다. 퀘스트 시작 화면·전투 중·결과창에서 실행하더라도 사전 편성 확인을 요구하지 않습니다. 편성 및 결과창 순서의 일관성은 사용자가 조율합니다. 실행 중 캐릭터를 바꾸면 같은 결과 칸에 계속 합산되므로 별도로 집계하려면 실행을 종료한 뒤 다시 시작하세요.

## 일반 결과와 레벨업 창

일반 결과창을 감지하면 **1.2초 기다린 뒤 새 화면에서** MAX 이미지와 증가량을 읽습니다. 게임의 숫자 증가 애니메이션을 기다리는 시간이므로 앱 대기 배율로 줄어들지 않습니다. 증가량은 신뢰도가 높은 판독 두 개 이상과 연속 화면의 값이 일치해야 기록합니다. 같은 퀘스트의 화면을 다시 보아도 중복 합산하지 않습니다. 다른 칸의 판독 실패로 칸 번호를 당겨 바꾸지 않습니다.

레벨업 창에서는 가려진 배경의 증가량·MAX를 읽지 않습니다. 화살표 오른쪽의 **도달 레벨**이 10 이상이고 결과 카드의 LEVEL UP 표시로 결과 칸을 확정할 수 있으면 그 캐릭터의 MAX 정지 조건에 적용합니다. 9 이하는 정지 조건에 적용하지 않습니다.

위치나 도달 레벨이 미확정인 레벨업 창은 건너뛰고, 사용자 지정 정책에 따라 **다음 퀘스트의 일반 결과에서 MAX를 재확인**합니다. 이 경우 추가 퀘스트 한 회가 진행될 수 있습니다. 보석으로 현재 인연레벨을 추적하거나 NEXT 숫자를 읽지 않습니다.

## 종료 화면의 합계

이번 실행 동안 캐릭터 1~5별 포인트 합계, 집계 횟수와 누락 횟수를 표시합니다. 새로 실행하면 합계를 초기화합니다. 이미 MAX인 일반 결과는 증가량 0으로 기록하지만, 가려졌거나 읽지 못한 획득량은 누락으로 표시합니다. 누락이 있으면 표시 합계가 실제 전체 획득량보다 작을 수 있습니다.

기능을 켜면 결과 화면을 한 번씩 넘겨 판독 시간을 확보합니다. 두 기능을 끄면 기존 결과 처리로 동작합니다. MAX 정지만 켜면 증가량 OCR과 합계 표시는 생략합니다.

## 검증 범위

제공된 한국·일본 전체 화면을 720p 게임 영역 기준으로 정규화하여 출하 템플릿·좌표·OCR 설정으로 검사합니다. 일반 결과 12장(60칸: 증가량 49개, MAX 11개), 레벨업 5장(도달 7·10·11·12·16), 편성 화면 3장(인연 결과로 오인하지 않는지 확인), 빈 화면 2개를 사용합니다. 일반 결과마다 획득량을 지우고 NEXT만 남긴 대조군 12개도 검사합니다. 총 34개 케이스입니다.

### 1.0.2-beta.4 — 스크린샷 기반 1차 개선

- 획득량 OCR 영역을 720p 기준 높이 46px에서 38px로 줄여 아래 NEXT 줄의 윗부분이 섞이지 않게 했습니다. MAX 이미지 검색 영역은 유지합니다.
- 기본 판독이 미확정이면 숫자의 가로 폭을 1.4배 보정해 재시도합니다. 같은 보정을 레벨업 도달 숫자의 미확정 판독에도 사용합니다. 신뢰도 85 이상인 완전한 숫자 두 개의 일치가 필요하며, 기본 판독과 재시도의 강한 값이 충돌하면 계속 미확정으로 남깁니다.
- 2026-10-16 추가 제공 화면 7장(한국 5장·일본 2장)의 35칸에서 기존 15칸 확정 → 개선 후 35칸 확정(획득량 33개·MAX 2개)을 확인했습니다. 긴 보너스 `+3,797(+11,267)`, `+815(+590)`, PC 캡처, NEXT만 달라지는 화면을 포함합니다. 전체 화면 축소 후 게임 영역 자르기 순서에서도 같은 35칸이 일치했습니다.
- 이 결과는 OpenCV 4.11.0·Tesseract 5.5.1과 앱에 포함된 영어 OCR 데이터로 실행한 고정 화면 검증입니다. 새 버전으로 퀘스트를 돌리며 애니메이션·화면 전환·실제 누적을 확인하는 2차 검증은 별도로 진행합니다.

### 1.2.1-beta.2 — 일본판 짧은 증가량 누락 개선

- 2026-10-17 추가 제공 화면 2장(미션 배너가 있는 결과와 일반 결과)을 회귀 표본에 추가했습니다. `+365(+372)`, `+365(+374)`, `+365(+261)`을 다섯 칸에서 독립적으로 읽습니다.

- 기존 표본과 새 표본을 포함해 총 34개 화면·대조군이 통과했습니다. 새 두 화면은 기존 5/10칸 확정에서 10/10칸 확정으로 개선됐습니다. 각 화면의 1~5번 합산값은 `737 / 737 / 739 / 626 / 626`입니다.
- 신뢰도 85, 완전한 기본값·보너스 쌍의 판독 2개 이상 일치, 강한 충돌 거부와 연속 화면 확인은 유지합니다. 이 검증은 고정 스크린샷에 대한 검증이며 새 실전 퀘스트는 실행하지 않았습니다.

```bash
python tools/verify_bond_images.py --output bond-image-results.json
```

OpenCV·Pillow·tesserocr가 필요합니다. 자동 테스트는 사전 편성 확인 없는 실행, 다섯 칸 독립 누적, 중복 방지, 각 칸 MAX 정지·예외, 스크립트별 저장·복사·내보내기를 검사합니다. 데스크톱 시험은 실제 Android/FGO 터치·전환 검증을 대신하지 않습니다. 적은 인원 편성이나 여러 캐릭터의 동시 레벨업은 추가 실기 확인이 필요합니다.

티포트·스톰포드는 기존의 **화면 아이템 아이콘 기준** 동작을 유지합니다. 자동 설정 기능은 기본 켜짐이며 **더 많은 옵션 → 추가기능 → 티포트·스톰포드 자동 설정 사용**에서 켤 수 있습니다. [아이템 안내](Quest-Items-KR.md).

### 1.6.2-beta.4 진단 로그

베타에서 `adb logcat -s Bond`로 매 결과 화면의 판독 0~3회, 각 열의 OCR 후보·신뢰도와 최종 합의 값을 확인할 수 있습니다. 미확정 열은 OCR 합의 실패인지 연속 화면 불일치인지 표시합니다. 안정 버전에는 이 로그가 나오지 않습니다. 인연 판독 임계값과 대기 시간은 그대로입니다.

### 1.6.2-beta.5 인연 누락 보강

기존 신뢰도 85 이상 두 후보의 합의가 실패하면, 한 화면의 신뢰도 60 이상 완전한 숫자쌍으로 다수결을 시도합니다. 최소 3표와 신뢰도 85 이상 1표가 필요하며, 2위보다 최소 2표 많고 2배 이상이어야 합니다. 다른 두 열 이상이 같은 기본 획득량으로 확정되면 다른 기본값 후보를 제외합니다. 보너스는 각 열에서 직접 읽으며, 근거가 부족하거나 표가 비슷하면 미확정으로 남습니다.

4회 읽기와 마지막 두 번 일치 조건을 유지합니다. 베타 `Bond` 로그의 확정 규칙은 `consensus`, `majority`, `majority+base`로 표시합니다. 고정 화면 검증과 별도로 태블릿 실사용 결과는 소유자가 확인합니다.

### 1.6.2-beta.6 읽기 간 합의

획득량을 4회 읽은 뒤 각 열에서 Unknown을 제외한 마지막 두 확정값이 같으면 집계합니다. 예를 들어 같은 값이 세 번 나온 뒤 마지막 회차만 미확정이면 앞선 합의를 보존합니다. 확정값이 한 번뿐이거나 마지막 두 확정값이 다르면 누락으로 남습니다. MAX 정지와 레벨업 팝업 확인은 기존 방식입니다.

베타 `Bond` 로그는 `reason=agreed(reads=1,2)`처럼 합의한 회차를 0부터 시작하는 번호로 표시합니다. 이 예시는 두 번째·세 번째 판독이 일치했다는 뜻입니다.

### 1.6.2-beta.9 — 만장일치와 같은 기본값 보완

기존 합의·다수결이 모두 실패한 칸은 신뢰도 60 이상 후보가 같은 기본값·보너스로만 6표 이상 모이고, 같은 화면의 다른 두 칸 이상이 그 기본값을 이미 확정했을 때만 보완합니다. 이 경로에는 신뢰도 85 이상의 표가 없어도 됩니다. 다른 값이 섞이거나 다른 두 칸의 근거가 없으면 Unknown을 유지합니다. 새 보완으로 확정한 칸을 같은 화면의 다른 칸을 확정하는 근거로 재사용하지 않습니다.

로그에는 `rule=unanimous+base`를 남깁니다. 여러 판독 중 **마지막 두 non-Unknown 값이 일치해야 합산**하는 규칙과 MAX의 연속 화면 조건은 유지합니다.
