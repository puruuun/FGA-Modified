# 외부 앱 프록시 모드

Android는 한 번에 하나의 VPN만 실행할 수 있어 로컬 VPN 기반 앱(예: AdGuard 등)과 FGA의 기본 VPN 수집 모드를 동시에 켤 수 없습니다. **외부 앱 프록시** 모드를 선택하면 FGA가 VPN을 열지 않고 기기 내부 주소(`127.0.0.1`)에 상주 로컬 프록시를 열어 두고, 외부 프록시·방화벽 앱이 FGO 앱의 트래픽만 이 프록시로 보내도록 연결합니다.

연결 방식의 기본값은 **FGA VPN**이며, 다른 VPN·프록시 앱을 함께 쓰지 않으면 바꿀 필요가 없습니다.

> 모든 통신은 기기 내부에서만 처리되며 외부 서버로 전송되지 않습니다.

## 사전 준비

1. **더보기 → 로그 수집**에서 **로그 수집 사용**을 켜고 안내 동의에 동의합니다.
2. 기존 VPN 방식과 마찬가지로 FGA 인증서를 발급해 기기의 **사용자 인증서**로 설치합니다. (JP 서버 루트 자동 주입을 사용하는 경우에도 인증서·모듈 설정은 동일합니다.)
3. **연결 방식**에서 **외부 앱 프록시**를 선택합니다.
4. 카드 상단의 **호스트**(`127.0.0.1`)와 **포트**(예: `8899`)를 확인합니다. 각 항목의 **복사** 버튼으로 호스트와 포트를 따로 복사할 수 있고, `1024~65535` 범위의 다른 포트를 입력한 뒤 **적용**(또는 키보드 완료)을 눌러 포트를 바꿀 수 있습니다.
5. FGA가 백그라운드에서 종료되지 않도록 **배터리 최적화에서 FGA를 제외**합니다. 카드의 **배터리 최적화 제외** 버튼(이미 제외되어 있으면 "제외됨"으로 표시)으로 설정 창을 엽니다.
6. FGA의 접근성 서비스를 켜 두면, FGO가 화면 앞으로 올 때 프록시가 내려가 있으면 FGA가 프록시를 대기 상태로 다시 엽니다(최대 30초에 한 번 확인). 수집을 켜지는 않습니다.

## 공통 요구사항 (외부 앱 종류 무관)

어떤 외부 앱을 쓰더라도 아래 세 가지 조건을 모두 만족해야 동작합니다.

1. **FGO만 `127.0.0.1:포트`(SOCKS5 또는 HTTP, 인증 없음)로 보낼 것** (KR, JP를 함께 쓰면 JP도 포함).
2. **그 앱의 대상에서 FGA를 제외할 것**. FGA는 게임 서버에 직접 연결하므로, 외부 앱이 FGA의 HTTPS 통신까지 가로채거나 프록시로 돌리면 게임 서버에 연결할 수 없습니다.
3. **그 앱이 FGO의 HTTPS를 복호화하지 않게 둘 것**. 외부 앱이 FGO 트래픽을 먼저 복호화하면 게임에서 연결 오류가 나거나 로그가 비어 있을 수 있습니다.

> 다른 VPN·프록시 앱도 위 공통 요구사항을 만족하면 **원리상 가능**하지만, 실제 동작은 **직접 확인이 필요**합니다.

## AdGuard 사용 시 설정 방법

대표적인 사용 예시로 **AdGuard**를 사용할 때의 설정 절차는 다음과 같습니다.

1. **AdGuard → 설정 → 필터링 → 네트워크 → 프록시 → 프록시 서버**에서 서버를 추가할 때, 호스트 칸과 포트 칸을 나누어 입력합니다(`127.0.0.1:8899`처럼 호스트 칸에 포트를 함께 넣지 마세요).
   - **유형**: `SOCKS5` 또는 `HTTP`
   - **호스트**: `127.0.0.1`
   - **포트**: FGA에 표시된 포트 번호(기본 `8899`)
   - **프록시 인증**: **끈 상태**로 둡니다.
2. **"프록시를 통해 작동하는 앱"**에서 **FGO만** 선택합니다(KR, JP를 쓰면 JP도).
3. **AdGuard 앱 관리**에서 **FGA를 AdGuard 대상에서 제외**합니다.
4. **AdGuard 앱 관리**에서 **FGO의 HTTPS 필터링을 끕니다**.
5. AdGuard에서 **프록시를 켭니다**.

### AdGuard 프록시 자동 전환

기기에 AdGuard(`com.adguard.android`)가 설치되어 있으면 **AdGuard 사용 시** 영역 아래에 **AdGuard 프록시 자동 전환** 설정이 표시됩니다. 이 기능을 켜면 FGA가 드랍 수집을 켜고 끌 때 AdGuard의 아웃바운드 프록시를 자동으로 켜고 끕니다.

- **설정 방법**:
  1. **AdGuard 설정의 '자동화' 화면**에서 **자동화**를 켜고, 표시된 자동화 비밀번호를 복사하거나 확인합니다.
  2. FGA의 **AdGuard 자동화 비밀번호** 입력란에 비밀번호를 입력하고, **AdGuard 프록시 자동 전환** 스위치를 켭니다. (비밀번호가 비어 있으면 자동 전환은 동작하지 않습니다.)
- **동작 방식**:
  - **수집 켜기**: FGA 프록시가 열린 뒤, FGA가 AdGuard에 기본 프록시(`127.0.0.1:포트`, SOCKS5)를 지정하고 프록시를 켭니다.
  - **수집 끄기**: 수집을 끄기 직전에 FGA가 AdGuard 프록시를 끕니다.
  - **대기 상태로 서비스 시작**: 수집이 꺼진 상태로 FGA 프록시 서비스가 처음 시작될 때(앱 시작, 부팅, 재시작 등) 서비스 인스턴스당 한 번 AdGuard 프록시를 끕니다.
  - **모드 전환 또는 기능 끄기**: 자동 전환이 활성 상태(스위치 켜짐 + 비밀번호 비어 있지 않음)이면 "먼저 외부 프록시를 끄세요" 확인 창을 건너뛰고 AdGuard 프록시를 끈 뒤 종료합니다.
  - **자동 전환 스위치를 끌 때**: 스위치를 끄는 시점에는 AdGuard에 별도 명령을 보내지 않으며 현재 상태를 유지합니다.
- **비밀번호가 틀린 경우 확인 방법**:
  - AdGuard의 자동화 브로드캐스트는 비밀번호가 틀려도 FGA 쪽으로 오류를 돌려주지 않아 **조용히 실패**합니다.
  - 수집을 켠 뒤 카드의 **마지막 FGO 연결**이 갱신되지 않고 FGO 연결 확인이 안 된다면, AdGuard 자동화 화면의 비밀번호와 FGA에 입력한 비밀번호가 일치하는지 확인하세요.

## 프록시 대기와 수집 켜기·끄기

- **프록시 대기 중**: 외부 프록시 앱이 FGO 연결을 계속 통과시킬 수 있도록, **수집 끄기** 상태에서도 FGA의 로컬 프록시 서비스는 상주 상태로 열려 있습니다. 이 상태에서는 게임 응답을 기록·해독하지 않고 그대로 전달만 합니다. (AdGuard 자동 전환을 쓰면 수집 중일 때만 AdGuard 프록시가 켜집니다.)
- **수집 켜기 / 수집 끄기**: 상시 알림의 버튼, **더보기 → 로그 수집**, 메인 화면 버튼, 홈 화면 위젯에서 전환할 수 있습니다. FGA VPN 권한 창은 뜨지 않으며, 수집을 꺼도 프록시는 열린 채로 남아 FGO 연결이 끊기지 않습니다.
- **포트 변경**: 수집 중이었다면 먼저 수집을 끈 뒤 새 포트를 열고 기존 포트를 닫지만, 전환 순간 FGO의 기존 연결이 잠시 끊길 수 있습니다. 자동 전환을 쓰지 않는다면 외부 앱 쪽 포트 번호도 맞춰 주세요.

## 상태 확인과 문제 해결

- **마지막 FGO 연결**: FGO가 프록시를 통해 게임 서버에 연결한 마지막 시각을 분 단위로 표시합니다. 아직 기록이 없다면 외부 앱에서 프록시가 켜져 있는지, FGO가 프록시 대상 앱에 포함되어 있는지(자동 전환 사용 시 자동화 비밀번호가 맞는지) 확인하세요.
- **포트 사용 중 오류**: 선택한 포트를 다른 앱이 쓰고 있으면 해당 포트로 프록시를 열 수 없습니다. 다른 포트로 바꾸고 외부 앱에도 같은 포트를 넣은 뒤, 필요하면 사용 중인 앱을 종료하고 수집 버튼 또는 앱 재진입으로 다시 시도하세요.
- **TLS / 업스트림 실패 경고**:
  - **게임이 FGA 인증서를 거부한 경우**: **외부 앱에서 FGO의 HTTPS 복호화(HTTPS 필터링)를 끄고**, FGA 인증서가 기기의 사용자 인증서로 설치되어 있는지도 확인하세요.
  - **FGA가 게임 서버에 연결하지 못한 경우**: **외부 앱에서 FGA를 대상에서 제외**했는지와 기기 네트워크 상태를 확인하세요.
- **IPv6가 없는 네트워크(예: 일부 Wi-Fi·에뮬레이터)**: 외부 앱이 게임에 IPv6 주소를 넘겨 IPv6 연결 요청이 들어오더라도 기기 네트워크가 IPv6을 지원하지 않으면 FGA가 연결 실패 응답을 바로 돌려주어 게임이 IPv4로 다시 연결하도록 합니다(별도 설정 불필요).

## 알려진 한계

- **수집 중 FGA 강제 종료**: 수집을 켜고 AdGuard 자동 전환이 프록시를 켠 상태에서 안드로이드 설정의 **강제 종료** 등으로 FGA가 즉시 종료되면, FGA가 종료 명령을 보낼 수 없어 AdGuard 프록시가 켜진 채로 남고 FGO가 통신할 수 없습니다. 이때는 FGA를 다시 열거나 AdGuard에서 직접 프록시를 끄세요.
- **사용자의 기존 AdGuard 기본 프록시 덮어쓰기**: AdGuard 자동 전환을 켜고 수집을 시작하면 FGA가 `127.0.0.1:포트`를 AdGuard의 기본 프록시 서버로 지정하므로, 사용자가 AdGuard에 별도로 지정해 둔 기본 프록시 서버가 있었다면 수집을 켜는 시점에 덮어씌워집니다.
- **최근 앱에서 밀어 내기와 강제 종료**: 최근 앱 목록에서 FGA를 밀어 내도 프록시는 유지됩니다. 안드로이드 설정의 **강제 종료**를 누른 경우에만 프록시가 멈춥니다.
- **배터리 최적화**: FGA가 배터리 최적화 대상이면 백그라운드에서 종료되어 FGO 연결이 끊길 수 있습니다. 카드의 **배터리 최적화 제외** 버튼으로 제외하세요.
- **앱 업데이트 및 재부팅**: FGA를 업데이트하는 동안에는 FGO가 몇 초간 오프라인 상태가 됩니다. 업데이트가 끝나거나 기기를 재부팅하면 프록시는 자동으로 다시 시작됩니다.
- **네트워크 전환 중 응답 누락**: Wi-Fi와 모바일 데이터를 전환하는 동안 처리 중이던 응답은 로그에 빠질 수 있습니다.

## 모드 되돌리기 또는 기능 끄기

외부 앱이 FGO 트래픽을 FGA 프록시(`127.0.0.1`)로 보내고 있는 상태에서 FGA의 연결 방식을 **FGA VPN**으로 바꾸거나 **로그 수집 사용**을 끄면, 프록시가 종료되면서 FGO의 통신이 차단될 수 있습니다.

- **수동 설정(또는 자동 전환 미사용)**: 반드시 **AdGuard 등 프록시 앱의 프록시 설정을 먼저 끈 뒤**, FGA에서 안내 창을 확인하고 전환하거나 끄세요.
- **AdGuard 자동 전환 사용 중**: FGA가 AdGuard 프록시를 끈 뒤 전환·종료하므로 안내 창 없이 바로 전환·종료됩니다.
