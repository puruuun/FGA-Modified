# FGA 카드 개수 조건 시작 모드 수정판

## 다운로드 파일

- `FGA-3059-CardCountStart-20261012-arm.apk`: ARM 안드로이드 설치용 수정판.
- `FGA-card-count-start-source.zip`: 변경 사항이 포함된 전체 소스.
- `FGA-card-count-start.patch`: 공식 v3059 소스에 적용할 패치.
- `build-manifest.json`, `SHA256SUMS.txt`: 빌드 기준과 파일 검증 정보.

공식 FGA **v3059**, 커밋 `e138a15273dee9cac342833ee2d8aee93d8ae700`에 기능을 추가했습니다. 수정판 버전명은 `3059-CardCountStart-20261012`입니다. 공식 릴리스가 아닌 개인 테스트용 빌드입니다.

## 설치와 설정

1. APK를 안드로이드 기기로 옮겨 설치합니다. Android 7 이상, arm64-v8a / armeabi-v7a 대상입니다.
2. 앱에서 접근성 서비스와 화면 캡처 권한을 설정합니다.
3. **Battle Configs → 사용할 설정 → 커맨드 시작 조건**을 엽니다.
4. **시작 모드 → 커맨드 카드 개수 선택 모드**를 선택합니다.
5. 대상 서번트를 전투 시작 시 전열 1~3번 중 고릅니다.
6. 필요한 일반 카드 수를 설정합니다. **2는 2장 이상**을 의미합니다.
7. 최대 대기 턴은 **0 = 무제한**입니다. 양수로 설정하면 그만큼 일반 공격으로 대기한 뒤에도 조건이 부족할 때 중단합니다. 마지막 허용 대기 이후의 카드가 조건을 만족하면 시작할 수 있습니다.
8. 기존 커맨드를 그대로 작성하고 전투를 시작합니다.

이 APK의 패키지는 `io.github.fate_grand_automata.cardcount`입니다. 앱 이름은 **FGA (Card Count)**이며 초록색 **Quick** 아이콘을 사용합니다. 공식 앱·공식 CI판·앞서 제공한 CI APK와 별도 설치되며, 다른 앱의 설정이 자동 공유되지 않습니다. 필요한 Battle Config는 기존 앱에서 `.fga`로 내보낸 뒤 수정판으로 가져옵니다.

[비공개 저장소](https://github.com/puruuun/FGA-card-count)와 [APK 릴리스](https://github.com/puruuun/FGA-card-count/releases)에서 다운로드할 수 있습니다. 접근 권한이 있는 GitHub 계정으로 로그인해야 합니다.

기본 모드를 선택하면 기존 실행 방식이 유지됩니다. 이전 설정 파일에 새 항목이 없어도 기본 모드로 동작합니다.

## 동작

전투 시작부터 매 턴 카드 수를 확인합니다. 대상의 사용 가능한 일반 카드가 부족하면 **스킬과 보구를 쓰지 않고 일반 공격**으로 턴을 넘깁니다. 대기 중 Skill/NP Spam과 자동 셔플도 보류합니다.

조건이 처음 충족되면 같은 턴에 스킬 화면으로 돌아가 기존 커맨드의 첫 번째 턴을 실행합니다. 이후에는 시작 조건을 검사하지 않습니다. 공격 카드 선택을 위한 기존 인식은 계속 사용합니다. 다음 주회에서는 다시 조건을 기다립니다.

웨이브가 바뀌어도 대기를 계속합니다. 실제 **2웨이브 3턴**에 시작했다면 다음처럼 이동합니다.

| 원래 커맨드 | 실제 실행 위치 |
|---|---|
| 1웨이브 1턴 | 2웨이브 3턴 |
| 1웨이브 2턴 | 2웨이브 4턴 |
| 2웨이브 1턴 | 3웨이브 1턴 |

시작 후 카드 우선순위·브레이브 체인·Spam·자동 셔플의 웨이브 설정도 이동된 커맨드 웨이브를 기준으로 적용합니다. 실제 턴 통계에는 기다린 턴도 포함됩니다.

이 설정에서는 전역 얼굴 카드 검사 생략 옵션과 관계없이 서번트 얼굴 검사를 사용합니다. 전역 설정 자체는 변경하지 않습니다. 진행 상태는 기존 서비스 알림에 소리·진동 없이 표시합니다.

## A 보구 + A 일반 카드 2장 설정

- 필요 카드 수: 2장 이상.
- 시작 턴에는 A의 보구 하나만 지정.
- Cards before NP: 0.
- Brave Chain: With NP.
- 추가 보구가 끼어들지 않도록 NP Spam 설정 확인.

시작 조건은 보구 게이지나 보구 사용 가능 여부를 검사하지 않습니다. 시작 후 스킬이 카드 셔플·변환·서번트 교체를 일으키면 카드 상태가 달라질 수 있습니다. 최신 카드로 선택하되 이미 쓴 스킬을 되돌리거나 시작 조건을 다시 적용하지 않습니다.

## 중단 조건

- 대상 서번트가 전열에서 사라짐.
- 같은 카드 화면을 세 번 확인해도 소유 서번트나 카드 종류를 인식하지 못함.
- 지정한 최대 대기 턴 도달 후에도 조건 부족.
- 조건 충족 후 스킬 화면으로 복귀하지 못함.

인식 실패를 카드 0장으로 간주해 계속 턴을 넘기지 않습니다. 조건 전에 전투가 끝나면 커맨드 미실행을 기록하고 다음 주회에서 초기화합니다. 커맨드 위치를 밀어도 게임의 웨이브 수가 늘어나지는 않으므로 뒤쪽 커맨드가 실행되지 않을 수 있습니다.

## 개발자 재현

JDK 21과 Android SDK 37을 준비한 뒤 소스 루트에서 다음 작업을 실행합니다.

```sh
./gradlew :scripts:test :prefs:testCiUnitTest :app:compileDebugKotlin :app:assembleCi
```

개인 저장소 기본 브랜치: `main`.

저장 설정 키: `command_start_mode`, `command_start_servant`, `command_start_card_count`, `command_start_max_turns`.

핵심 구현은 `CommandStartGate`, `Battle`, `BattleState.commandPosition`에 있습니다. 실제 카운터는 그대로 유지하고 별도 커맨드 위치를 통해 시작 웨이브의 턴 오프셋과 이후 웨이브 이동을 처리합니다. 기존 인식 모듈과 좌표·이미지 템플릿은 재사용했습니다.
