# ウィークリーミッション自動周回

**今週のウィークリーミッションを最小APで満たすクエストと回数を計算し、メイン画面から章とマップを辿って全ルートを実行します。使用するバトル設定とAP回復アイテム設定を事前に確認してください。**

JP・KRサーバー向けの機能で、正式版1.6.0から対応しています。インターネット接続が必要です。実際のゲーム内のミッション進行状況は読み取りません。

## 始め方

1. ゲームの**メイン画面**を開きます。左上に `お知らせ` / `공지` がある画面です。クエストパネルや章一覧から開始しないでください。
2. FGA再生ボタン → 設定ウィンドウ左下の **ウィークリーミッションクリア** を押します。
3. 実行ウィンドウの**右側にウィークリーミッションパネル**が開きます。同じボタンをもう一度押すと折りたたまれます。左側のバトル設定・AP回復アイテム・アイテム・周回設定をそのまま使用します。
4. **ダウンロード** を押します。ミッション・章・敵構成のダウンロード段階と進行バーが表示されます。今週分のキャッシュがある場合はすぐにルートが表示されます。
5. 手動ミッションにはチェックボックスがなく、保存されていた過去の選択も無視されます。チェックを外したミッションは元の順番の位置にグレー表示で残ります。ミッション前のチェックを外すと計算から除外します。すでに達成済みのミッションもこのように除外してください。初期値はすべてオンで、サーバー・週ごとの選択はアプリ再起動後も保持され、新しい週になるとリセットされます。選択を変更するとルートが再計算され、**−/+ 回数** も新しい計算値に戻ります。
6. 合計APとクエストごとの回数を確認したあと、共通の **OK** を押します。パネルが開いていて回数が残ったルートがあればウィークリールートを実行します。ルートが空の場合はOKを押しても実行されず、**実行するクエストがありません** と表示されます。パネルを折りたたんでいる場合は通常どおりバトルを開始します。キャンセルするとゲームは操作しません。

**その他の設定 → バトル → ウィークリーミッション自動化機能を使用** は初期値オンです。オフにするとバトル起動ウィンドウのウィークリーミッションボタンが非表示になります。

章・クエスト候補は **その他の設定 → その他 → ウィークリークエスト追跡設定** でサーバー別にオン・オフできます。章名の `+` を押すとフリークエストを展開します。初期値はすべてオンで、章をオフにしても個別のクエスト選択状態は保持されます。データがない場合は、先に起動ウィンドウで該当サーバーのデータをダウンロードしてください。ミクトランと奏章（Ordeal Call Ⅰ〜Ⅳ）は非対応のため一覧に表示されません。

## 確認ウィンドウと計算

**宝物庫・初級**（10 AP）も候補に含まれます。敵構成がキャスター9体固定のため他の難易度の代わりに初級のみを使用し、ルートでは常に最後に訪れます。**ウィークリークエスト追跡設定 → 曜日クエスト** でオフにでき、探索テストにも含まれます。

他のクエストが終わると、お知らせボタンでメイン画面を確認します。移動順は **メイン → カルデアゲート → 曜日クエスト → 黄色の宝物庫・初級パネル** です。ゲートを押した後に閉じるのを待ち、一覧内の曜日バナーを探して押した後、閉じるのとデイリークエストパネルのアンカーを合わせて待ちます。右側のタイトルやイベント背景は画面判別に使用しません。一覧から**上から最初に見つかる黄色いパネル**（色相38〜52°、彩度0.80以上）を初級とみなし、名前を読み取らずにタップします。名前とAPは `map.log` 記録用としてのみ読み取ります。黄色いパネルがなければ下にスクロールし、最後まで見つからなければ中断します。赤色の種火・緑色の修練場や `CLEAR`・`NEW!`・`∞` パネルは色判定に使いません。キャンペーン中で表示APが異なっていても色で判別し、最終周回後には曜日クエスト一覧に戻ります。まずは探索テストで確認してください。

| 項目 | 説明 |
|---|---|
| 今週のミッション | チェックしたミッションだけを計算します。完了済みのミッションはチェックを外してください。一部の進行度は回数で調整します。 |
| チェックを外したミッション | 今週の一覧の元の位置にグレー表示で残り、再度オンにできます。手動ミッションにはチェックボックスがありません。 |
| ルート | 章 / スポット / クエスト名 / AP / 回数および合計APです。回数0のクエストは実行しません。 |
| 候補設定 | 別途ウィークリークエスト追跡設定でオフにした章・クエストはルート計算から除外されます。 |
| 手動 | ドロップミッションなど計算できない条件です。ご自身で達成してください。 |
| 除外対象 | **非対応の章:** ミクトラン（war 311）は階層切り替え方式が異なるため、奏章Ⅰ〜Ⅳ（war 402〜405）はオーナー判断により除外しています。ルート候補・探索テスト対象・ウィークリークエスト追跡設定・章一覧のいずれにも表示されません（JP・KR共通）。平安京（307）・トラオム（310）はメイン・インタールードの章として対応しています。 |
| バトル設定 | 左側の一覧で選んだ設定を使用します。異なる敵構成でも動作する設定を選んでください。 |

繰り返し可能なメインストーリーのフリークエストのみを計算します。`afterClear=close` である冬木の1回限定 `危険地帯` などは除外します。敵特性・クラス・サーヴァントクラス・特定の敵・クエストクリア・クエスト特性条件に対応しており、非対応や達成可能な候補がない場合は手動として表示します。合計ミッションは個別条件を達成する過程で合わせて満たされます。

KRの候補・名前・APはKRデータを使用し、**KRの敵構成はJPデータ基準**です。同じクエストIDでJPのAPとKRのAPが異なる場合は除外します。計算用データはサーバー・週ごとにアプリキャッシュへ保存されます。初回取得や形式更新時は時間がかかる場合があります。章バナーはAtlas Academyから取得してキャッシュします。beta.10からはマップ画像を取得せず、マップサイズとスポット座標のみを使用します。

## 自動移動とバトル

- JPはメイン・レコード **1 / 1.5 / 2** を辿ります。KRは **1 / 1.5** を辿り、2部の章はメイン画面の一覧から探します。平安京・トラオムはメイン・レコードではなくメイン画面最下部の **メイン・インタールード** ボタン内にあるため最後に訪れます（beta.10）。
- 章ボタンはAtlasバナーの実際のボタン内側画像で探します。下の項目を探す際は指を上にスワイプし、片方向で見つからなければ逆方向にも検索します。各方向最大14回で、見つからなければその章のクエストをスキップします。
- 章に入るとき、2本指のピンチ操作でマップを最小ズームまで縮小します。ジェスチャーが拒否された場合は進みません。
- 名札の位置を推測して押すことはしません。beta.10からはマップ画像の照合を行わず、マップを上端・下端までドラッグして位置を固定したうえでスポット座標から計算します（下記「マップ位置特定 — beta.10」参照）。
- クエストの `mapId` に合ったマップサイズを使用します。マップ位置を決められない場合、その章の残りのクエストもスキップします。複数マップ間の任意の切り替えやミクトランの階層ボタンは押しません。
- クエストパネルは **Free Quest表示＋名前** を確認します。編成制限のあるミッションクエストは押しません。上のパネルがミッションクエストの場合は下のフリークエストも検査します。
- 名前はJP・KRのOCR結果をサーバーの**全フリークエスト名辞書**と照合します。目標名だけを辞書として渡すことはしません。珍しい漢字やハングルパッチムの誤読は、最大2文字かつ全体の1/3以内・次点候補と2文字以上の差・2回の読み取り一致をすべて満たす場合のみ補正します。似た名前が重複したり読み取れない場合はスキップします。APはログ記録のため引き続き読み取りますが判定には使いません。APや文字幅だけが一致するパネルは採用しません。
- バトル・サポート選択・AP回復は既存のFGAフローを使用します。回数制限のみクエストごとに一時適用し、終了時に元の制限を復元します。果実の使用数はルート全体で使った分だけ1度差し引かれます。
- 同じ章の次のクエストはパネルを閉じてマップを再度探します。別の章は `ターミナル` / `터미널` で章一覧へ戻り、必要なら `閉じる` / `닫기` でメイン画面に戻ります。

## 終了と確認内容

クエストごとの **予定回数 / 実行回数 / 完了・見つからず・中断・未実行** と手動ミッションを表示します。バトル中にAP不足・敗北・撤退・ユーザー停止などで止まった場合、残りのルートは進めません。マップやボタンが見つからなかった場合も実行回数を確認してください。

メイン画面でない場合は何も押さず、開始画面の案内を表示します。データ読み込み失敗時はインターネットやAtlas接続状況を確認し、ルート計算失敗時は使用する章を減らして再試行してください。探索失敗の詳しい段階はログに残ります。

```text
adb -s 127.0.0.1:5555 logcat -s WeeklyRoute
```

## 確認範囲と制限

- 章バナー・ボタン・クエストパネルは保存画面を使って本番と同じコードでテストしています。マップ位置特定は8種類の画面比率と3種類の開始位置のシミュレーションで確認しており、実ゲームでの確認はオーナー側で行います。
- 実ゲームでの全移動・ピンチ・連続バトル実行は実装者側では操作していません。オーナーがまず短いルートで確認する必要があります。端末・画面比率・ゲームフォントの違いで判読根拠が不足する場合はスキップします。
- まだ解放していない章は必ずオフにしてください。Atlasと実ゲームの敵構成の違いによりミッションが足りなくなる場合があり、ゲーム内のウィークリーミッション進捗は直接確認してください。
- マップの見た目が異なっていたり目的のスポットを確定できない場合は推測でタップしません。すべての複数マップ章・ワイド画面・すべてのクエスト名を実画面で検証したわけではありません。

## パネル位置が動く場合 — beta.6

- Free Quest表示を画面の広い帯域で探し、その位置を基準にAP・名前・タップ位置をまとめて計算します。一覧が少し上にズレても固定枠座標に依存しません。
- **先に読み取ります。** 一致（Match）ならそのまま進み、一覧をドラッグしません。表示が切れていたり一致しない場合のみ、パネル内のボタンがない場所で上から下へ1回ドラッグして読み直します。
- それでも一致しない場合はパネルを閉じ、スポットが画面中央付近に来るよう慣性なしで移動してからマップを合わせ直し、もう一度だけ試みます。マップ端で中央へ動かせなくても現在スポットが安全ならその場でもう一度開きます。最終的な名前読み取りが一致しなければスキップします。**Matchでなければクエストを押しません。**
- 章バナーからマップに入った直後とターミナルへ戻った直後は従来より1秒長く待ちます（各3秒）。
- ウィークリーパネルが開いている間、左側の **周回設定** 項目は非表示になります。AP回復アイテム・アイテム・絆はそのまま表示されます。パネルを閉じると周回設定項目が戻り、保存された値は変更しません。
- ベータ版で読み取りが一致しなかった場合、**1回の実行につき最大8枚**の診断PNGをFGA保存フォルダの `diagnostics/weeklyRoute/<実行番号>/` に保存します。`WeeklyRoute` ログの `panel diagnostic path=` でファイルを探せます。正式版では保存しません。

## 探索テストモード — beta.7

APを消費せずに、すべての章のマップでクエストを見つけられるか実ゲームで点検するモードです。

- **オンにする場所:** ウィークリーミッションパネル上部の **探索テスト（AP消費なし）** チェックボックス。オンにするとルート一覧の代わりにテストオプションが表示されます。メイン画面から開始してください。
- **対象範囲:** すべてのメインストーリーフリークエスト / 選択した章 / 「ウィークリークエスト追跡設定」でオンにしたクエスト。選択されたクエスト数が即座に表示されます。ミクトランは除外されます。
- **動作:** ウィークリールートと同じ移動（メイン → メイン・レコード → 章 → 縮小・マップ合わせ → スポットタップ → パネル読み取り）を行い、**パネル判定まで**実行します。パネルがMatchでも **クエストパネルは押さず**、パネルを閉じて次のクエストへ進みます。バトルと連続出撃は開始しません。章順・マップ位置順に巡回します。
- **結果:** クエストごとに 成功 / マップ位置合わせ失敗 / スポットタップ後にパネルなし / パネル不一致 / 章が見つかりません / 未実行 と所要時間を記録します。終了するとサマリーダイアログ（状態別件数と失敗一覧）が表示され、CSVがFGA保存フォルダ `diagnostics/weeklyRoute/probe/` に保存されます。失敗した箇所の画面は診断PNGとして `diagnostics/weeklyRoute/<実行番号>/` に最大100枚保存されます。
- **途中で止めた場合:** それまでの結果をCSVとサマリーに残し、未到達のクエストは未実行として表示します。
- **すでに成功したクエストをスキップ:** このオプションをオンにすると、以前のテストで成功したクエストは再訪問しません（サーバー別に記憶）。
- ログは `WeeklyRoute` タグに `mode=probe` が付きます。JP・KRの両方で使用できます。
- ウィークリールートと同様、マップやパネルの読み取りが不確実な場合は推測せず失敗として記録します。

## クエスト終了後 — beta.7

最後のバトル後に連続出撃ダイアログを閉じたあと、マップへ戻るロードのため **さらに5秒待ってから** マップとクエストパネルを確認します。

## 名前判定とマップ端 — beta.8

- Free Quest表示があり、全クエスト名辞書で投票した名前が目標と一致すればMatchです。APを読み取れなかったりAPが異なっても名前が一致すれば進みます。名前が読めない場合は既存回数だけ再読み取りし、それでも確認できなければスキップします。
- マスター肖像画・レベル/AP・プレゼント/ミッション・MENUなど実際のUI領域を避け、スポット中心の周囲12pxが画面内にあればタップできます。画面外やUIに隠れたスポットはスクロールしてマップを合わせ直します。マップ端で原点が4pxも動かない場合は同じドラッグを繰り返しません。
- パネルを一度でも開いた後に失敗した場合、探索結果は **パネル不一致**（`panel_mismatch`）となり、最後の判定と復帰失敗理由をログ・CSVに記録します。最初からスポットを安全な位置へ動かせなかった場合のみ `spot out of reach` になります。
- 探索テストではMatchでもクエストパネルを押しません。画面比率が異なる端末ではまず探索テストで確認してください。

## スポット名確認・成功証拠・シンマップ — beta.9

beta.8 探索テスト（JP 224件中165件成功）で見つかった失敗を減らす補強です。

- **スポット名を第2の確認手段に使います。** スポットを押すとゲームがそのスポットを拡大表示し、地名ラベルを見せます。この名前を読み取り、同じ章のAtlasスポット名と比較します。
  - クエスト名が読み取れた場合は **クエスト名だけで単独判定** します（`by=quest-name`）。読み取った名前が目標と異なる場合、スポット名が合っていても採用しません。
  - クエスト名が**まったく読み取れない場合のみ**、以下を**すべて**満たせば採用します（`by=spot-name+cells`）：スポット名一致 / そのスポットのAtlasフリークエストが1つだけ / パネルにFree Quest表示 / 名前の文字幅が目標名と近い。スポットにフリークエストが2つ以上ある場合、このルールは使いません。
  - APは引き続き判定に使用しません。ログ（`WeeklyRoute`）にクエスト名・スポット名の文字認識候補と信頼度（`rawNames=`、`rawSpots=`）、判定ルール（`by=`）を記録します。
- **名前読み取りを修正しました。** 名前領域を文字のある部分だけ切り抜き、4つの方式（2・3・4倍拡大、二値化と元のグレースケール）で読み取り、最もよく読めたもの同士が一致したときのみ採用します。辞書と完全一致する読み取りは低い信頼度でも1票として数えます。
- **スポットがUIボタンに掛かった場合。** スポットがマスター情報・プレゼントボックスなどの固定ボタン領域から30px以内に掛かっておりマップがそれ以上動かない場合、アイコンの見えている部分（領域と逆方向へ最大30px）を押します。タップ点は領域から4px以上離れている必要があります。
- **スポットアイコンを押します。** タップ点はAtlasのスポット座標ではなくアイコン中心（座標よりマップ上で25px上）です。隠れていれば見えている部分、それも無理なら隠れていないスポット座標を押し、すべて隠れていれば押しません。プレゼント・ミッションの吹き出し領域も含みます。
- **スポットを押してもパネルが出ない場合**は、押した直後の画面を診断PNGとして保存し、1秒後に同じ点をもう一度押します。それでも出なければ `スポットタップ後にパネルなし` として記録します。
- **シン（Lostbelt No.3）マップ。** Atlasのシンマップ画像は8×8の空画像であり、実際のマップ（`mapGimmicks` の背景レイヤー `gimmick_030301`）はAtlasサーバーにありません。そのため画像合わせの代わりにマップサイズとスポット座標で位置を決めます。マップを上端または下端までドラッグして（マップは端で止まります）位置を固定したうえでスポットを押します。オーナー提供のキャプチャ1枚で11スポットの位置が8px以内で合うことは確認しましたが、**実ゲームでの動作はオーナー確認が必要です。** スポットに表示されるクエストパネルと名前が異なれば従来どおり失敗扱いとなり、バトルは開始しません。
- **平安京（307）が章一覧で見つからない問題。** バナー画像・サイズ・探索範囲は他の章と同じであり、コードからは原因を確定できませんでした。章一覧を最後まで探しても見つからない場合、一覧画面を診断PNG（上端・下端）として保存し、最も近いスコアをログに残します。この画面で原因を確認します。

### 探索テストの成功証拠と照合表

探索テストは**成功したクエストごと**に小さな証拠PNG（上段にパネル名領域、下段にスポット名ラベル、2倍拡大）を `diagnostics/weeklyRoute/<実行番号>/evidence/q<クエストID>.png` に保存します。枚数制限はありません。CSV（`diagnostics/weeklyRoute/probe/`）には列が4つ増えました：`evidence_file`（証拠ファイル）、`by`（判定ルール）、`read_quest`（読み取ったクエスト名）、`read_spot`（読み取ったスポット名）。

CSVと証拠フォルダをPCへ移し、1枚の照合表（HTML）を作成できます。行ごとに期待されるクエスト名・スポット名、証拠画像、判定ルールが表示されます。リスクの高い `spot-name+cells` が先頭に並びます。

```text
py -3 tools/weekly-audit/contact_sheet.py probe-JP-<日時>.csv <証拠フォルダー> -o audit.html
```

## マップ位置特定 — beta.10

マップ画像を照合する方式はオリュンポス・アトランティス・アガルタ・セイレム・アヴァロン・ル・フェ等で崩れたため廃止しました。現在すべての章が同じ方法で位置を決めます。

- **最小ズーム確認。** ピンチ後にマップ中央部分の前後画面倍率を測ります。すでに最小であればもう一度ピンチしても倍率は1.0のままです。2回連続で変化がない場合のみ確定し（最大6回）、確定できなければその章をスキップします。
- **端に合わせる。** 最小ズームのマップは画面幅と同じになるため、倍率は 画面幅 ÷ マップ幅、縦移動範囲は マップ高さ × 倍率 − 720 となります。スポットが上端・下端から押せる場合はそちらの端へ、そうでなければスポットに近い端へ長くドラッグしたあと、もう一度ドラッグして動かないことを確認します。端では位置を正確に把握できます。
- **中央付近のスポット。** 端から押せないスポットは端から出発して1回最大180pxずつドラッグし、毎回前後画面の動きを測って位置を累積します（重なり100px以上を維持）。測定に失敗した場合は端へ戻って1回やり直し、それでも失敗すると `map movement did not converge` でスキップします。
- **タップ。** 最後はこれまでと同じルール（固定ボタン領域・画面端余白・アイコン／スポット）で押し、パネル名の確認が最後の防波堤になります。
- **ログ。** `map.log` に `edge quest=… edge=Top|Bottom scale=… range=…`、`step quest=… drag=… measured=… origin=…`、`tap point …` が残ります。
- **制限。** 画面幅で制約されないマップは `map not recognized` でスキップします（現行データにはありません）。平安京のマップ4枚チェックはなくなりました。
