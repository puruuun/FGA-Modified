# スキル・アペンドスキル自動強化

**サーヴァントを選択した状態のスキル強化／アペンドスキル強化画面で、枠ごとに指定した目標レベルまで強化を繰り返します。強化はQPと素材を消費する取り消せない操作です。最初は1枠、目標＝現在レベル＋1で動作を確認してください。**

KR・JPサーバーでのみ動作します。

## 始め方

1. ゲーム内で **強化 → スキル強化**（または **アペンドスキル強化**）を開き、**先にサーヴァントを選択**します。
2. FGAの再生ボタンを押します。画面中央左・素材一覧の上にある案内文（JPは `スキル強化に必要なアイテム` / `アペンドスキルの強化/解放に必要なアイテム`、KRは `스킬 강화에 필요한 아이템` / `어펜드 스킬 강화/해방 시 필요 아이템`）を見て、スキル強化かアペンドスキル強化かを自動で判別します。右上のタイトルバナーは使用しなくなりました。
3. 設定ウィンドウで枠ごとに **目標レベル** を指定し、**OK** を押します。

サーヴァントが選択されていない画面（左上に `サーヴァント再選択` / `서번트 재선택` ボタンがない画面）では設定ウィンドウを開かず、「サーヴァントが選択されていません。先にスキル強化画面でサーヴァントを選択してください。」と表示して終了します。

## 設定

| 項目 | 初期値 | 動作 |
|---|---|---|
| スキル強化 1〜3番枠 | **オフ（0）** | 目標レベル 1〜10。現在レベルが目標以上の場合は触れません。 |
| アペンドスキル強化 1〜5番枠 | **オフ（0）** | 同上。ロックされた枠は目標を指定してもスキップします。 |

すべての枠がオフの場合、OKボタンは押せません。設定ウィンドウを開くたびに**すべての枠がオフ（0）**から始まり、指定した値は保存されません。実行するたびに目標を指定する必要があります。

## 動作と保護ルール

### ベータ専用：レベル読み取りのみ確認（1.6.8-beta.2）

強化素材を消費せずにパネルと確認ダイアログの読み取りを比較したい場合は、サーヴァントを選択したスキル／アペンド強化画面でFGA再生ボタンを押し、**レベル読み取りのみ確認（強化しない）** にチェックを入れてください。目標レベルは無視され、左からすべての枠を1回ずつ確認します。毎回デフォルトはチェック解除で、設定は保存されません。正式版にはこのオプションはありません。

ロックされた枠は解放しません。鍵アイコンが見える枠は選択せず、選択後にパネルを読み取って解放ボタンやパネル上のロック根拠が見つかった場合もそれ以上操作しません。残りの枠は強化ボタンを押して確認ダイアログを読み取った後、**必ずキャンセル**します。パネルで10を読み取った場合でも確認ダイアログとの比較を試みます。想定外のダイアログもキャンセルし、キャンセルに失敗した場合は実行全体を停止します。強化の決定操作はコード上で遮断されています。確認ダイアログが出ない場合は、最大レベルボタンの有無に応じて `max` または `no-response` を記録します。素材不足は個別には区別しません。

終了ダイアログと `SkillLevel` ログに枠ごとに次のような1行を残します。`slot` は1始まりで、アペンドの `score`/`margin` も併記されます。

```text
slot=1 panel=3 dialog=unread verdict=panel-only reason=cancelled score=0.9 margin=0.2
```

| verdict | 意味 |
|---|---|
| `match` / `mismatch` | 両方の読み取り値が一致 / 不一致 |
| `panel-only` / `dialog-only` | パネルのみ / 確認ダイアログのみ読み取り |
| `both-unread` | 両方とも読み取れず |
| `no-dialog` | 強化ボタンを押した後に確認ダイアログなし（`reason=max` または `no-response`） |
| `locked` | ロック中 |

`panel=abstain:<理由>` はパネル読み取りの棄権、`dialog=unread` は開いたダイアログから有効なレベルを読み取れなかったこと、`dialog=-` はダイアログを開けなかったか開かなかったことを表します。`reason=unexpected-dialog` は強化確認ダイアログではないためキャンセルした場合、`cancel-failed` はキャンセル失敗により停止した場合です。

**`mismatch` または `both-unread` が出た場合**は、アプリバージョン、KR/JPサーバー、スキル／アペンドの別、枠番号・実際のレベル・画面解像度、選択中の枠が写った強化画面と可能であれば確認ダイアログの元スクリーンショット、その実行の `SkillLevel` ログ全体と終了サマリーをお送りください。再現のために強化の決定を押さないでください。実機でのチェックモード動作確認は開発者側で行います。

1.6.8-beta.3からは、黄色・金色のアペンドアイコンにおけるパネル数字の読み取りを改善しました。2色の読み取りが衝突したりスコア／マージンが不足したりする場合は引き続き棄権します。

1.6.8-beta.4からは、アペンドはまず各枠自身のサンプルで読み取ります。他の枠のサンプルで得た確定値と異なる場合は棄権し、自身での読み取りもスコア0.70・マージン0.10および2色候補の一致を要求します。自身の読み取りが棄権した場合は従来のbeta.3の読み取り結果で補完します。この補完も同じく2色一致・スコア・マージン基準を満たす必要があります。KR・JPの16:9やワイド画面、特に2番・4番枠は **レベル読み取りのみ確認（強化しない）** モードでご確認ください。保存画面や未確認の画面では引き続き棄権する場合があります。

1.6.8-beta.5からは、枠の上にある案内帯の文言や色は検査しません。1番枠でも他の枠と同じ手順で確認ダイアログの比較を試みます。

1.6.8-beta.6からは、確認ダイアログの現在・次のうち片方だけが確実に読み取れた場合、**次＝現在＋1** としてもう片方を推論します。現在レベルを推論すると `dialog=9(inferred)`、次のレベルを推論すると `dialog=8(next-inferred)` として終了ダイアログとログに表示します。両方を読み取って連続していない場合は推論で上書きしません。読み取りまたは推論した現在レベル0は解放防止のためキャンセルし、通常強化のパネル不一致・レベル上昇チェックもそのまま適用されます。

### 通常強化

枠ごとに以下を繰り返します。

1. 鍵アイコンが見えたらスキップします。それ以外は枠アイコンをタップして選択し、画面が落ち着くまで待ちます。
2. 選択した枠のパネルレベルを読み取り、解放ボタンとパネル上のロック根拠を確認します。ロックされている枠ならスキップします。
3. 確実に読み取れたパネル値が10なら「最大レベル」、目標以上なら「目標達成」、直前の強化前レベルよりちょうど1大きくなければ「レベルが上がらないため停止」でその枠を終了します。このとき強化ボタンは押しません。曖昧なパネル値は使いません。
4. 解放ボタンでないことを押す直前にもう一度確認し、右下のボタン**位置**を押します。**0.4秒待った後**、最大2秒間、強化確認ダイアログが表示されるか確認します。出なければ最大レベルボタンが見えるとき「最大レベル」、それ以外は「強化不可」となります。ただし直前の決定で目標に到達していた場合は「目標達成」を維持します。素材・QP・コイン不足は個別に区別しません。強化タイトルを確認したダイアログで `Lv.<現在> › Lv.<次>` を読み取り、パネルと比較します。2つの値が異なればキャンセルします。確認ダイアログの現在1〜9と次＝現在＋1が確認できればその値を使います。片方だけ確定した場合はもう片方を±1で推論し、両方とも読み取れなくてもパネルが確実ならパネル現在値と現在＋1を使います。パネルが曖昧な場合は確認ダイアログのみで判断します。選択された値が**目標より小さく**、初回強化でなければ**直前の強化前よりちょうど1高いときのみ**決定を押します。
5. 決定後の追加待機は入れません。目標達成で**キャンセルを押した場合は0.4秒待ってから**次の枠へ進みます。決定後は右上のタイトル位置を0.5秒間隔でタップして演出と結果画面を飛ばし、スキル強化画面が再び表示されるまで最大20秒待ちます。タイムアウトすると停止します。待機中に通信エラーダイアログの「やり直す」（KR は `다시 시도`）が表示された場合は最大3回タップし、20秒を最初から数え直します。4回目が表示された場合はタップせずに停止します。スキルモードではこの待機中に案内文は見えているのに `サーヴァント再選択` / `서번트 재선택` ボタンが見えない状態が（0.5秒間隔で）2回連続で確認されると、その場で下記の理由により停止します。3つのスキルがすべて10になるとゲーム側がサーヴァント選択を解除するためです。アペンドモードは従来どおりです。

期間限定加入サーヴァントは、強化確認ダイアログの前にもう1つ案内ダイアログが表示されます。この案内ダイアログの右側のボタン（`実行する` / `실행`）が見えればそのボタンを押して通過し（ボタンが見えるたびに押す点を含め、従来FGAのサーヴァント強化と同じです）、続いて表示される強化確認ダイアログで上記と同じレベル確認を適用します。実行するボタンが見えない別のダイアログが出た場合は決定せずにキャンセルします。日本（JP）・韓国（KR）サーバーで確認済みで、認識には期間限定サーヴァント強化（サーヴァントレベルアップ）と同じ `実行する` / `실행` ボタン画像を使用します。

保護ルールは以下のとおりです。

- **解放（`解放する` / `해방`）ボタンはいかなる場合も押しません。** アペンド枠は鍵マーク、パネルのロック根拠、ボタン文字で確認します。ボタン文字は押す直前にも再確認します。確認ダイアログで0が読み取れた場合はパネル値があってもキャンセルします。
- **目標レベルを超えません。** 決定は現在レベルが目標より小さいときだけ押します。
- パネルと確認ダイアログのどちらも読み取れない、両方の確定値が一致しない、または選択した現在値が直前よりちょうど1高くない場合は決定せず、その枠を停止します。開いた確認ダイアログはキャンセルします。
- 想定外の確認ダイアログ（強化タイトル以外のダイアログ）が出たらキャンセルします。
- 聖晶石・果実・ショップは使用しません。素材やQPを自動で集める機能はありません。

## 終了メッセージ

終了時、枠ごとに `開始 Lv → 終了 Lv (目標) 理由` を表示します。

| 理由 | 意味 |
|---|---|
| 目標達成 | 目標レベルまで上げたか、すでに目標以上でした。 |
| 最大レベル | Lv.10のためこれ以上上げられません。 |
| 強化不可 | 確認ダイアログが出ませんでした。素材・QP・コイン不足などは区別しないため画面を確認してください。 |
| ロック中・スキップ | ロックされているアペンド枠です。解放していません。 |
| レベル確認失敗・強化せず | パネルと確認ダイアログから有効なレベルを取得できなかったか、確認ダイアログで0を読み取りました。 |
| パネルと確認ダイアログのレベル不一致・キャンセル | 2つの読み取り値が異なったためキャンセルしました。自動再試行はせず、実際のレベルを確認したうえで下記の診断資料をお送りください。 |
| レベルが上がらないため停止 | 決定を押したにもかかわらずレベルが上がりませんでした。ゲーム画面を確認してください。 |
| 想定外の確認ダイアログ・キャンセル | 強化確認ダイアログではないためキャンセルしました。 |
| ゲームが強化画面に戻りませんでした | 演出後20秒以内に画面が戻りませんでした。すでに強化が行われた可能性があるため確認してください。 |
| 通信エラーが続いたため停止しました | 決定後に通信エラーダイアログの「やり直す」が4回表示されたため停止しました。すでに強化が行われた可能性があるため画面を確認してください。 |
| すべてのスキルがLv.10に達したため、選択が解除されました。 | 最後の強化で3つのスキルがすべて10になり、ゲーム側でサーヴァントの選択が解除されました。強化は完了しています。 |
| オフ | 目標を0にしたままの枠です。 |

全体のメッセージは「完了しました。」「サーヴァントが選択されていません…」「スキル強化／アペンドスキル強化画面ではないため停止しました。」「すべての枠がオフのため実行することがありません。」「ユーザーにより停止されました。」のいずれかで始まります。

## 診断ログ

タグは `SkillLevel` です。ベータ版でもINFOログを記録します。枠選択、パネル読み取り、強化タップ、確認ダイアログ有無、現在・次レベル、決定・キャンセル、スキップ復帰を段階ごとに記録します。停止案内や枠ごとのサマリーにも **枠選択 / 強化ボタン / 確認ダイアログ / レベルOCR / 決定・キャンセル / スキップ・復帰** の段階を表示します。

画面判別に失敗して `WrongScreen` / `NoServantSelected` で停止した場合や、KR・JPで自動判別が実行された際は、案内文スコアを1行で出力します。報告時はこの行も添えてください（`<0.30` はスコアが0.30未満という意味です）。

```text
scores label-append=1.000 label-skill=0.680 reselect=1.000 detected=Append
```

```text
adb -s 127.0.0.1:5555 logcat -s SkillLevel
slot=1 step=ocr current=3 next=4
slot=1 step=ocr panel=3 dialog=3 source=both score=0.9 margin=0.2
slot=1 step=confirm action=confirm
slot=1 step=skip return=true
stop slot=1 step=ocr reason=Reached
summary slot=1 step=ocr target=4 start=3 end=4 reason=Reached
```

エラーや手動停止の際も進行中の枠のサマリーは保持されます。`slot` は1始まりで、開始前チェックの `slot=0` はまだどの枠も実行していないことを意味します。エラーが発生した場合は上記コマンドでログを収集し、ゲーム内で実際の強化結果を確認してください。

各回で `panel=<レベル|abstain:<理由>|locked> dialog=<レベル|unread> source=<dialog|panel|both>` を記録し、アペンドではパネルの `score` と `margin` も残します。`abstain` はパネル読み取りを使わなかったことを意味します。確認ダイアログを開く前に停止した回の `dialog=unread source=panel` は確認ダイアログを読み取っていないことを意味します。どちらも読み取れなかった回でも `source=panel` が記録されますが、強化は行いません。

**不一致が出た場合**は、アプリバージョン、KR/JPサーバー、スキル／アペンドモード、枠番号、目標・実際のレベル、画面解像度、選択中の枠が写った強化画面と可能であれば確認ダイアログの元スクリーンショット、該当実行の `SkillLevel` ログ全体と終了サマリーをお送りください。確認ダイアログを再現するために強化の決定を押す必要はありません。

## 既知の制限

- 確認ダイアログ16枚（KR・JP）の現在1–9、次2–10を実機QAで確認しました。2桁の10も含みます。数字9はOCRが読めない場合に画面形状で補助確認し、曖昧なら採用しません。1.6.8-beta.1からは確認ダイアログ読み取り失敗時に確実なパネル値（1〜9）で補完します。確認ダイアログの0および強化タイトル検査はそのまま維持されます。
- オーナーにより beta.2 JP で1枠・目標＝現在＋1での強化は確認されましたが、途中のエラーも発生しており原因はまだ確定していません。beta.3 はオーナーが JP・KR のスキル画面で実行し正常動作を確認しました。アペンド強化はまだ実機ゲームで実行していません。1.6.1-beta.2 では 2560×1080 KR アペンドのキャプチャで5枠・4つの鍵・確認ダイアログ・結果の位置を個別に確認しました。ロックされた枠はスキップし解放しません。このバージョンの実機QAおよびワイド画面での実ゲーム実行確認は待機中です。

### 1.6.2-beta.4

タブレットの日本版アペンドスキル確認ダイアログで次のレベル10の上部が切れていた数字領域を広げました。9→10を確認でき、現在レベルと次のレベルが確定しない場合は従来どおり停止します。

### 1.6.2-beta.9 — タブレット アペンド 2→3

韓国版タブレット確認ダイアログの現在数字領域を数字列に狭めました。Lv.記号と背後の枠絵柄のせいで2を4と誤読していた事例を減らします。現在・次レベルの確定読み取りと **次＝現在＋1** の条件は変わらず、曖昧な場合は確認せずキャンセルします。

### 1.6.2 — KR・JP アペンド数字読み取り

韓国版7→8などで背景が数字に混ざっていた二値化条件をアペンド専用に調整しました。現在数字領域は幅を広げずに少し左へ寄せ、輪郭の余白を確保します。KR・JPワイドの1→2から9→10までとBlueStacks 7→8の保存画面を確認しました。ワイド資料はアップロード時に縮小された画面です。通常スキルは従来の読み取り条件を維持します。相互に一致する複数読み取りと **次＝現在＋1** の条件は引き続き必須で、不確実な場合はキャンセルします。

### 1.6.8-beta.1 — パネル・確認ダイアログ交差検証

半透明なKR確認ダイアログを読み取れない場合、選択中の枠のパネルレベルで補完します。両方の値が確定した場合は必ず一致しなければならず、異なれば強化せずキャンセルします。パネルの読み取り基準は緩和していません。特に16:9のアペンド4番枠は引き続き読み取りを棄権することがあり、実機の16:10キャプチャ検証はまだありません。実ゲームでのKRスキル／アペンド補完動作およびJP回帰確認はオーナー確認が必要です。
