# 루트 수집 모드

**더 많은 옵션 → 추가기능 → 로그 수집 → 연결 방식 → 루트**는 루트 권한이 있는 기기에서 Android VPN 슬롯을 차지하지 않고 앱별 투명 리다이렉트와 루트 감시 프로그램으로 동작하며, **수집이 켜져 있는 동안에만** FGO 앱(UID)의 TCP 443 통신을 FGA 내부 투명 프록시(`127.0.0.1:<포트>` 및 `[::1]:<포트>`)로 보내 로그를 수집하는 모드입니다.

처음 설정하는 방법은 [로그 수집 시작 설정](Log-Collection-Setup-KR.md)을 참고하세요. 수집이 꺼져 있을 때는 커널 규칙(`FGA_CAP_<앱 UID>`)도 없고 FGA 프록시도 포트를 열지 않으므로, FGO는 FGA를 전혀 거치지 않고 직접 통신합니다.

---

## 1. 준비 사항 및 요구 조건

- **루트 권한 (`su`)**: Magisk, KernelSU, APatch 등에서 FGA에 루트 권한을 허용해야 합니다.
  - 연결 방식에서 **루트** 칩을 누르면 `"루트 권한 확인 중 — 허용 팝업을 눌러 주세요"` 안내가 표시되며 최대 30초 동안 루트 권한을 확인합니다.
  - 권한이 거부되거나 루트가 없으면 `"루트 권한을 확인할 수 없습니다"` 토스트가 표시되고 기존 연결 방식이 유지됩니다.
- **커널 `iptables -t nat` `REDIRECT` 지원**:
  - 수집 시작 전 `iptables -w 3 -t nat -S OUTPUT` 사전 검사를 수행합니다.
  - 기기 커널에서 `nat REDIRECT`를 사용할 수 없으면 규칙을 넣지 않고 `"이 기기에서는 루트 규칙(nat REDIRECT)을 쓸 수 없습니다"` 안내를 표시합니다.
- **커널 `iptables` `owner` 매치(`xt_owner`) 지원**:
  - 수집 시작 전 `iptables -w 3 -t nat -C OUTPUT -p tcp --dport 443 -m owner --uid-owner 0 -j RETURN` 읽기 전용 사전 검사를 수행합니다.
  - 커널이 앱별 UID 매치(`owner`)를 지원하지 않으면 규칙을 넣지 않고 `"이 기기는 앱별 통신 규칙(iptables owner)을 지원하지 않아 루트 모드를 쓸 수 없습니다. FGA VPN이나 외부 앱 프록시를 쓰세요."` 안내를 표시합니다.
- **CA 인증서 설정**:
  - **한그오(KR)**: KR 게임이 설치되어 있고 KR 인증서가 생성·설치되어 있어야 합니다.
  - **일그오(JP)**: `JP 서버 (루트)`가 켜져 있고 JP 게임이 설치되어 있으며 JP 인증서가 준비되어 있어야 합니다.
  - 준비된 대상이 있는 FGO 앱의 UID에만 규칙이 적용됩니다.

## 2. 작동 방식

### 수집 켜기 (`수집 켜기` / 메인 화면 `로그 수집 시작`)

!!! note "한 번에 하나의 FGA 앱만 실행"
    루트 수집은 한 번에 FGA 앱 하나(정식판 또는 베타판)에서만 켤 수 있습니다. 다른 FGA 앱이 이미 루트로 수집 중이면 두 번째 앱은 '다른 FGA 앱이 루트 수집 중입니다' 메시지를 보여 주고 시작하지 않으며, 다른 앱의 규칙은 건드리지 않습니다. 두 앱이 거의 동시에 시작했거나 수집 중에 다른 앱이 시작되면, 이를 알아챈 앱이 같은 메시지를 보여 주고 자기 수집을 멈춥니다.

1. **프록시 리스너 시작**: FGA가 `127.0.0.1:<포트>`와 `[::1]:<포트>`에서 투명 TLS 프록시를 먼저 엽니다.
2. **커널 규칙 적용 (`FGA_CAP_<앱 UID>` 체인)**:
   - `iptables -w 3 -t nat` 및 `ip6tables -w 3 -t nat`에 `FGA_CAP_<앱 UID>` 체인을 만들고, 인증서가 준비된 FGO 앱 UID에 대해 `-p tcp --dport 443 -m owner --uid-owner <UID> -j REDIRECT --to-ports <포트>` 규칙을 추가한 뒤 `OUTPUT` 체인 맨 위에 `-j FGA_CAP_<앱 UID>` 점프를 넣습니다.
   - `REDIRECT` 규칙 앞에 `127.0.0.0/8`, `0.0.0.0`(IPv4) 및 `::1`, `::`(IPv6) 목적지에 대한 `RETURN` 규칙을 먼저 넣어 해당 연결은 리다이렉트에서 제외합니다. 따라서 DNS 차단으로 `127.0.0.1` 응답을 받은 호스트로의 연결은 수집을 켜지 않았을 때와 마찬가지로 게임 내부에서 그대로 실패합니다.
   - FGO 앱의 UID에만 적용되므로 FGA 자신이 게임 서버로 나가는 연결은 다시 리다이렉트되지 않습니다.
3. **루트 감시 프로그램(Watchdog) 시작**:
   - 루트 권한으로 분리된 감시 스크립트가 루트 cgroup으로 이동한 뒤 백그라운드에서 동작합니다.
   - 시작 직후 첫 소켓 확인이 성공(`FGA_WATCHDOG_OK`)해야만 수집 시작이 완료되며, 실패하면 즉시 규칙을 롤백하고 수집을 끕니다.
4. **재연결 안내**:
   - 이미 열려 있던 FGO 연결은 기존 소켓을 그대로 쓰므로, 수집을 켠 뒤 FGO가 새로 연결할 때(타이틀 화면 재접속, 퀘스트 진입 등)부터 수집이 시작됩니다.

### 게임 통신과 게임 외 통신(블라인드 터널) 처리

FGO 앱의 모든 TCP 443 연결이 리다이렉트되므로, 프록시는 TLS ClientHello의 SNI(Server Name Indication, 3초 제한·최대 16 KiB)를 먼저 확인합니다.

- **게임 서버 호스트 (`yfgo-game.netmarble.com`, `game.fate-go.jp`)**:
  - 해당 서버의 인증서 컨텍스트가 있으면 복호화하여 읽기 전용으로 응답을 수집하고 원본 바이트 그대로 전달합니다.
- **게임 서버 외 호스트 (로그인, 인게임 공지 웹뷰, 리소스·데이터 다운로드 CDN 등)**:
  - SNI가 존재하지만 게임 서버가 아닌 경우, 복호화나 기록을 하지 않고 `SNI:443`으로 그대로 연결하는 **블라인드 터널**로 통과시킵니다.
  - 따라서 넷마블/애니플렉스 로그인, 공지사항 웹뷰, 데이터 다운로드가 모두 정상 작동합니다.
- **SNI가 없거나 TLS가 아닌 연결**:
  - 목적지를 알 수 없으므로 연결을 즉시 닫고 카드에 `예상 밖 연결(SNI 없음·비TLS 닫힘)` 건수로 표시합니다.

### IPv6 지원 안내

- 일그오(CloudFront)나 모바일 데이터의 IPv6(DNS64/NAT64 포함) 환경을 위해 IPv4(`iptables`)와 IPv6(`ip6tables`)에 모두 동일한 UID 기반 TCP 443 리다이렉트 규칙을 적용합니다.
- 만약 기기 커널이 `ip6tables -t nat` 규칙을 지원하지 않으면 IPv4 규칙만 적용하고, 상태 카드에 `"이 기기는 IPv6 규칙을 지원하지 않아 IPv6 연결은 수집되지 않습니다(게임은 정상)"` 안내를 표시합니다. 이 경우에도 IPv6 연결은 차단되지 않고 직접 통과하므로 게임 플레이에는 지장이 없습니다.

## 3. 수집 끄기 및 안전 장치

### 정상 수집 종료 순서

수집을 끌 때는 진행 중인 FGO 요청이 끊기지 않도록 다음 순서로 종료합니다.

1. `iptables`/`ip6tables`에서 `FGA_CAP_<앱 UID>` 점프와 체인을 먼저 제거하고 제거 완료(`FGA_CLEANUP_OK`)를 확인합니다. 이후 새 FGO 연결은 즉시 직접 연결됩니다.
2. 프록시가 새 연결 수락을 멈춥니다.
3. 이미 열려 있던 연결이 끝날 때까지 최대 30초 동안 기다린 뒤 프록시를 닫고 감시 프로그램을 종료합니다.

만약 규칙 제거가 일시적으로 실패하면 프록시 리스너를 닫지 않고 유지하여 FGO 통신이 계속 되도록 보호하면서 10초마다 규칙 제거를 다시 시도하고, 알림과 화면에 `"루트 규칙을 지우지 못했습니다. 다시 시도 중이며, 계속 실패하면 재부팅하세요."` 경고를 표시합니다.

### 자동 후퇴 (Auto-retreat)

- 게임 서버 호스트와의 연결에서 **30초 이내에 성공 없이 클라이언트 TLS 핸드셰이크 실패가 5회 발생**하거나, **게임 서버 연결 실패가 5회 연속 발생**하면 자동으로 수집을 끄고 규칙을 제거합니다.
- 이때 `"루트 모드 수집을 자동으로 껐습니다: <이유>"` 토스트와 알림이 표시되며, 이후 FGO는 프록시 없이 직접 연결됩니다.
- 게임 서버가 아닌 외부 호스트(블라인드 터널)의 연결 실패는 횟수(`게임 외 호스트 연결 실패`)만 카드에 표시하고 자동 후퇴를 일으키지 않으며, 루트 수집을 새로 시작할 때마다 0부터 다시 셉니다.

### 강제 종료·크래시·업데이트·재부팅·네트워크 전환 시 동작

- **FGA 강제 종료 / 크래시 / 앱 업데이트 / 최근 앱에서 밀어내기**:
  - 루트 cgroup에서 분리 실행 중인 **감시 프로그램**이 3초마다 `/proc/net/tcp`(및 `/proc/net/tcp6`)에서 FGA UID 소유의 리스닝 소켓을 확인합니다.
  - FGA 프로세스가 사라져 소켓이 닫히면 약 3초 안에 `iptables`와 `ip6tables`의 `FGA_CAP_<앱 UID>` 규칙을 모두 지우고 스스로 종료합니다.
  - 또한 FGA가 다시 시작되거나 업데이트될 때 이전 실행에서 규칙 플래그 파일이 남아 있으면 백그라운드에서 규칙과 감시 프로그램을 한 번 더 정리합니다(플래그가 없으면 `su`를 호출하지 않습니다).
- **Wi-Fi ↔ 모바일 데이터 전환 / 비행기 모드**:
  - 규칙이 IP 주소가 아닌 **FGO 앱 UID + TCP 443** 기준이므로 네트워크나 IP가 바뀌어도 규칙을 다시 계산할 필요가 없으며, 60초마다 체인 유지 여부를 점검하여 누락 시 자동으로 다시 적용합니다.
- **재부팅**:
  - 커널의 `iptables`/`ip6tables` 규칙과 임시 폴더의 감시 프로그램은 모두 메모리에만 존재하므로 **기기를 재부팅하면 모든 규칙이 완전히 초기화**됩니다.

## 4. AdGuard 및 개인 VPN과 함께 쓰기

- **개인 VPN (WireGuard, Surfshark 등)**:
  - 루트 모드는 Android `VpnService`를 사용하지 않으므로 WireGuard 등 개인 VPN을 켠 상태에서도 동시에 로그 수집을 사용할 수 있습니다.
- **AdGuard**:
  - **AdGuard는 '자동 프록시' 모드로 두고, AdGuard 필터링에서 FGO와 FGA를 모두 제외하세요.**
  - AdGuard가 로컬 VPN 모드로 동작하거나 FGO/FGA 트래픽을 가로채면 루트 리다이렉트 규칙과 충돌할 수 있습니다.
  - **AdGuard → 앱 관리**에서 FGO(한국판·일본판 모두)를 열고 **AdGuard를 통한 트래픽 라우팅**을 **끕니다**. FGA도 같은 방법으로 끕니다.
    - AdGuard 자동 프록시도 루트 규칙으로 통신을 돌리며, AdGuard 규칙이 FGA 규칙보다 먼저 적용됩니다. 라우팅이 켜져 있으면 FGO의 게임 통신이 FGA가 아니라 AdGuard로 들어가서, 로그가 잡히지 않고 게임 접속이 실패할 수 있습니다.
    - 이 설정은 **외부 앱 프록시 모드와 반대**입니다. 외부 앱 프록시 모드에서는 FGO의 라우팅을 켜야 하므로, 연결 방식을 바꿀 때 AdGuard 설정도 함께 바꾸세요.
  - **AdGuard → 설정 → 필터링 → 네트워크 → 프록시**에 등록한 FGA 프록시 서버(`127.0.0.1:<포트>`)는 끕니다. 이 서버는 외부 앱 프록시 모드에서만 씁니다.
  - **확인 방법**: AdGuard를 켠 상태에서 FGO가 접속되지 않고 AdGuard를 끄면 접속된다면, FGO의 AdGuard 라우팅이 아직 켜져 있는 것입니다. 라우팅을 끈 뒤 FGO를 완전히 종료했다가 다시 실행하세요.

## 5. 문제가 생겼을 때 (남은 규칙 제거 방법)

- 화면에서 **수집 끄기**를 누르거나 연결 방식을 **FGA VPN**으로 바꾸면 규칙이 즉시 제거됩니다.
- 만약 루트 매니저 오류 등으로 규칙 제거가 계속 실패하더라도 **기기를 한 번 재부팅하면 모든 `iptables`/`ip6tables` 규칙과 감시 프로그램이 남김없이 사라집니다.**
