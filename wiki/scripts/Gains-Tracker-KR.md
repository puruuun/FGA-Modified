# 로그 수집

**KR·JP 서버의 게임이 서버와 주고받는 응답을 이 기기 안에서 읽기 전용으로 모아, 계정 요약(AP, 성정석, 과일, 프리즘, QP 등)과 실행별 전투 획득량을 보여 줍니다.**

Android 10 이상에서 KR 서버(`com.netmarble.fgok`)와 루트 기기의 공식 JP 서버(`com.aniplex.fategrandorder`)를 지원합니다. Android 9 이하에서는 메뉴가 보이지 않습니다. 처음 켜는 단계별 순서는 [로그 수집 시작 설정](Log-Collection-Setup-KR.md)을 먼저 보세요. 메인 화면의 계정 카드, **저장소 → 로그 아이콘 데이터 다운로드**, **추가기능 → Chaldea 파일 내보내기**와 **프렌드 관리**는 **로그 수집 사용**을 켠 Android 10 이상에서만 나타나며, 스위치를 켜고 끄면 화면을 나가지 않아도 바로 나타나거나 사라집니다. 저장된 데이터는 삭제되지 않습니다. **로그 수집** 설정 항목(스위치를 켜는 곳)과 **메인 → 로그**는 스위치와 관계없이 그대로 보입니다. 전투 스크립트를 로그 수집 중에 시작하면 인연 숫자는 응답으로 가져오고, 재료 개수와 인연 MAX 정지는 화면 판독을 그대로 사용합니다. 자세한 적용 조건은 아래를 참고하세요.

## 연결 방식

로그 수집은 FGO 통신을 FGA 프록시로 보내는 방법을 셋 중 하나로 고릅니다. KR과 JP 모두 같은 방식으로 수집합니다.

- **FGA VPN**(기본): FGA가 기기 안에 VPN을 만듭니다. 다른 VPN 앱과 동시에 쓸 수 없습니다. 이 페이지의 설명은 이 방식을 기준으로 합니다.
- **외부 앱 프록시**: AdGuard 등 이미 쓰는 앱의 프록시 설정으로 FGO 통신을 FGA에 넘깁니다. [외부 앱 프록시 모드](Capture-AdGuard-KR.md)를 참고하세요.
- **루트**: 루트 권한으로 FGO 통신만 FGA로 돌립니다. 다른 VPN과 함께 쓸 수 있습니다. [루트 수집 모드](Capture-Root-KR.md)를 참고하세요.

## JP 서버 (루트)

Android 10 이상에서 공식 FGO JP 앱이 설치되어 있으면 **로그 수집 → JP 서버 (루트)**가 표시됩니다. 이 구역의 **루트 권한으로 JP 인증서를 자동 설치합니다** 스위치로 설정합니다. 루트 권한이 필요하며, 권한이 없거나 거부하면 켤 수 없습니다. KR과 JP는 따로 설정하며 각 서버의 인증서가 준비된 경우에만 해당 서버를 수집합니다. 두 서버가 준비되면 로그 수집 시작 한 번으로 함께 수집합니다. 루트 권한은 JP 인증서 설치에 필요하며, 연결 방식은 위의 셋 중 무엇이든 쓸 수 있습니다. JP만 사용하는 경우에도 시작할 수 있으며 KR 게임이나 KR 인증서는 필요하지 않습니다. JP 스위치가 켜져 있고 공식 JP 앱과 JP 인증서가 준비되어 있어야 합니다.

- **KR 서버** 구역의 **인증서 만들기 / 설치 방법** 버튼 아래에 별도 **JP 서버 (루트)** 구역이 표시됩니다. 스위치를 켜면 JP 전용 인증서를 만들고 시스템 CA 저장소에 자동 설치합니다. **KR 서버**의 인증서는 별도로 만들어 설치해야 합니다. **JP 인증서: 설치됨**은 JP 인증서의 현재 설치 상태입니다.
- JP 응답으로 추가된 계정은 메인 카드·대시보드·프렌드 관리 계정 선택기에 **JP**로 표시하며, KR 계정은 **KR**로 표시합니다. 계정은 `userId`별로 따로 보관합니다. JP의 Chaldea 내보내기는 기존 응답 구조를 그대로 사용하며, Chaldea의 기본 서버 판별은 JP입니다.
- 처음 설치했을 때 게임이 켜져 있었다면 JP 게임을 종료한 뒤 다시 실행하세요. FGA는 게임을 종료하지 않습니다.
- 재부팅하면 설치가 해제되며 다음 로그 수집 시작 시 자동으로 다시 설치합니다. 설치에 실패해도 KR 수집은 계속됩니다.
- 로그 수집을 중지해도 CA는 남습니다. **JP 서버 (루트)** 구역의 스위치를 끄면 가능한 마운트를 해제하고, **완전히 지우려면 기기를 재부팅하세요**를 표시합니다.
- 이름·얼굴·아이콘·분류는 Atlas KR 공개 데이터를 먼저 사용합니다. 표시 중인 계정이나 기록의 계정이 **JP**이거나 KR 목록에 없는 ID가 있으면 JP의 서번트·개념예장·아이템·마술예장 공개 목록도 내려받고, KR에 없는 항목을 보충합니다. JP에서 가져온 이름은 **일본어 원문**으로 표시합니다. 대시보드·프렌드·로그와 **로그 아이콘 데이터 다운로드**에 함께 적용됩니다.
- JP 목록은 앱 내부 `capture/names/jp_*_details.json`에 별도로 보관합니다. 화면이 목록을 필요로 할 때만 Atlas의 공개 데이터 버전을 최대 한 시간에 한 번 확인하고, Atlas 데이터가 바뀐 서버의 목록만 다시 내려받습니다(목록별 재시도도 한 시간에 최대 한 번). 따라서 새 서번트·개념예장·아이템이 게임에 추가되면 Atlas에 반영되는 즉시 이름이 표시되며, 이름은 화면을 열 때 ID로 다시 찾으므로 예전 로그도 새 이름으로 바뀝니다. 버전을 읽지 못할 때는 기존 규칙(7일마다, 목록별 하루 최대 한 번)을 따릅니다. 아이템이 두 서버의 목록에 모두 없으면 기존처럼 공개 ID로 JP 아이템을 개별 조회하며, 이 보충 조회는 KR 계정에도 적용됩니다. 공개 목록과 이미지만 요청하며 계정 데이터는 전송하지 않습니다.

## 안전과 개인정보

- FGA VPN과 루트 방식은 **게임 앱의 통신만** 이 기기 안의 FGA 프록시로 보냅니다. 외부 앱 프록시 방식은 프록시 앱(AdGuard 등)에서 고른 앱의 통신이 들어옵니다.
- 프록시는 요청과 응답을 **고치지 않고** 그대로 전달하며, 게임 서버(`yfgo-game.netmarble.com`, JP 설정을 켠 경우 `game.fate-go.jp`)의 응답만 읽습니다. 다른 주소는 그대로 통과시킵니다.
- 계정·로그인 토큰 경로는 읽지도 저장하지도 않습니다. 요청 본문, 토큰, 헤더는 기록하지 않습니다.
- 모은 계정 요약은 기기 안(앱 전용 저장소)에만 저장하고 **어디로도 전송하지 않습니다**.
- 인증서 개인 키는 저장하지 않습니다. 인증서를 만들 때 서명용 키로 한 번만 서명하고 버립니다. 자세한 내용은 아래를 참고하세요.

### 설치하는 인증서는 안전한가요?

보통 CA 인증서를 설치하면, 그 CA의 개인 키를 가진 사람이 은행이나 검색 사이트 같은 **아무 사이트의 가짜 인증서**를 만들어 이 기기의 통신을 엿볼 수 있습니다. 그래서 CA 인증서 설치는 원래 조심해야 합니다. FGA의 인증서는 이 위험이 생기지 않도록 만들어집니다.

- **CA 개인 키를 바로 버립니다.** 인증서를 만들 때 FGA는 이 기기에서 새 CA를 만들고, 그 CA로 **게임 서버 주소 하나의 인증서에만** 서명한 뒤 CA 개인 키를 저장하지 않고 버립니다. 그래서 FGA를 포함해 누구도 이 CA로 다른 사이트의 인증서를 만들 수 없습니다. 인증서 이름에 "single-use(일회용)"가 붙은 이유입니다.
- **기기에 설치되는 것은 CA 인증서의 공개 부분뿐입니다.** 공개 부분으로는 새 인증서를 만들 수 없고, 서명을 확인하는 데만 쓰입니다.
- **서명된 인증서는 게임 서버 주소에만 쓸 수 있습니다.** KR은 `yfgo-game.netmarble.com`, JP는 `game.fate-go.jp`입니다.
- **기기마다 따로 만듭니다.** 모든 사용자가 같은 인증서를 쓰지 않으므로, 다른 사람의 인증서로 이 기기를 노릴 수 없습니다.
- **게임 서버용 키는 FGA 앱 전용 저장소에만 있습니다.** 클라우드 백업과 기기 이전에서도 빠집니다.
- 인증서를 설치하면 Android가 "네트워크가 모니터링될 수 있음" 같은 알림을 표시할 수 있습니다. 사용자가 설치한 모든 CA 인증서에 똑같이 나오는 일반 알림입니다.
- **새 인증서 만들기**를 누르면 새 CA가 만들어집니다. 예전 CA 인증서는 설정 앱의 **신뢰할 수 있는 자격증명 → 사용자**에서 지워도 됩니다. 로그 수집을 더 쓰지 않을 때도 같은 곳에서 지우면 됩니다.

## KR 서버 설정 및 인증서 파일

전체 설정 순서는 [로그 수집 시작 설정](Log-Collection-Setup-KR.md)을 참고하세요. **KR 서버** 구역은 루트 권한이 필요하지 않으며, KR 게임 설치 여부와 관계없이 표시됩니다.

1. **더 많은 옵션 → 추가기능 → 로그 수집**을 열고 **로그 수집 사용**을 켠 뒤 **동의하고 사용**을 누릅니다.
2. **KR 서버 → 인증서 만들기**를 누르면 **FGA 폴더 → `capture` → `fga-capture-ca.crt`**로 저장되고 경로가 화면에 표시됩니다. 같은 이름의 파일이 있으면 덮어쓰고, 그 이름으로 쓸 수 없으면 `fga-capture-ca-<날짜>-<시각>.crt`로 한 번 더 저장합니다. FGA 폴더를 쓸 수 없으면 시스템 저장 창이 열립니다. 예전 버전이 `Download`에 만든 파일은 그대로 남으며 지우지 않습니다.
3. **설치 방법 → 보안 설정 열기**에서 **CA 인증서**로 설치하면 상태가 **KR 인증서: CA 인증서로 설치됨**으로 바뀝니다.
4. **수집 연결**에서 선택한 연결 방식([FGA VPN / 외부 앱 프록시 / 루트](Log-Collection-Setup-KR.md))에 맞게 시작하고, 게임을 새로 실행하면 계정 요약 카드가 채워집니다. 스냅샷이 없는 동안에는 **로그 수집을 켠 상태에서 게임을 시작해 주세요**가 표시됩니다.

게임이 인증서를 거부하면 **수집 연결** 구역에 거부 횟수와 안내가 표시됩니다. CA 인증서로 설치했는지 확인하세요.

응답 본문이 너무 크거나 메모리가 부족하여 복사하지 못한 경우, 또는 응답 처리 중 오류가 발생하면 수집 중 화면에 기록하지 못한 응답 개수와 마지막 경로가 표시됩니다. 게임 통신은 그대로 전달되므로 게임 플레이나 자동 주회에는 전혀 영향을 주지 않으며, 해당 응답만 로그 기록에서 빠집니다.

## 처음 사용할 때 안내

**로그 수집 사용 전 안내**는 작동 방식(연결 방식 셋: FGA VPN, 외부 앱 프록시, 루트)과, KR·JP와 각 방식에 필요한 것을 설명합니다. 작은 화면에서는 안내 내용을 위아래로 스크롤할 수 있습니다.

- 게임 업데이트로 기능이 동작하지 않을 수 있습니다. 로그인이 안 되면 로그 수집을 끄면 됩니다.
- 로그 수집이 꺼져 있던 동안의 변화는, 켠 상태로 다시 로그인하기 전까지 반영되지 않습니다.
- 외부 앱 프록시: FGA가 종료되어 있으면 FGO가 접속하지 못합니다. FGA를 다시 켜거나, 프록시 앱의 프록시 설정을 끄세요. (AdGuard 프록시 자동 전환을 쓰면 수집 중일 때만 해당됩니다.)
- 루트: 수집을 켠 뒤 FGO가 새로 연결할 때(타이틀 화면 등)부터 기록됩니다.
- JP: 기기를 켠 뒤 처음 수집을 시작할 때 JP 게임을 한 번 다시 실행해야 합니다.
- **이 기능의 사용과 그 결과에 대한 책임은 사용자 본인에게 있습니다.**

동의는 저장됩니다. 이미 동의한 사용자에게는 안내를 다시 묻지 않습니다. 이후 안내 문구의 동의 버전이 바뀌면 다시 동의를 요청할 수 있습니다. 설정의 **안내 다시 보기**로 언제든 다시 읽을 수 있습니다. 다시 보는 것만으로 사용 설정이 켜지지는 않습니다.

## 메인 화면에서 쓰기

로그 수집 사용 설정이 켜져 있고, Android 10 이상이며 KR 게임 또는 JP 설정을 켠 공식 JP 게임이 설치되어 있으면 서비스 버튼 왼쪽에 **로그 수집 시작** 버튼이 나타납니다. 두 버튼이 한 줄에 들어가지 않으면 서비스 버튼 위로 올라갑니다.

- **파란색 · 로그 수집 시작**: 수집이 꺼져 있습니다. 동의가 없다면 안내부터 표시합니다. 인증서가 없으면 짧은 안내와 함께 로그 수집 설정을 엽니다. FGA VPN 방식에서 Android VPN 허용이 필요하면 연결 요청을 표시하고, 허용한 뒤 시작합니다.
- **빨간색 · 로그 수집 중지**: 수집이 실행 중입니다. 누르면 로그 수집만 멈추고 FGA 서비스는 계속 실행됩니다. 외부 앱 프록시에서는 프록시가 열린 채로 남아 FGO 연결이 끊기지 않습니다.
- 알림에서 중지하거나, 시스템이 수집을 종료하거나, FGA VPN 방식에서 다른 VPN이 대신하면 버튼은 바로 파란색으로 돌아옵니다.

로그 수집 사용 설정이 켜져 있고(Android 10 이상) 로그인 스냅샷이 있으면 메인 화면 위쪽에 **프로필 카드**가 나타납니다. 계정마다 마스터 이름과 작은 **KR / JP** 서버 표시, AP 현재/최대와 AP가 가득 차는 시각을 표시하며, 이미 가득 차면 **가득 참**으로 표시합니다. 카드는 빌드·접근성 상태 줄 아래에 일정한 폭으로 가로 나열되며, 여러 계정이면 현재(최근 플레이) 계정이 맨 앞에 옵니다. 화면에 다 들어가지 않으면 좌우로 스크롤합니다. 화면을 보는 동안 AP는 1분마다 갱신됩니다. 카드를 누르면 해당 계정의 대시보드가 열립니다.

전투 실행 창을 열 때 로그 수집이 실행 중이면 **인연포인트 획득량 추적** 옵션은 숨기고, **인연 MAX 확인 시 정지**와 정지가 켜져 있을 때의 무시할 칸 설정은 유지합니다. 숨겨진 추적 설정의 저장값은 바뀌지 않습니다.

## 여러 계정 쓰기

계정을 직접 선택할 필요가 없습니다. 로그인 응답의 `userId`로 계정을 자동으로 추가하고, 이후 응답도 그 안의 계정 ID에 맞춰 저장합니다. 다른 계정으로 로그인하면 메인의 가로 카드 목록에서 **마지막으로 플레이한 계정**이 맨 앞으로 옵니다. 서로 다른 계정 ID가 섞인 응답은 반영하지 않습니다.

**더 많은 옵션 → 추가기능 → 로그 수집**에는 계정별 카드가 최근 플레이 순으로 표시됩니다. 각 카드에는 계정 이름, 마스터 레벨, 서버(KR/JP), 현재 계정의 **최근 플레이** 표시, 스냅샷 시각과 마지막 갱신 시각이 표시됩니다. 보유 재화와 AP 현황은 계정 대시보드에서 확인할 수 있습니다.

- **이름 변경**: 처음에는 게임의 마스터 이름을 사용합니다. 원하는 이름을 입력할 수 있으며, 비워 두고 확인하면 마스터 이름으로 돌아갑니다. 메인 카드에도 이 이름이 표시됩니다.
- **삭제**: 확인 창에 표시된 계정의 수집 데이터와 해당 Chaldea 파일만 지웁니다. 최근 플레이 계정을 지우면 남은 계정 중 가장 최근 계정이 표시됩니다. 이후 그 계정으로 다시 로그인하면 새로 추가됩니다.
- 계정 상태와 이름은 앱 내부 `capture/accounts/<userId>/`에 각각 보관됩니다. 이전 단일 계정 데이터는 처음 실행할 때 자동으로 이전됩니다. 로그인 스냅샷이 없는 새 계정은 다음 로그인 후 요약이 채워집니다.

전투 로그에는 실행 계정의 이름이 표시됩니다. 실행은 시작할 때의 계정에 속하며, 아직 계정이 없으면 처음 확인된 응답의 계정에 속합니다. 도중에 다른 계정의 응답이 들어와도 그 실행의 획득량에는 섞이지 않습니다. 기록에 저장된 이름은 나중에 이름을 바꾸거나 계정을 지워도 유지됩니다.

**듀얼 앱·복제 앱 등 여러 게임 인스턴스의 동시 실행은 지원하지 않습니다.** 공식 KR 게임(`com.netmarble.fgok`)과 JP 설정을 켠 공식 JP 게임(`com.aniplex.fategrandorder`)의 응답을 수집합니다. BetterFGO는 지원 대상에서 제외됩니다.

## FGA 서비스와 함께 쓰기

로그 수집을 켜고 KR 또는 JP 경로가 준비된 상태에서 메인의 **서비스 시작**을 누르면, FGA 서비스가 시작된 뒤 로그 수집도 시작합니다. FGA VPN 방식에서 VPN 권한이 없으면 그 자리에서 Android 연결 요청을 표시하며, 허용하면 시작합니다. 인증서가 없으면 짧은 안내를 표시하고 FGA 서비스는 그대로 실행합니다.

**서비스가 멈추면 로그 수집 중지**(기본 꺼짐, 기존에 저장한 설정은 유지)를 켜 두면 메인의 서비스 중지, FGA 서비스 알림의 중지, 시스템에 의한 서비스 종료 시 로그 수집도 멈춥니다. 직접 시작한 수집도 포함합니다. 설정을 끄면 서비스가 멈춰도 로그 수집은 유지됩니다.

스크립트를 시작할 때 로그 수집이 꺼져 있다면, KR 서버 또는 JP 경로가 준비된 공식 JP 서버이고 로그 수집 사용 설정·인증서(FGA VPN 방식은 VPN 권한도)가 준비된 경우 다시 시작합니다. 권한이나 인증서가 없으면 안내만 표시하고 스크립트는 그대로 실행합니다. **스크립트가 끝나도 로그 수집은 멈추지 않습니다.** 실행별 획득량 수집은 기존처럼 스크립트 시작부터 끝까지입니다.

## 전투의 재료 집계와 인연 정지

전투 스크립트 시작 시 **KR 서버이고 로그 수집이 실행 중이면**, 해당 실행은 인연 숫자에 로그 수집 응답을 사용합니다. 스크립트 시작 때 로그 수집을 자동으로 시작하는 중이면 최대 3초 기다린 뒤 결정합니다. 결정은 실행 중 바뀌지 않으므로, 중간에 수집을 켜도 기존 화면 판독 실행은 그대로이고 중간에 꺼도 응답 방식은 유지됩니다. JP와 수집 없이 시작한 실행은 기존 동작을 유지합니다.

- **재료**: 로그 수집 여부와 관계없이 드롭 화면의 템플릿 매칭으로 선택한 재료를 집계합니다. 재료 개수 제한과 자동 차감도 화면 인식 결과를 그대로 사용합니다. 전투 로그에는 화면 판독으로 집계된 재료와 로그 수집의 획득량이 함께 표시될 수 있습니다.
- **인연**: 인연 획득량의 숫자는 로그 수집 응답에서 가져옵니다. 종료 화면의 캐릭터별 인연 합계 대신 로그의 **획득량 (로그 수집)**에서 서번트별 포인트를 확인합니다. 인연포인트 획득량 추적만 켜 두었다면 OCR과 그 판독 대기를 생략하고, 결과 화면을 인연 추적을 끈 때와 같은 횟수로 넘깁니다.
- **인연 MAX 정지**: 인연 기능과 MAX 정지가 켜져 있으면 로그 수집 중에도 로그 수집을 끈 때와 똑같이 **결과 화면을 읽어서(OCR)** 판단합니다. 캐릭터별 MAX 표시(연속 두 프레임 확인)나 레벨 10 이상 도달 레벨업 창이 보이면, 무시하지 않은 칸에 한해 기존 MAX 메시지로 정지합니다. 결과 화면을 넘기는 속도와 대기도 로그 수집 전과 같습니다. 로그 수집 응답은 정지 판단에 쓰지 않으며, 인연 숫자 집계에만 사용합니다. 완료한 퀘스트는 주회 횟수에 포함합니다.
- **응답 누락**: 첫 결과 화면에서 해당 전투 응답을 최대 3초 기다립니다. 응답이 오지 않거나 필요한 데이터가 빠져 있으면 그 전투의 인연 숫자는 더하지 않고 **정지하지 않고 계속 진행**합니다. 재료 개수와 인연 MAX 정지는 화면 판독이라 응답과 관계없이 동작합니다.

CE 드롭 확인, 스크린샷, 나머지 화면 감지와 터치·대기는 기존 설정을 따릅니다. 인연 설정과 기존 화면 판독 방식은 [인연포인트 누적·MAX 정지](Bond-Tracking-KR.md)를 참고하세요.

## 추가기능과 Chaldea 파일 내보내기

**더 많은 옵션 → 추가기능**에는 **서포트 이미지 검색·저장**, **원본 FGA 데이터 가져오기**, **Chaldea 파일 내보내기**, **로그 수집**, **프렌드 관리**, **게임 영역 (시험기능)**이 있습니다.

**Chaldea 파일 내보내기**는 로그 수집 사용이 켜진 Android 10 이상이고 수집된 계정 데이터가 있을 때만 나타납니다. 계정이 하나면 바로 내보내고, 여러 개면 계정을 골라 해당 계정만 내보냅니다. 로그 수집 설정의 계정 카드에서도 해당 계정을 내보낼 수 있습니다. 내보내기 전에 계정 카드의 마지막 갱신 시각을 확인하세요. 내보낸 파일에는 Chaldea가 읽는 계정 테이블만 담기며, 결제 내역이나 소환 시각 기록처럼 Chaldea가 사용하지 않는 기록은 제외됩니다.

1. 로그인 스냅샷이 없으면 **로그 수집을 켠 상태에서 게임을 시작해 주세요**가 표시됩니다. 게임을 다시 시작해 계정 카드가 채워진 뒤 재시도합니다.
2. 해당 계정 상태를 `FGA 폴더/capture/chaldea-account-<userId>-<yyyyMMdd-HHmm>.json`으로 저장합니다. 같은 이름이 이미 있으면 덮어쓰고, 쓸 수 없으면 초 단위를 붙인 이름으로 한 번 더 저장하며, 그것도 안 되거나 FGA 폴더를 쓸 수 없으면 시스템 저장 창이 열립니다. 안내 창에는 실제로 저장된 폴더와 파일 이름이 표시됩니다. 계정 정보가 담긴 파일이므로 **계정별로 최신 한 개만 남깁니다**. 다른 계정의 최신 파일은 유지하며, 기존 `chaldea-kr-<userId>-<yyyyMMdd-HHmm>.json`도 계정별로 함께 정리하며, FGA가 예전에 만든 계정 ID 없는 `chaldea-kr-<yyyyMMdd-HHmm>.json` 파일은 내보낼 때 정리합니다.
3. 저장이 끝나면 **저장했습니다. Chaldea에서 이 파일을 선택하세요** 안내 창에 파일 이름과 가져오는 순서를 표시합니다. **확인**은 창을 닫고, **Chaldea로 이동**은 Chaldea를 연 뒤 창을 닫습니다. 자동으로 앱을 열지는 않습니다. Play/GitHub판과 F-Droid판을 지원합니다.
4. Chaldea가 설치되지 않았으면 **Chaldea로 이동** 버튼 대신 설치 안내가 표시됩니다. 파일은 저장되어 있으므로 Chaldea를 설치한 뒤 **가져오기 → HTTPS 스니핑 → 파일에서**에서 안내된 파일을 고르세요. 저장이나 이전 파일 정리에 실패하면 기존 오류 안내를 확인하고 다시 시도합니다.

**파일에는 로그 수집이 실행 중일 때 받은 내용만 반영됩니다.** 로그 수집 없이 플레이했다면 로그 수집을 켜고 게임을 다시 시작해 스냅샷을 갱신한 뒤 파일을 만드세요. FGA는 계정 데이터를 외부로 전송하지 않으며, Chaldea에서 파일을 직접 선택해 가져옵니다.

친구들의 서포트 서번트를 모아 보는 화면은 [프렌드 관리](Friend-Manager-KR.md)를 참고하세요.

## 전투 로그에서 획득량 보기

로그 수집이 실행 중인 동안 스크립트의 전투 결과를 모읍니다. 직접 켠 수집과 스크립트가 자동으로 켠 수집 모두 지원합니다. 스크립트가 끝나면 **메인 → 로그**의 해당 기록에 **추적됨** 표시가 붙고, 상세 요약 아래에 **획득량 (로그 수집)**가 추가됩니다.

- **아이템**: 서버가 알려 준 드롭을 합산해 획득량이 큰 순서로 표시합니다. 개념예장 등도 포함합니다. 계정 스냅샷이 있으면 아이템의 종료 시 보유량도 표시합니다.
- **QP**: 퀘스트 클리어 QP, QP 드롭, 첫 클리어 QP를 합칩니다.
- **마스터 EXP·인연**: 전투 전후 차이를 표시합니다. 인연은 내가 편성한 서번트만 서번트별로 합산하며(서포트와 NPC는 제외), 0인 줄은 표시하지 않습니다. 그 전투에서 인연 등급이 한도(10 + 초과 횟수)에 새로 도달한 서번트는 포인트 옆에 **MAX**를 붙입니다. 전투별 내역과 전체 합계, 로그 목록 모두 같고, 이전에 저장된 로그는 MAX 표시 없이 그대로 보입니다.

  KR·공식 JP에서 편성 응답의 서번트 종류 ID가 0 이하이거나 빠져 있어도, 계정의 보유 서번트·두 번째 보관소 또는 결과 응답의 전투 전 서번트 정보로 확인해 인연을 기록합니다. 편성한 서번트를 한 기도 확인할 수 없으면 응답에 포함된 인연 변화를 모두 집계합니다.

- **사용한 과일**: 황금색·백은색·청동색·적동색 과일별로 `시작 보유량 − 종료 보유량 + 획득량`을 계산합니다. 시작 또는 종료 스냅샷이 없으면 **알 수 없음**입니다.
- **전투별 내역 펼치기**: 기본은 접혀 있습니다. 펼치면 각 전투의 시각, 퀘스트 ID, 드롭, QP, EXP와 인연을 확인합니다.

스크립트 도중 로그 수집을 켜거나, 수집이 중지되면(FGA VPN 방식에서 다른 VPN으로 바꾸거나 권한을 철회한 경우 등) 이미 모은 내역은 남습니다. 완료한 주회보다 기록한 전투가 적으면 **전투를 기록하지 못했습니다**라는 누락 안내가 표시됩니다. 이 경우 획득량은 일부일 수 있으며, 중지 후 변화는 반영하지 못합니다. 보유량과 과일 사용량도 마지막으로 추적한 시점을 기준으로 합니다. 계정 스냅샷이 없어도 드롭과 응답에서 확인되는 QP·EXP·인연은 기록합니다. 응답에 없는 값은 **알 수 없음**으로 표시하거나 생략합니다.

로그 수집을 한 번도 실행하지 않은 기록과 예전 기록은 기존 요약만 보여 줍니다. 일시정지 상태 확인 화면과 0회 주회는 전투 로그를 저장하지 않습니다. 스크립트 밖에서 직접 플레이한 전투는 아래의 **스크립트 밖 변화**에 포함됩니다. 전투 로그와 스크립트 밖 기록의 보관 한도는 **로그 → 필터 아이콘 → 로그 보관 개수 (종류별)**에서 **50 / 100 / 200**건 중 고르며 기본·최대는 각각 200건입니다.

아이템·서번트·개념예장 이름은 **Atlas Academy의 공개 KR 목록**에서 먼저 가져옵니다. 기록의 계정이 JP이거나 KR에 없는 ID가 있으면 이름과 아이콘을 JP 공개 목록에서 보충하며, 이름은 일본어 원문으로 표시합니다. 처음 필요할 때 내려받아 앱 내부 `capture/names/`에 ID와 이름, 아이템 아이콘 주소를 보관합니다. 화면이 목록을 필요로 할 때 Atlas 데이터 버전을 최대 한 시간에 한 번 확인해 바뀐 서버의 목록만 다시 내려받으므로, 새 서번트·개념예장·아이템은 Atlas에 반영되는 대로 예전 로그에서도 새 이름으로 표시됩니다. 버전을 읽지 못할 때는 KR 목록에 모르는 ID가 나타나면 목록별 하루 최대 한 번, JP 목록은 받은 지 7일이 지나면 파일별 하루 최대 한 번 갱신을 시도합니다. 다운로드가 실패하면 `Item #6510`, `Servant #100100`, `CE #9400010` 같은 ID 표시를 쓰며 기록은 정상적으로 저장합니다.

획득량과 사용량은 **획득 (+)**·**사용 (−)** 두 묶음의 작은 타일로 표시합니다. 아이템은 아이콘·짧은 이름·개수를, QP·마나프리즘·레어프리즘·성정석·과일·성정편은 아이콘과 개수만 표시합니다. 성정석에는 작은 무료·유료 구분도 붙습니다. 모든 타일은 같은 높이이며, 아이콘 왼쪽·텍스트 오른쪽 구조입니다. 종료 시 보유량이나 무료·유료 구분은 아이콘 아래가 아닌 텍스트의 둘째 줄에 표시합니다. 타일을 누르거나 길게 눌러도 팝업은 열리지 않으며, 화면 읽기 도구에는 이름과 개수를 제공합니다. 아이콘 주소 목록은 이름 목록과 별도로 최초 다운로드와 실패 재시도 제한을 관리합니다. 화면에 표시할 아이콘 중 파일이 없는 것만 공개 `static.atlasacademy.io` HTTPS 서버에서 내려받아 앱 내부 `capture/icons/<아이템 ID>.png`에 영구 보관합니다. 이후에는 이 파일을 사용하며 Coil의 디스크 캐시에 의존하지 않습니다. APK에는 포함하지 않습니다. 오프라인이거나 다운로드가 실패하면 이름으로 표시하고, 최소 한 시간 뒤 다시 시도합니다. 공개 목록과 이미지만 내려받고 계정·게임 데이터는 업로드하지 않습니다.

## 계정 대시보드

메인 화면의 계정 카드를 누르면 **그 카드의 계정** 대시보드가 열립니다. 오른쪽 위 **설정 아이콘**은 로그 수집 설정을 엽니다. 설정 왼쪽의 **내보내기 아이콘**은 지금 보고 있는 계정의 Chaldea 파일을 만들고 위의 저장 안내 창을 보여 줍니다(Android 10 이상). 친구 목록을 받은 계정이면 설정 왼쪽(내보내기 아이콘 오른쪽)에 **프렌드 아이콘**이 나타나며, 누르면 그 계정이 선택된 프렌드 관리가 열립니다. **더 많은 옵션 → 추가기능 → 로그 수집**에서도 설정에 들어갈 수 있습니다.

대시보드는 기기에 저장된 수집 상태를 읽기만 하며 새 응답을 받으면 갱신합니다. 없는 항목은 숨기고, 아이템 표를 받은 계정의 재화 행만 없을 때 0으로 표시합니다. 내용은 **섹션**으로 나뉘며 한 번에 한 섹션만 보입니다. 섹션 목록은 **개요 → 서번트 → 아이템 → 편성 → 도감·소환 → 선물함** 순서이고, 데이터가 없는 섹션은 목록에서 빠집니다(편성은 서포트 편성 카드가 항상 있었으므로 항상 표시합니다). 섹션 이름 옆에는 개수를 붙이지 않습니다.

- **폭 840dp 이상**: 왼쪽에 약 240dp 너비의 창이 있고 위에 계정 헤더(AP 포함), 아래에 섹션 목록이 있습니다. 항목은 네모난 모양이며 선택한 항목은 배경 없이 왼쪽 끝의 3dp 막대와 굵은 글자(강조색)로 표시하고, 선택하지 않은 항목은 흐린 글자입니다. 항목 높이는 48dp 이상이고 헤더 글자와 항목 글자는 같은 위치에서 시작합니다. 선택한 섹션은 오른쪽에 표시되며 그 섹션만 자체 스크롤합니다.
- **폭 840dp 미만**: 맨 위에 계정 헤더, 그 아래에 좌우로 스크롤되는 섹션 탭, 그 아래에 선택한 섹션이 나옵니다. 목록을 먼저 보여 주는 대신 탭을 쓰는 이유는 섹션을 한 번에 바꿀 수 있게 하기 위해서입니다.
- 대시보드는 열 때마다 **개요**에서 시작합니다. 고른 섹션은 화면을 돌리거나 앱이 다시 만들어져도 유지되며, 고른 섹션의 데이터가 사라지면 개요로 돌아갑니다. 최대 폭은 1280dp이고 섹션 안의 긴 목록은 정해진 높이 안에서 따로 스크롤합니다.

**계정 헤더**에는 사용자 지정 이름과 게임 이름, 서버 표시(**KR / JP**), `Lv N`, **N분 전 갱신**(마지막 갱신 시각 기준이며 1분마다 다시 계산합니다. 정확한 시각은 화면 읽기 설명에 있습니다)이 들어 있고, 그 아래에 **AP**가 있습니다. AP는 `현재 / 최대`를 크게, 가는 진행 막대와 **HH:mm 가득 참**(이미 가득 차면 **가득 참**) 뒤에 게임이 알려 주면 ` · 이월 AP N`을 표시하며 어느 섹션에서나 보입니다(넓은 화면은 왼쪽 창, 좁은 화면은 맨 위 헤더). 친구 코드는 헤더가 아니라 개요의 **계정**에 있습니다. 생일과 메시지는 표시하지 않습니다. 내보내기·프렌드·설정 아이콘은 상단 바에 그대로 있습니다.

### 개요

위에서부터 다음 순서이며, 데이터가 없는 항목은 숨깁니다. AP는 헤더로 옮겼으므로 개요에는 핵심 수치 줄이 없습니다.

- **재화**: 아이콘·이름·오른쪽 정렬 개수를 한 줄씩 다음 순서로 표시합니다. 성정석(이름 뒤에 작은 글자로 **무료 N · 유료 N**), 성정편, 소환권(호부), 티포트(가진 티포트 합계), 스톰 포드, 마나 프리즘, 레어 프리즘, 청동 묘목, QP. 아이템 표를 받은 계정은 **모든 줄을 항상 표시**하며 갖고 있지 않은 재화는 0입니다(티포트가 없어도 0으로 나오며, 아이콘은 Atlas에 있는 티포트 중 하나를 씁니다). 아이템 표가 없으면 0을 채우지 않고 값을 아는 줄만 표시합니다.
- **사과**: 금·은·청동색 코발트·청동 순서의 과일 네 종류를 아이콘과 개수로 한 줄에 표시합니다.
- **서번트**: **보유 `보유 / 전체`**(막대 없음), **★5 보합**(보유한 ★5 서번트의 보구 레벨 합), **전체 보합**(보유한 모든 서번트의 보구 레벨 합)을 한 줄에 표시하고, 그 아래에 ★5부터 서버에 있는 가장 낮은 레어도까지 한 줄씩 레어도·가는 막대(보유/전체)·`보유 / 전체`·그 레어도의 보합을 표시합니다. 전체는 계정 서버(KR 또는 JP)의 Atlas 서번트 목록에서 도감 번호가 있고 플레이 가능한 종류(`normal`, `heroine`)인 것만 세며, 서버마다 자기 목록을 씁니다. 그 목록이 없으면 `/ 전체`와 막대 없이 보유 수와 보합만 표시합니다. 보유 수와 보구 레벨은 서번트 섹션의 줄과 같은 값입니다.
- **보관**: 서번트와 기타(종화·포우 등)를 한 막대에 두 색으로 나누고 범례 줄을 붙이며, 개념예장은 별도 막대로 일반 보관 상한과 비교합니다. 커맨드 코드와 두 번째 보관소 수는 이름 아래에 숫자로 표시합니다. Atlas 분류 목록이 없으면 총수만 표시합니다. 보관소 확장 보정값은 상한에 더하지 않습니다.
- **최근 기록**: 이 계정의 최근 전투 기록과 스크립트 밖 변화 한 건씩의 시각·이름 또는 기간·간단한 증감을 표시하고, **전체 보기**로 로그를 엽니다. 둘 다 없으면 이 그룹은 숨깁니다.
- **계정**: 친구 코드(복사 버튼 포함), 프렌드 포인트, 경험치, 코스트 상한, 친구(친구 목록을 받았으면 `143 / 146`, 아니면 상한만), 계정 생성일, 스냅샷 시각, 앞으로의 영주 회복 시각을 격자로 표시합니다.

폭 840dp 이상에서는 재화·사과·서번트가 왼쪽 열, 보관·최근 기록이 오른쪽 열이며 **계정**은 두 열 아래에 전체 폭으로 놓입니다. 좁은 화면에서는 재화, 사과, 서번트, 보관, 최근 기록, 계정 순서로 한 열에 이어집니다.

### 서번트

- **서번트 도감**: 보유 상태인 서번트의 이름·클래스·레어도·코스트·얼굴, 인연·보구·최고 스킬·최고 레벨을 표시합니다. 정렬 버튼은 **인연 / 코스트 / Lv** 순서이며 기본은 인연입니다. 모두 높은 순서로 정렬하고 인연은 포인트도 비교합니다. 동률은 인연→포인트→코스트→최고 Lv 중 아직 비교하지 않은 항목, 마지막으로 ID 순으로 정합니다. 코스트는 ★5=16, ★4=12, ★3=7, ★2=4, ★1=3, ★0=4이며 마슈는 0입니다. 클래스 필터는 맨 위 **전체**와 클래스 칩 줄(가로 스크롤, 세이버·아처·랜서… 게임의 클래스 순서이고 비스트 계열과 모르는 클래스는 맨 뒤)로 고르며, 같은 표시 이름은 하나로 묶고 모든 비스트 종류는 **비스트** 하나로 고릅니다. U-올가마리의 언비스트 클래스는 **언비스트**로 따로 표시합니다. 모르는 클래스는 원래 이름을 표시합니다. 맨 위 줄에는 **보유 `327 / 412` (79%) · ★5 보합 `142` · 전체 보합 `612`**와 정렬 칩이 있습니다(개요의 서번트와 같은 정의이며 전체가 없으면 `/ 412`와 퍼센트를 뺍니다). 이 줄은 선택한 클래스 칩에 따라 다시 계산합니다(**전체**는 전부, **세이버**는 세이버만, 여러 클래스를 묶은 칩은 그 묶음 전체이고 전체 수도 서버의 해당 클래스 서번트로 셉니다). 좁은 화면에서는 줄이 부분 사이에서만 넘어갑니다. 넓은 화면은 얼굴·이름(아래에 클래스 · ★)·Lv `현재/최대`·인연·보구·스킬 `a/b/c`·어펜드 `a/b/c/d/e` 열이 있는 표이고, 좁은 화면은 한 서번트가 세 줄입니다(1줄: 얼굴·이름·클래스 · ★, 2줄: `Lv · 인연 · 보구`, 3줄: `스킬 · 어펜드`). 레벨 10인 스킬·어펜드는 금색으로 표시하고 해금하지 않은 어펜드는 흐린 –로 나타냅니다. 5기 제한과 **전체 보기**는 없고, 선택된 서번트 전체가 목록 안에서 스크롤됩니다(정렬 칩과 클래스 칩, 표 머리글은 고정). 이름 검색은 없습니다.

### 아이템

- **아이템 보유 현황**: 양수가 있는 아이템을 강화 재료(퓨어 프리즘·짐승의 발자국 포함), 휘석·마석·비석, 피스·모뉴먼트, **성배·전승 결정·몽화**, 이벤트, **서번트 코인**, 기타로 나눕니다. 그룹 순서는 성배·전승 결정·몽화가 맨 위이고 그다음 강화 재료, 휘석·마석·비석, 피스·모뉴먼트, 이벤트, 서번트 코인, 기타입니다. 칼데아의 몽화(KR), カルデアの夢火·カルデアの大夢火(JP)는 Atlas 아이템 이름으로 찾아 성배 그룹에 넣으며 강화 재료에는 나오지 않습니다. **서번트 코인**은 1개 이상 가진 서번트의 코인을 개수가 많은 순서로 표시하며, 이름과 아이콘은 Atlas 아이템 목록에서 가져옵니다. 이벤트·서번트 코인·기타는 처음에 접혀 있고 위에 나온 재화는 중복하지 않습니다. 개요의 재화에는 소환권과 스톰 포드가 항상(없으면 0) 표시되고, 가진 티포트는 모두 합쳐 **티포트** 타일 하나로 보여 주며 이 항목들은 목록에서 빠집니다.
- **이름으로 찾기**: **아이템 보유 현황** 제목 오른쪽 끝의 **검색 아이콘**을 누르면 제목 아래에 검색란이 나타나고 바로 입력할 수 있습니다(처음에는 숨겨져 있습니다). 이름 일부를 넣으면(대소문자 무시) 일치하는 아이템이 있는 그룹은 자동으로 펼쳐지고, 없는 그룹은 숨겨집니다. 검색란 오른쪽 **×**를 누르면 검색어를 지우고 검색란을 닫으며, 그룹은 검색 전에 열려 있던 상태로 돌아갑니다. 휘석·피스 표는 일치하는 칸을 강조해 보여 줍니다.
- **휘석·마석·비석 / 피스·모뉴먼트 표**: 행은 휘석·마석·비석(피스·모뉴먼트 표는 피스·모뉴먼트), 열은 세이버·아처·랜서·라이더·캐스터·어새신·버서커 순입니다. 8번째 열은 계정에 그 아이템이 하나라도 있을 때만 생기며 머리글은 Atlas 아이템 이름입니다. 갖고 있지 않은 칸은 흐린 "–"로 표시하고, 개수가 **10 미만**이면 빨간색으로 표시합니다. 좁은 화면에서는 "세이", "아처"처럼 짧은 클래스 이름을 쓰며 화면 읽기 도구에는 전체 이름을 읽어 줍니다.
- **강화 재료 등 목록**: 아이콘·이름·오른쪽 정렬 개수로 표시하며 넓은 화면은 3열, 좁은 화면은 1열입니다. 강화 재료는 기록된 순서의 반대로 나열하며(퓨어 프리즘·별빛의 모래·신성의 토치 등은 맨 뒤) 처음 12종만 보이고 **더 보기 (N종)**로 나머지를 펼칩니다. 이벤트·서번트 코인·기타는 접힌 채 시작하며 펼치면 처음 48종만 보입니다. 각 그룹 제목에는 종류 수가 붙습니다(예: **강화 재료 96종**).

### 편성

- **서포트 편성**: 내 서포트 편성을 읽기 전용으로 보여 줍니다. **일반 / 이벤트** 선택(게임의 고정 편성 목록 기준)과 **편성 1, 2, …** 선택이 있습니다. 클래스별 행 왼쪽에 40dp 서번트 얼굴, 가운데에 이름과 **관위** 표시(관위 서번트만), 그 아래 `Lv · 보구 · 클래스`를 표시합니다. 오른쪽 개념예장은 아이콘 없이 `이름 · Lv100 · 최대`처럼 한 줄로 표시하며, **최대**는 최대 한계 돌파 때만 붙습니다. 이름이 길면 이름부터 줄이고 레벨·최대 표시는 남깁니다. 장착 예장이 없으면 **예장 없음**을 표시합니다. 스킬·어펜드는 표시하지 않습니다. 편성 목록을 읽지 못하면 모든 편성을 일반 아래에 나열합니다.
- **관위 편성**: 관위 자리 순서대로 같은 간결한 서번트 행을 표시합니다. 개념예장 1과 3은 각각 한 줄로, 그 아래에 작은 **인연: NP 차지 / 기본 효과 / 없음** 표시를 보여 줍니다. 관위 편성 데이터가 없으면(KR 등) 이 카드는 나타나지 않습니다.
- **마술예장**: 레벨순으로 이름·아이콘·레벨과 장착 상태를 표시합니다.

### 도감·소환

- **커맨드 코드 도감**: 로그인 스냅샷에서 보유 상태(`status == 2`)인 커맨드 코드 수와 Atlas 목록 기준 전체 수(**보유 N / 전체 M**, Atlas 목록이 없으면 **보유 N**)를 표시합니다. **+ 보유 (N)** 그룹은 처음에 접혀 있으며 누르면 보유한 커맨드 코드 아이콘·이름 격자를 펼칩니다. 커맨드 코드 도감 표가 없으면 이 카드는 숨깁니다.
- **클래스 스코어**: 마지막 로그인 스냅샷의 클래스 스코어 보드별 칸·잠금 해방 진행도(**칸 a / b · 잠금 c / d**, Atlas 요약이 없으면 **칸 a · 잠금 c**. 빈칸은 세지 않고 잠금 칸은 따로 셉니다)와 완료 표시를 보여 주며 아직 시작하지 않은 보드도 포함합니다. 처음 3개 보드만 보이고 나머지는 **전체 보기 (N)** / **접기**로 전체를 볼 수 있습니다. 클래스 스코어 표가 없으면 이 카드는 숨깁니다.
- **소환 기록**: 마지막 로그인 스냅샷의 **친구 포인트 소환 N회** 합계와 기타 소환 목록(상위 10개 기본 표시, **전체 보기**·**접기**)을 보여 주며 **+ 최근 소환 내역** 그룹을 눌러 날짜별 소환 기록을 펼칩니다. 소환 기록 표가 모두 없으면 이 카드는 숨깁니다.

### 선물함

- **선물함**: 로그인 스냅샷의 선물함(`userPresentBox`) 행 수를 **선물함 (N)**으로 표시합니다. 같은 종류·ID의 선물을 합산해 아이템(`giftType 2`)을 먼저, 그다음 종화·포우·서번트·개념예장·커맨드 코드 등을 수량이 많은 순서(동률은 ID 순)로 타일로 표시하며 선물 메시지는 표시하지 않습니다. 처음 12종류만 보이고 나머지는 **전체 보기 (N)** / **접기**로 펼칩니다. 선물함 표가 있지만 비어 있으면 **선물 없음**을 표시하고, 선물함 표 자체가 없으면 카드를 숨깁니다.

편성 카드에는 별도의 데이터 기준 시각을 표시하지 않습니다. 마지막 갱신 시각은 계정 헤더에서 확인합니다. 서포트 편성 데이터가 없거나 읽을 수 없으면 **편성 정보 없음**을 표시합니다. 표시 전용이며 자동화의 OCR·탭과 수집에는 영향이 없습니다.

Atlas KR의 공개 아이템·서번트·개념예장·마술예장 목록을 파일별로 캐시하고, 실패 재시도는 각 파일의 하루 제한으로 따로 관리합니다. 표시 중인 계정이 JP이거나 KR에 없는 ID가 있으면 별도 JP 목록으로 이름·얼굴·아이콘·분류를 보충합니다. 클래스 스코어와 소환 요약은 해당 계정 지역(KR 또는 JP)의 공개 목록에서 필요한 이름·기간·칸 ID만 추려 작은 요약 파일로 저장합니다. 스크립트가 실행 중일 때는 대시보드용 Atlas 목록을 내려받지 않고 기기에 저장된 파일만 읽습니다. 이름을 모르는 서번트는 `#ID`로 표시합니다. 얼굴과 마술예장 아이콘은 표시할 때 없는 파일만 공개 HTTPS 자산 서버에서 내려받아 영구 보관합니다. **로그 수집 데이터 삭제** 후에도 이 공개 목록과 이미지는 남습니다. 계정 데이터는 전송하지 않습니다.

**더 많은 옵션 → 저장소 → 로그 아이콘 데이터 다운로드**(로그 수집 사용이 켜진 Android 10 이상에서만 표시)로 대시보드와 로그 아이콘을 미리 준비할 수도 있습니다. 서포트 이미지 추출과는 별개의 항목입니다. 일반 서번트·마슈 얼굴, 스킬·보구 강화 재료, 재화·과일, 마술예장을 받으며 이벤트 아이템은 제외합니다. 첫 다운로드는 약 15 MB로 Wi-Fi를 권장합니다. 화면을 나가도 계속되며 진행 중 다시 눌러도 작업이 중복되지 않습니다. 앱 종료 후에는 다음에 누를 때 없는 파일만 받습니다. 항목 아래에는 진행 상태나 결과만 표시합니다. [진행 표시와 재시도 안내](Default-Support-Images-KR.md)

## 스크립트 밖 변화

로그 수집이 실행 중이고 스크립트를 실행하지 않는 동안의 계정 변화를 **메인 → 로그**에 한 기간당 **한 줄**로 모읍니다. 스킬 강화, 퀘스트 없이 과일 사용, 선물함 수령, 상점 교환, 소환, 수동 퀘스트 등이 대상입니다. 스크립트 실행 중의 응답은 기존 실행별 전투 로그에서 처리하며 이 기록에 중복으로 넣지 않습니다.

첫 자원 변화부터 목록 맨 위에 **진행 중** 기록을 표시합니다. 변화가 추가될 때마다 합계·출처·종료 시각이 바로 갱신됩니다. 다음 경우 같은 기록을 확정하며 중복으로 추가하지 않습니다.

- 다음 스크립트 시작
- 버튼·알림·권한 철회·시스템 종료 등으로 로그 수집 중지
- FGA 서비스 종료(서비스가 멈춰도 로그 수집을 유지하는 설정일 때도 확정)
- 다른 계정의 응답 수신: 이전 계정의 기간을 확정하고 계정을 섞지 않음

변화가 없는 기간은 기록하지 않습니다. **로그인(`login/top`)의 차이는 기록하지 않습니다.** 로그 수집을 끄거나 다른 기기에서 플레이한 변화가 섞일 수 있으므로, 로그인에서는 계산 기준만 새 스냅샷으로 바꿉니다. 이후 받은 응답부터 변화를 계산합니다.

목록 카드는 두 줄입니다. 첫 줄은 제목과 바로 옆의 작은 계정 이름, 오른쪽의 시각(전투는 종료 일시, 스크립트 밖 변화는 시작–종료 범위)을 표시합니다. 둘째 줄은 전투의 주회 수·평균 턴·추적됨·종료 이유 또는 스크립트 밖 변화의 아이템·카드 증감 종류 수·성정석 변화를 표시합니다. 전투 카드는 회색, 스크립트 밖 카드는 별도 색과 아이콘을 사용하며 선택했을 때만 같은 테두리가 붙습니다. 누르면 다음을 확인할 수 있습니다.

- **전체 변화**: 기간 내 아이템·서번트·개념예장·종화·포우·커맨드 코드의 순변화를 합산해 획득(+)과 사용(−) 목록으로 나누고, 각각 양이 큰 순서로 표시합니다. QP, 마나프리즘, 레어프리즘, 무료·유료 성정석은 부호가 붙은 수로 표시합니다.
- **사용한 과일**: 황금색·백은색·청동색·적동색 과일이 각 응답에서 줄어든 수를 합칩니다. 나중에 과일을 받더라도 앞서 사용한 수는 지워지지 않습니다.
- **출처별 변화**: 선물함, 상점, 소환, 룰렛, 강화, AP 회복, 수동 퀘스트, 미션, 로그인별로 묶습니다. 로그인할 때 받은 프렌드 포인트(다른 플레이어가 내 서포트를 빌려 간 몫)는 **로그인**으로 기록됩니다. 기본은 접혀 있으며 누르면 같은 형식의 자원 변화를 볼 수 있습니다. 분류되지 않은 응답은 **기타**와 쿼리를 제외한 경로를 표시합니다.

서번트·개념예장·종화·포우는 일반 보관함과 두 번째 보관소의 카드 수를 합쳐 종류별로 비교합니다. 강화에 종화 12장을 쓰면 −12, 상점에서 같은 개념예장 3장을 팔면 −3으로 기록합니다. 보관함 사이 이동이나 레벨·재림·잠금만 바뀐 경우에는 개수 변화가 생기지 않습니다. 커맨드 코드도 종류별 카드 수를 비교합니다.

전체·출처별 상세는 같은 아이콘 타일을 사용합니다. 변하지 않은 재화와 사용하지 않은 과일 등 **0인 항목은 숨깁니다**. 과일은 순변화에 묻히지 않도록 받은 양과 실제 사용한 양을 나누어 표시합니다.

카드 이름과 얼굴은 Atlas KR의 공개 `basic_svt`(모든 카드 종류, 약 2 MB)·`basic_command_code` 목록을 사용합니다. 기록의 계정이 JP이거나 KR에 없는 서번트·개념예장이 있으면 JP의 `basic_servant`·`basic_equip` 목록에서 보충합니다. 종화는 같은 이름 뒤에 클래스 이름을 괄호로 붙이며, 모든 비스트 계열은 **비스트**, ALL 클래스는 **전체**로 표시합니다. 이름이 없으면 `#ID`로 표시합니다. 목록은 앱 내부 `capture/names/`에 보관하며 화면이 필요로 할 때 Atlas 데이터 버전을 확인해 바뀐 경우에만 다시 내려받고, 버전을 읽지 못하면 파일이 없거나 받은 지 7일 이상일 때 파일별 하루 최대 한 번 갱신을 시도합니다. 카드 얼굴은 표시할 때 없는 파일만 받아 서번트·개념예장·종화·포우는 `capture/icons/servants/`, 커맨드 코드는 `capture/icons/commandCodes/`에 보관합니다. **로그 수집 데이터 삭제** 후에도 공개 목록과 아이콘은 남습니다.

출처는 API 경로로 추정합니다. KR 응답에서 확인된 경로는 `present/receive`(선물함)와 `battle/result`(수동 퀘스트)입니다. 나머지 접두사(`shop/`에서 `shop/Verify` 제외, `gacha/`, `boxGacha/`, `card/`, `svt` 계열, `item/recover`, `eventMission/`, `mission/`)는 추정 분류이며 게임 업데이트나 실제 응답에 따라 달라질 수 있습니다. 강화의 `svt` 계열에는 `svt/`뿐 아니라 `svtCombine/`, `svtSkill/`처럼 접두사를 공유하는 경로도 포함합니다. `shop/Verify`와 모르는 경로는 기타로 남습니다. 웹 스토어 결제 반영 응답(`externalPayment/reflect`)은 **트럭**으로 표시되며 필터에서는 기타로 집계됩니다.

열린 기간은 앱 내부 `capture/accounts/<userId>/outside-period.json`에 저장되며 프로세스가 종료되어도 다음 초기화 때 이어집니다. 확정된 기록은 별도의 `outside-log.json`에 설정한 보관 개수만큼 최신 기록을 보관합니다. 진행 중 기록 다음에 전투 로그와 함께 종료 시각 순으로 표시합니다.

필터·보관 개수(50 / 100 / 200건, 기본 200건)·삭제 사용 방법은 [전투 로그](Battle-Log-KR.md)와 같습니다.

- **획득 자원 필터**: 같은 ID인 아이템과 카드는 구분해서 고르며, 스크립트 밖 기록은 다른 출처에서 더 많이 사용해 최종 합계가 음수여도 획득한 출처가 있으면 표시합니다.
- **진행 중 기록 삭제**: 진행 중 기록을 삭제하면 그 열린 기간을 버리고, 이후 새 변화부터 새 기간을 시작합니다.

계정을 삭제하면 그 계정의 열린 기간을 버리고, **로그 수집 데이터 삭제**는 모든 열린 기간을 버립니다. 이미 확정된 전투 로그와 스크립트 밖 기록은 유지되므로 **메인 → 로그**에서 따로 삭제합니다.

## 제한

- FGA VPN 방식: Android는 한 번에 **VPN 하나**만 허용합니다. 다른 VPN 앱을 켜면 로그 수집은 중지되고 중지 사유가 표시됩니다. AdGuard나 WireGuard 등 다른 VPN·프록시 앱과 함께 사용하려면 연결 방식을 **외부 앱 프록시**([외부 앱 프록시 모드](Capture-AdGuard-KR.md)) 또는 루트 기기에서는 **루트**([루트 수집 모드](Capture-Root-KR.md))로 전환해 사용하세요.
- 로그 수집이 켜져 있는 동안 상단 알림에 **중지** 버튼(외부 앱 프록시와 루트는 **수집 끄기**)이 표시됩니다.
- 세 방식 모두 FGO의 통신을 FGA가 대신 주고받으므로, 게임 데이터 사용량이 FGA로 집계됩니다. 휴대폰 설정에서 FGA의 모바일 데이터 사용을 막아 두면 와이파이에서는 되지만 셀룰러(LTE/5G)에서는 게임이 접속하지 못합니다.
- 로그 수집이 실행 중일 때 받은 응답만 반영합니다. 게임을 시작하지 않은 사이의 변화는 다음 로그인에서 새 스냅샷으로 갱신됩니다.

## 데이터와 인증서 지우기

- **로그 수집 데이터 삭제**를 누르고 확인하면 **모든 계정**의 수집 데이터와 열린 기간, FGA가 FGA 폴더의 `capture` 폴더에 만든 Chaldea 파일을 지웁니다. 예전 버전이 `Download/FGA/`에 저장한 파일은 지우지 않으므로 필요하면 직접 지우세요. 계정 카드의 **삭제**는 그 계정만 지웁니다. 이미 저장된 전투 로그와 스크립트 밖 기록은 **메인 → 로그**에서 별도로 삭제합니다. 공개 자산인 이름 목록과 아이콘 파일은 유지합니다.
- 인증서가 이미 있으면 **인증서 파일 다시 저장**이 같은 인증서를 `capture` 폴더에 다시 저장합니다. 새 인증서를 만들려면 **새 인증서 만들기**를 따로 눌러야 하며, 이때 이미 설치한 인증서를 다시 설치해야 한다는 확인 창이 먼저 나옵니다. 저장에 실패하면 기존 인증서는 바뀌지 않습니다. 새 인증서를 만든 뒤에는 이전 인증서를 삭제하고 새 인증서를 설치하세요.
- **새 인증서 만들기**는 로그 수집을 중지한 뒤에만 사용할 수 있습니다. 수집 중에도 기존 인증서 파일은 다시 저장할 수 있습니다. 인증서 저장 중에는 두 버튼이 모두 잠기며, 시스템 저장창을 취소하면 기존 인증서와 키는 바뀌지 않습니다.
- 시스템 저장창으로 저장하면 공급자가 알려 주는 상위 폴더나 선택한 폴더 이름과 실제 파일 이름을 표시합니다. 폴더 이름을 확인할 수 없으면 **선택한 위치/파일 이름**으로 안내합니다.
- Chaldea 파일은 시스템 저장창으로 저장한 것도 계정별로 관리합니다. 새 파일을 저장한 뒤 이전 파일을 지우며, 계정 삭제와 전체 데이터 삭제에도 포함합니다. 파일 앱 등에서 이미 지운 파일은 다음 내보내기나 삭제 때 없는 것이 확인되면 관리 목록에서도 지우고 삭제 실패로 안내하지 않습니다. 이전 파일이 남아 있지만 지울 권한이 없거나 파일 공급자가 삭제를 거부하면 **내보낸 Chaldea 파일을 삭제하지 못했습니다**라고 표시하고 새 파일과 이전 파일의 관리 기록은 유지합니다. FGA 폴더 권한이 사라진 경우에도 같은 안내가 나오며 앱 내부 데이터는 삭제됩니다. 권한을 다시 허용한 뒤 재시도하거나 남은 파일을 직접 지우세요. 저장창을 취소하면 기존 Chaldea 파일은 유지됩니다.
- 인증서를 완전히 지우려면 **설정 → 보안 → 암호화 및 사용자 인증 정보 → 사용자 인증서**(또는 신뢰할 수 있는 인증 정보의 사용자 탭)에서 `FGA-Modified log collection`(기존 인증서는 `FGA-Modified gains tracker`) 인증서를 삭제합니다. 필요하면 `capture` 폴더의 `fga-capture-ca.crt` 파일(예전 버전은 `Download/fga-capture-ca.cer`)도 지웁니다.
