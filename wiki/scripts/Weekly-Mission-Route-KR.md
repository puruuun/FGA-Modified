# 주간 미션 클리어

**이번 주 주간 미션을 가장 적은 AP로 채우는 퀘스트와 횟수를 계산하고, 메인 화면에서 장과 지도를 찾아 전체 경로를 실행합니다. 사용할 전투 설정과 사과 설정을 먼저 확인하세요.**

JP·KR 서버용 기능으로 정규판 1.6.0부터 지원합니다. 인터넷이 필요합니다. 실제 게임 진행도는 읽지 않습니다.

## 시작하는 방법

1. 게임의 **메인 화면**을 엽니다. 왼쪽 위에 `お知らせ` / `공지`가 있는 화면입니다. 퀘스트 판이나 장 목록에서 시작하지 마세요.
2. FGA 재생 버튼 → 설정 창 왼쪽 아래의 **주간 미션 클리어**를 누릅니다.
3. 실행 창 **오른쪽에 주간 미션 패널**이 붙습니다. 같은 버튼을 다시 누르면 접힙니다. 왼쪽 전투 설정·AP·아이템·제한 설정을 그대로 사용합니다.
4. **다운로드**를 누릅니다. 미션·장·적 구성 다운로드 단계와 진행 막대가 표시됩니다. 이번 주 캐시가 있으면 바로 경로가 나옵니다.
5. 수동 미션에는 체크박스가 없으며 저장된 과거 선택도 무시합니다. 체크를 끈 미션은 원래 순서에 회색으로 남습니다. 미션 앞 체크를 끄면 해당 미션을 계산에서 뺍니다. 이미 끝낸 미션도 이렇게 제외하세요. 기본은 모두 켬이며 서버·주차별 선택이 앱 재시작 후에도 유지되고 새 주에는 초기화됩니다. 선택을 바꾸면 경로를 다시 계산하며 **−/+ 횟수**도 새 계산값으로 돌아갑니다.
6. 총 AP와 퀘스트별 횟수를 확인한 뒤 공용 **확인**을 누릅니다. 패널이 열려 있고 횟수가 남은 경로가 있으면 주간 경로를 실행합니다. 경로가 비면 확인을 눌러도 실행하지 않고 **실행할 퀘스트가 없습니다**를 표시합니다. 패널이 접혀 있어도 일반 전투를 시작합니다. 취소하면 게임을 조작하지 않습니다.

**더 많은 옵션 → 추가기능 → 주간 미션 경로 활성화**는 기본 켜짐입니다. 끄면 전투 시작 창의 주간 미션 버튼이 숨겨집니다.

장·퀘스트 후보는 **더 많은 옵션 → 추가기능 → 주간 퀘 추적 설정**에서 서버별로 켜고 끕니다. 장 이름의 +를 누르면 프리 퀘스트를 펼칩니다. 기본은 모두 켬이며, 장을 끄더라도 개별 퀘스트 선택은 보존됩니다. 데이터가 없으면 먼저 실행 창에서 해당 서버의 데이터를 다운로드하세요. 믹틀란과 주장(Ordeal Call Ⅰ~Ⅳ)은 지원하지 않아 목록에 나오지 않습니다.

## 확인 창과 계산

**보물창고 초급**(10 AP)도 후보입니다. 적 구성이 고정된 캐스터 9체여서 다른 난이도 대신 초급만 사용하며, 경로에서 항상 마지막에 방문합니다. **주간 퀘 추적 설정 → 요일 퀘스트**에서 끌 수 있고 탐색 시험에도 포함됩니다.

다른 퀘스트가 끝나면 공지 버튼으로 메인 화면을 확인합니다. 이동은 **메인 → 칼데아 게이트 → 요일 퀘스트 → 노란 보물창고 초급 판**입니다. 게이트를 누른 뒤 닫기를 기다리고, 목록 안의 요일 배너를 찾아 누른 뒤 닫기와 일일 퀘스트 판 앵커를 함께 기다립니다. 우측 제목이나 이벤트 배경은 화면 분류에 쓰지 않습니다. 노란 배경과 두 번 일치한 퀘스트 이름을 함께 확인해야 누릅니다. 빨간 종화·초록 수련장과 보물창고의 다른 난이도는 사용하지 않습니다. 캠페인 중 표시 AP가 계산 AP와 달라도 이름·색으로 확인하며, 마지막 주회 뒤에는 요일 퀘스트 목록으로 돌아옵니다. 먼저 탐색 시험으로 확인하세요.

| 항목 | 설명 |
|---|---|
| 이번 주 미션 | 체크한 미션만 계산합니다. 이미 완료한 미션은 체크를 끄세요. 일부 진행량은 횟수로 조정합니다. |
| 체크를 끈 미션 | 이번 주 목록의 원래 위치에 회색으로 남으며 다시 켤 수 있습니다. 수동 미션에는 체크박스가 없습니다. |
| 경로 | 장 / 지점 / 퀘스트 이름 / AP / 횟수 및 전체 AP입니다. 횟수 0인 퀘스트는 실행하지 않습니다. |
| 후보 설정 | 별도 주간 퀘 추적 설정에서 끈 장·퀘스트는 경로 계산에서 제외됩니다. |
| 수동 | 드롭 미션 등 계산하지 못하는 조건입니다. 직접 채워야 합니다. |
| 제외됨 | **지원하지 않는 장:** 믹틀란(war 311)은 층 전환 방식이 달라, 주장 Ⅰ~Ⅳ(war 402~405)는 소유자 결정으로 제외합니다. 경로 후보·탐색 시험 대상·주간 퀘 추적 설정·장 목록 어디에도 나오지 않습니다(JP·KR 공통). 헤이안쿄(307)·트라움(310)은 메인·인터루드 장으로 지원합니다. |
| 전투 설정 | 왼쪽 목록에서 고른 설정을 사용합니다. 서로 다른 적 구성에서도 동작할 설정을 사용하세요. |

반복 가능한 메인 스토리 프리 퀘스트만 계산합니다. `afterClear=close`인 후유키의 일회성 `危険地帯` 등은 제외합니다. 적 특성·클래스·서번트 클래스·특정 적·퀘스트 클리어·퀘스트 특성 조건을 지원하며, 지원하지 못하거나 달성 가능한 후보가 없으면 수동으로 표시합니다. 합계 미션은 개별 조건을 완료하면서 함께 채워집니다.

KR 후보·이름·AP는 KR 데이터이고, **KR 적 구성은 JP 데이터 기준**입니다. 같은 퀘스트 ID의 JP AP와 KR AP가 다르면 제외합니다. 계산 자료는 서버·주차별로 앱 캐시에 저장합니다. 처음 받거나 형식이 갱신되면 시간이 걸릴 수 있습니다. 장 배너·지도 그림도 Atlas Academy에서 받아 캐시합니다.

## 자동 이동과 전투

- JP는 메인 레코드 **1 / 1.5 / 2**를 거칩니다. KR은 **1 / 1.5**를 거치며 2부 장은 메인 화면 목록에서 찾습니다. 헤이안쿄·트라움은 메인 레코드가 아니라 메인 화면 맨 아래 **메인·인터루드** 버튼 안에 있으므로 마지막에 방문합니다(beta.10).
- 장 버튼은 Atlas 배너의 실제 버튼 내부 그림으로 찾습니다. 아래 항목을 찾을 때는 손가락을 위로 밀고, 한 방향에서 찾지 못하면 반대로도 검색합니다. 각 방향 최대 14회이며, 찾지 못하면 그 장의 퀘스트를 건너뜁니다.
- 장에 들어갈 때 두 손가락 핀치로 지도를 최대로 축소합니다. 제스처가 거부되면 진행하지 않습니다.
- 이름표 위치를 추측해 누르지 않습니다. Atlas 지도와 화면의 특징점을 맞춰 가로·세로 배율과 위치를 계산하고, 일치점 수·분포·오차가 충분한 경우에만 지점을 누릅니다. 화면 밖이면 관성 없는 스크롤 후 다시 확인합니다.
- 퀘스트의 `mapId`에 맞는 지도 그림을 사용합니다. 지도가 맞지 않으면 그 장의 나머지 퀘스트도 건너뜁니다. 여러 지도 사이의 임의 전환이나 믹틀란 층 버튼은 누르지 않습니다.
- 퀘스트 판은 **Free Quest 표시 + 이름**을 확인합니다. 편성 조건이 있는 미션 퀘스트는 누르지 않습니다. 위 판이 미션 퀘스트라면 아래 프리 퀘스트도 검사합니다.
- 이름은 JP·KR OCR을 서버의 **전체 프리 퀘스트명 사전**과 대조합니다. 목표 이름만 사전으로 주지 않습니다. 드문 한자·받침 오독은 최대 2글자·전체의 1/3 이내, 다음 후보와 2글자 이상의 차이, 두 판독의 합의를 모두 만족해야 보정합니다. 비슷한 이름이 겹치거나 읽지 못하면 건너뜁니다. AP는 계속 읽어 로그에 남기지만 판정에 쓰지 않습니다. AP나 글자 폭만 맞는 판은 인정하지 않습니다.
- 전투·서포트 선택·AP 회복은 기존 FGA 흐름을 사용합니다. 횟수 제한만 퀘스트별로 임시 적용하고, 종료 시 원래 제한을 복원합니다. 사과 사용량은 전체 경로에서 사용한 만큼 한 번만 차감합니다.
- 같은 장의 다음 퀘스트는 판을 닫고 지도를 다시 찾습니다. 다른 장은 `ターミナル` / `터미널`로 장 목록에 돌아가고, 필요하면 `閉じる` / `닫기`로 메인 화면에 돌아갑니다.

## 종료와 확인할 내용

퀘스트별 **계획 횟수 / 실제 횟수 / 완료·찾지 못함·중단·미실행**과 수동 미션을 표시합니다. 배틀 중 AP 부족·패배·철수·사용자 정지 등으로 멈추면 남은 경로를 진행하지 않습니다. 지도나 버튼을 찾지 못한 경우도 실제 횟수를 확인하세요.

메인 화면이 아니면 아무것도 누르지 않고 시작 화면 안내를 표시합니다. 데이터 불러오기 실패는 인터넷·Atlas 접속 상태를 확인하고, 경로 계산 실패는 사용할 장을 줄여 다시 시도하세요. 탐색 실패의 자세한 단계는 로그에 남습니다.

```text
adb -s 127.0.0.1:5555 logcat -s WeeklyRoute
```

## 확인 범위와 한계

- 저장된 화면으로 JP 후유키 06~09·11, 오를레앙 19, 아틀란티스 20, KR 카멜롯 28~29의 지도 위치 추정과 다른 지도 거부를 검사합니다. 장 배너·버튼·퀘스트 판도 같은 생산 코드를 검사합니다.
- 실제 게임에서의 전체 이동·핀치·전투 연속 실행은 구현자가 조작하지 않았습니다. 소유자가 먼저 짧은 경로로 확인해야 합니다. 기기·화면 비율·게임 글꼴이 달라 판독 근거가 부족하면 건너뜁니다.
- 아직 열지 않은 장은 반드시 끄세요. Atlas와 게임의 실제 적 구성 차이로 미션이 덜 찰 수 있으며, 게임 안 주간 미션 진행도는 직접 확인해야 합니다.
- 지도가 다른 모습이거나 원하는 지점을 확정하지 못하면 추측해서 누르지 않습니다. 모든 다중 지도 장·와이드 화면·모든 퀘스트 이름을 실제 화면으로 검증한 것은 아닙니다.

## 판 위치가 움직일 때 — beta.6

- Free Quest 표시를 화면의 넓은 띠에서 찾고, 그 위치를 기준으로 AP·이름·누를 위치를 함께 계산합니다. 목록이 조금 위로 올라가도 고정 칸 좌표에 의존하지 않습니다.
- **먼저 읽습니다.** Match면 바로 진행하며 목록을 드래그하지 않습니다. 표시가 잘렸거나 일치하지 않을 때만 판 내부의 버튼 없는 자리에서 손가락을 위→아래로 한 번 움직이고 다시 읽습니다.
- 그래도 일치하지 않으면 판을 닫고 지점이 화면 가운데 근처에 오도록 관성 없이 이동한 뒤, 지도를 다시 맞춰 한 번 더 시도합니다. 맵 끝이라 가운데로 옮길 수 없어도 현재 지점이 안전하면 그 자리에서 한 번 더 엽니다. 최종 이름 판독이 일치하지 않으면 건너뜁니다. **Match가 아니면 퀘스트를 누르지 않습니다.**
- 장 배너로 지도에 들어간 직후와 터미널로 나간 직후에는 기존보다 1초 더 기다립니다(각각 3초).
- 주간 패널이 열려 있으면 왼쪽의 **제한** 항목은 숨깁니다. AP 회복·아이템·인연은 계속 표시됩니다. 패널을 접으면 제한 항목이 돌아오며 저장된 값은 바꾸지 않습니다.
- 베타에서 판독이 일치하지 않으면 **실행당 최대 8장**의 진단 PNG를 FGA 저장소의 `diagnostics/weeklyRoute/<실행번호>/`에 남깁니다. `WeeklyRoute` 로그의 `panel diagnostic path=`로 파일을 찾을 수 있습니다. 정규판에서는 저장하지 않습니다.

## 탐색 시험 모드 — beta.7

AP를 쓰지 않고, 모든 장의 지도에서 퀘스트를 찾을 수 있는지 실제 게임에서 점검하는 모드입니다.

- **켜는 곳:** 주간 미션 패널 위쪽의 **탐색 시험(AP 소모 없음)** 체크. 켜면 경로 목록 대신 시험 옵션이 보입니다. 메인 화면에서 시작하세요.
- **대상 범위:** 모든 메인 스토리 프리 퀘스트 / 선택한 장 / "주간 퀘 추적 설정"에서 켠 퀘스트. 선택한 퀘스트 수가 바로 표시됩니다. 믹틀란은 제외됩니다.
- **동작:** 주간 경로와 같은 이동(메인 → 메인 레코드 → 장 → 축소·지도 맞추기 → 지점 탭 → 판 읽기)을 하고 **판 판정까지만** 합니다. 판이 Match여도 **퀘스트 판을 누르지 않고** 판을 닫은 뒤 다음 퀘스트로 갑니다. 전투와 연속 출격은 시작하지 않습니다. 장 순서·지도 위치 순서로 방문합니다.
- **결과:** 퀘스트마다 성공 / 지도 맞추기 실패 / 지점 탭 후 판 없음 / 판 불일치 / 장 못 찾음 / 미실행과 걸린 시간을 기록합니다. 끝나면 요약 창(상태별 개수와 실패 목록)이 뜨고, CSV가 FGA 저장소 `diagnostics/weeklyRoute/probe/`에 저장됩니다. 실패한 곳의 화면은 진단 PNG로 `diagnostics/weeklyRoute/<실행번호>/`에 최대 100장까지 저장됩니다.
- **중간에 멈추면:** 그때까지의 결과를 CSV와 요약에 남기고, 가지 못한 퀘스트는 미실행으로 표시합니다.

- 주간 경로와 마찬가지로 지도·판 판독이 불확실하면 추측하지 않고 실패로 기록합니다.

## 지점 이름 확인·성공 증거·신 지도 — beta.9

beta.8 탐색 시험(JP 224개 중 165개 성공)에서 드러난 실패를 줄이는 보강입니다.

- **지점 이름을 두 번째 확인 수단으로 씁니다.** 지점을 누르면 게임이 그 지점을 크게 띄우고 이름표를 보여 줍니다. 이 이름을 읽어 같은 장의 Atlas 지점 이름과 비교합니다.
  - 퀘스트 이름이 읽히면 **퀘스트 이름이 단독으로 판정**합니다(`by=quest-name`). 읽힌 이름이 목표와 다르면 지점 이름이 맞아도 인정하지 않습니다.
  - 퀘스트 이름이 **전혀 안 읽힐 때만** 아래를 **모두** 만족하면 인정합니다(`by=spot-name+cells`): 지점 이름 일치 / 그 지점의 Atlas 프리 퀘스트가 하나뿐 / 판에 Free Quest 표시 / 이름 글자 너비가 목표 이름과 비슷. 지점에 프리 퀘스트가 둘 이상이면 이 규칙은 쓰지 않습니다.
  - AP는 계속 판정에 쓰지 않습니다. 로그(`WeeklyRoute`)에 퀘스트 이름·지점 이름의 글자 인식 후보와 신뢰도(`rawNames=`, `rawSpots=`), 판정 규칙(`by=`)을 남깁니다.
- **이름 판독을 고쳤습니다.** 이름 영역을 글자가 있는 부분만 잘라 4가지 방식(2·3·4배 확대, 이진화와 원본 그레이스케일)으로 읽고, 가장 잘 읽힌 것들이 서로 합의해야 인정합니다. 사전과 정확히 일치하는 판독은 낮은 신뢰도에서도 한 표로 셉니다.
- **지점이 UI 버튼에 걸린 경우.** 지점이 마스터 정보·선물 상자 같은 고정 버튼 구역에 30px 이내로 걸렸고 지도가 더 움직이지 않으면, 아이콘의 보이는 부분(구역 반대 방향 최대 30px)을 누릅니다. 누른 점은 구역에서 4px 이상 떨어져야 합니다.
- **지점을 눌렀는데 판이 안 뜨면** 누른 직후 화면을 진단 PNG로 저장하고, 1초 뒤 같은 점을 한 번 더 누릅니다. 그래도 없으면 `판 없음`으로 기록합니다.
- **신(Lostbelt No.3) 지도.** Atlas의 신 지도 그림은 8×8 빈 그림이고 실제 지도(`mapGimmicks`의 바탕 레이어 `gimmick_030301`)는 Atlas 서버에 없습니다. 그래서 그림 맞추기 대신 지도 크기와 지점 좌표로 위치를 정합니다. 지도를 위 또는 아래 끝까지 끌어(지도는 끝에서 멈춥니다) 위치를 고정한 뒤 지점을 누릅니다. 소유자 캡처 한 장에서 11개 지점의 위치가 8px 이내로 맞는 것은 확인했으나, **실제 게임에서의 동작은 소유자 확인이 필요합니다.** 지점이 보이는 퀘스트 판과 이름이 다르면 이전과 같이 실패로 처리하며 전투는 시작하지 않습니다.
- **헤이안쿄(307)를 장 목록에서 못 찾는 문제.** 배너 그림·크기·찾는 범위는 다른 장과 같아서 원인을 코드에서 확정하지 못했습니다. 장 목록을 끝까지 찾아도 없으면 목록 화면을 진단 PNG(위/아래 끝)로 저장하고 가장 비슷한 점수를 로그에 남깁니다. 이 화면으로 원인을 확인합니다.

### 탐색 시험의 성공 증거와 대조표

탐색 시험은 **성공한 퀘스트마다** 작은 증거 PNG(판 이름 영역 위, 지점 이름표 아래, 2배 확대)를 `diagnostics/weeklyRoute/<실행번호>/evidence/q<퀘스트ID>.png`에 저장합니다. 개수 제한은 없습니다. CSV(`diagnostics/weeklyRoute/probe/`)에는 열이 넷 늘었습니다: `evidence_file`(증거 파일), `by`(판정 규칙), `read_quest`(읽은 퀘스트 이름), `read_spot`(읽은 지점 이름).

CSV와 증거 폴더를 PC로 옮겨 대조표 한 장(HTML)을 만들 수 있습니다. 행마다 기대 퀘스트·지점 이름, 증거 이미지, 판정 규칙이 나옵니다. 위험한 `spot-name+cells`가 맨 위에 옵니다.

```text
py -3 tools/weekly-audit/contact_sheet.py probe-JP-<시각>.csv <증거 폴더> -o audit.html
```

이미지에서 위 줄의 퀘스트 이름과 아래 줄의 지점 이름이 행의 기대값과 다르면 거짓 성공입니다.
