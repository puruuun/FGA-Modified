## 追加・変更した機能

<a id="card-start"></a>

### 1. 通常カード枚数によるコマンド開始

カード枚数による開始モードを有効にし、開始時の前衛1～3番から対象サーヴァントと必要な通常カード枚数（1～5枚）を指定します。使用可能な通常カードが指定枚数以上になったら、予約したコマンドを最初から実行します。宝具やスタンなどで使用できないカードは数えません。

条件を満たさない間は、スキル・宝具・自動使用を保留し、通常攻撃でターンを進めて再判定します。最大待機ターンを指定でき、0は無制限です。モードを無効にすると従来の動作に戻り、保存した設定は維持されます。

<a id="dual-conditions"></a>

### 2. 2人のサーヴァントによる開始条件

2人目の対象と必要枚数を追加できます。両方の条件を同じ手札で判定します。

| 条件1 | 条件2 | 動作 |
|---|---|---|
| 満たす | 満たさない | 設定1を開始 |
| 満たさない | 満たす | 設定2を開始 |
| 満たす | 満たす | 設定1を優先 |
| 満たさない | 満たさない | 通常攻撃後、次のターンで再判定 |

選んだ設定は、そのクエストが終了するまで固定されます。次の周回では再判定します。2人目を使用しない設定にすると、1つの条件だけで動作します。

<a id="separate-settings"></a>

### 3. 条件ごとのコマンド・カード選択設定

設定1と設定2に、それぞれコマンド、カード優先順位、サーヴァント優先順位、ブレイブチェイン、カードの並べ替えを保存できます。

従来の基本設定を設定1として使い、重複して表示しません。設定2はその下に追加されます。コピー・エクスポート・インポートにも両方の設定が含まれます。

<a id="command-timing"></a>

### 4. 待機に合わせたコマンド位置の移動

条件を満たした実際の位置を、コマンド上の第1wave・1ターン目として扱います。実際の第2wave・3ターン目で開始した場合、コマンド第1wave・2ターン目は実際の第2wave・4ターン目に、第2wave・1ターン目は実際の第3wave・1ターン目に実行されます。

開始後はカード枚数条件を再適用せず、コマンドを続けます。開始前にwaveが変わっても待機を継続します。

<a id="shared-automatic-use"></a>

### 5. スキル・宝具の自動使用とシャッフルの共通設定

スキル・宝具の自動使用（Spam）とカードシャッフルは、条件ごとに分けず共通設定で管理します。どちらの条件で開始しても同じ設定を使います。

従来の設定1の自動使用・シャッフル設定は維持します。以前の設定2の自動使用・シャッフル設定は使いません。パーティ、サーバー、サポート選択、自動敵指定も共通です。

<a id="first-turn-shuffle"></a>

### 6. 初ターンの条件不足時にシャッフルして再判定

カードシャッフルの使用条件に、初ターンのコマンド開始条件を満たさない場合の選択肢を追加しました。

1. 最初のwaveの最初のターンに開始条件を判定します。
2. 条件を満たせば、その設定のコマンドをすぐに開始します。
3. どちらも満たさない場合、マスターの第3スキルでシャッフルを1回試みます。
4. 新しい手札で両方の条件を再判定します。
5. 条件を満たせば同じターンに開始し、満たさなければ新しい手札で通常攻撃して次のターンへ進みます。

再判定でも設定1が優先です。シャッフル自体は待機ターン数に加算しません。1回のクエストの最初のターンにだけ試行し、次の周回で再び使用できます。

カード枚数モードと、第3スキルがカードシャッフルの魔術礼装が必要です。従来のシャッフル条件も維持します。

<a id="recognition-and-target-loss"></a>

### 7. 設定画面と例外処理

- モード選択をON/OFFの切り替えに変更し、基本設定と設定1の重複表示を整理しました。
- 同じサーヴァントを両方の対象に指定すると停止します。
- 一方の対象が前衛から離脱した場合は、残っている対象の条件で待機できます。両方いなくなると停止します。
- カード認識が不明確な場合は同じ手札で最大3回確認し、それでも確定できなければ攻撃せず停止します。シャッフル後も同じ処理です。

[カード枚数モードの個別ガイド（韓国語）](Card-Count-Start-KR.md)

<a id="support-append"></a>

### 8. サポートのアペンドスキル判定

サポート選択のサーヴァント優先設定に、アペンドスキル判定と5枠の `10 / x` 条件を追加しました。`10` に指定した枠がすべてLv.10のサポートを選びます。`x` は判定しません。未開放の枠をLv.10とは扱いません。

従来の条件を先に確認し、スキル表示を切り替えてアペンド5枠を読みます。判定後は通常表示に戻してから候補を選択します。切り替え・復帰を確認できなければ停止します。

初期設定は無効です。全枠が `x` なら表示を切り替えません。設定はコピー・エクスポート・インポートに含まれます。

[個別ガイド・検証範囲（韓国語）](Support-Append-Skills-KR.md)

<a id="support-score"></a>

### 9. クラススコア+62・グランドスコア+16

サポート選択のサーヴァント優先設定で、2つの判定を個別に有効にできます。`/` の前がクラススコア、後がグランドスコアです。両方有効なら、適用される条件をすべて満たす必要があります。AND/ORの選択機能はありません。

| 設定 | 通常のクラスのみの表示 | 特殊なクラス／グランド表示 |
|---|---|---|
| クラスのみ | クラス+62 | クラス+62 |
| グランドのみ | スコアによる制限なし | グランド+16 |
| 両方有効 | クラス+62 | クラス+62とグランド+16の両方 |
| 両方無効 | スコア条件なし | スコア条件なし |

通常表示と確認できた場合はグランド条件を無視します。特殊な `+0/+16` はグランドのみなら通過しますが、両方有効なら通過しません。表示形式が不明確な場合、グランド条件を勝手に無視しません。

スコア・宝具レベルなどの通常条件を先に確認し、その後アペンドスキルを確認します。他の優先条件もすべて満たす必要があります。

[個別ガイド・検証範囲（韓国語）](Support-Score-62-KR.md)

<a id="direct-cards"></a>

### 10. 特定ターンの攻撃順を直接指定

コマンド編集の攻撃設定から、通常カード・宝具を合わせた3枚の選択順を指定できます。バスター・アーツ・クイックは相性を区別しません。`&a4b` は、アーツ → 前衛1番の宝具 → バスターです。

直接指定したターンは、自動優先順位、ブレイブチェイン、並べ替え、追加の宝具自動使用を適用しません。必要なカードがない、または認識できない場合は、選択前に停止します。それ以外のターンは従来の方式で実行します。

[個別ガイド・コマンド構文（韓国語）](Direct-Cards-KR.md)

<a id="support-np"></a>

### 11. サポートの宝具レベル判定

サポート選択のサーヴァント優先設定で宝具レベル判定を有効にし、最低レベルを1～5から選びます。Lv.3を指定すれば、宝具Lv.3・4・5が通過します。判定は初期状態で無効、最低レベルの初期選択はLv.5です。

宝具名の範囲から `Lv.` と隣の数字を読み取ります。読めない、不確実、指定レベル未満の場合は次の候補を探します。通常条件のすべてを確認してからアペンドスキルを判定します。

0.5.1では、失敗した場合に表示サイズと前処理を変えて再判定する処理を追加しました。信頼度の高い複数の結果が一致した場合だけ採用します。

[個別ガイド・画像試験の範囲（韓国語）](Support-NP-Level-KR.md)

<a id="quest-items"></a>

### 12. ティーポット・ストームポッドの自動ON/OFF

再生ボタンの実行画面で、AP回復と制限の間にあるアイテム使用設定を指定します。チェックするとON、外すとOFFに合わせます。サーバーごとに保存します。

サポートとパーティを選んだ後、クエスト開始前に状態を確認します。直接切り替わる画面では、表示されているアイテムのアイコンに対応する設定を使います。設定ダイアログでは左がストームポッド、右がティーポットです。設定後に閉じます。

自動設定は初期状態では無効です。詳細オプション → 追加機能 → ティーポット・ストームポッドの自動設定を使用、を有効にした場合だけ確認・切り替えを行います。以前に明示的に保存した選択は維持します。連続周回で編成確認を省略する場合は、ゲームに保持された状態を使います。

[個別ガイド（英語）](Quest-Items.md)

<a id="bond-tracking"></a>

### 13. 絆ポイント集計・MAX停止 — 0.9.2

スクリプト編集画面のコマンド開始条件とカードシャッフルの間に**絆ポイント**を追加しました。リザルト画面の左からキャラクター1～5として、基本値とボーナスをクエストごとに一度加算します。終了画面に合計・取得回数・未取得回数を表示します。横一列に並んだ名前の下のチェックボックスで、MAXでも停止しないキャラクターを選びます。2番をチェックすると2番のMAXを無視して続行します。チェックしていないキャラクターのMAXを確認したら、そのクエストのリザルトで停止し、次のクエストを開始しません。

開始前の編成・サポート確認と元の編成位置への対応付けを削除しました。結果欄の順番はユーザーが調整します。設定はスクリプト別に保存し、コピー・エクスポート・インポートに含めます。0.8.0の実行画面設定は新しい番号に移行しないため、使うスクリプトで再度有効にしてください。

通常の絆リザルトを検出してから1.5秒待ち、新しい画面を読み取ります。待機倍率を下げてもこの時間は短縮しません。レベルアップ画面の隠れた獲得量・MAXは読みません。到達レベル10以上と結果欄の位置が確定した場合に停止条件を適用します。不確実な場合は次のクエストの通常MAXで再確認します。宝石とNEXTは読みません。[詳細と検証範囲（英語）](Bond-Tracking.md)。

### 14. アプリ画面

ホームにはインストール済みバージョンの**Build: 0.10.1**ボタンだけを表示し、改変版リリースに移動します。リポジトリ・トラブルシューティング・Discord・寄付ボタンを削除しました。絆設定のサーバー案内・長い説明とアペンドスキル選択の最大レベル見出しも削除しました。アイテム自動設定の使用スイッチは、詳細オプションの「高度な設定」の隣にある**追加機能**にあります。初期状態では無効です。

### 15. GitHubの更新確認

**詳細オプション → 高度な設定 → アップデートを確認**を有効にすると、アプリ起動時にFGA-Modifiedの最新正式リリースとインストール済みバージョンを比較します。ARM APKのアップロード完了後、新しいバージョンがあれば案内し、リリースを開くボタンでGitHubへ移動します。プレリリースは除外します。通信できなくても現在のアプリを使い続けられます。アプリ終了中の確認・通知やAPKの自動インストールはしません。

<a id="chaldea-import"></a>

### 16. Chaldea共有リンクから入力 — 0.10.1

コマンド欄のターミナルアイコンの左にあるリンクアイコンを押し、Chaldeaの戦闘共有URLを貼り付けて **変換して入力** を選びます。URL欄の下に初期状態でオフの **エネミーターゲット情報を無視** を追加しました。有効にすると特殊な敵枠を含むすべての敵選択コマンドを省略し、スキル・味方対象・宝具・交代順は保持します。既存コマンドの置き換えを案内し、変換とFGA構文検証に成功した場合だけ対象のコマンドを変更します。キャンセル・エラー時は保持します。1つ目・2つ目の両方に対応し、編成・サポート・カード設定は変更しません。Atlas AcademyのJPスキル・宝具・マスター礼装データを取得してキャッシュします。変換はfgo-converterの既定ルールに従い、`,#,`区切りや通常カード・特殊ギミックの制限も同じです。選択肢2つ・3つに対応し、未対応の行動では置き換えずエラーを表示します。実際のオーダーチェンジ例を含む35例を基準出力と比較しています。実機UI・FGO動作は別途確認が必要です。[詳細ガイド（韓国語）](Chaldea-Import-KR.md)。

## インストール・更新

[最新リリース](https://github.com/puruuun/FGA-Modified/releases/latest)からARM APKをインストールしてください。Android 7以降のARM端末（arm64-v8a / armeabi-v7a）に対応します。

アプリ名は **FGA(mod)**、アイコンは青いArts、パッケージは `io.github.fate_grand_automata.cardcount` です。以前の改変版とパッケージ・署名を維持しているため、上書き更新できます。公式FGAや公式CI版とは別のアプリです。設定を移す場合は、`.fga` ファイルをエクスポートしてから改変版へインポートします。

### Obtainiumで更新

1. [Obtainium](https://obtainium.imranr.dev/)をインストールします。
2. [README](../../README.ja.md)の追加リンクを使うか、Obtainiumのアプリ追加で `https://github.com/puruuun/FGA-Modified` を指定します。
3. プレリリースを含める設定は無効のままにします。各リリースのARM APKは1つです。
4. アプリ画面で更新を確認するか、バックグラウンド確認の間隔を設定します。

[Obtainium設定ファイル](../../obtainium.json)。自動インストールの可否はAndroidとObtainiumの権限・設定によって異なります。
