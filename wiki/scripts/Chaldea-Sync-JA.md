# Chaldea自動反映

**ログ収集で集めたアカウントデータを Chaldea の `userdata.json` に自動で書き込みます。Chaldea 側で手動「インポート」を行う必要はありません。** 現在はアイテム・サーヴァントコイン・概念礼装・コマンドコード・魔術礼装・クラスボード・サーヴァント育成・霊衣・性別まで反映します。

Shizuku を使って Chaldea のデータフォルダ（`/sdcard/Android/data/cc.narumi.chaldea/files/user/`）を読み書きします。KR サーバーと公式 JP サーバーのアカウントに対応しており、**ログ収集**がオンになっている必要があります。初期値はオフです。オフの間は FGA が Shizuku 機能を一切呼び出さず（権限要求・接続・サービス起動をすべて行わない）、何もしません。Shizuku が送信する接続情報を受け取るコンポーネント（Provider）はアプリインストール時から常に有効ですが、受け取るだけで動作はしません。

## 準備

1. 端末に **Shizuku** アプリをインストールして起動します（ワイヤレスデバッグまたは root で開始）。Shizuku 13 以上が必要です。
2. FGA の**ログ収集**画面でログ収集をオンにします。
3. 同じ画面の下にある**Chaldea自動反映**欄で**Chaldeaへ自動で反映**スイッチをオンにします。
4. スイッチをオンにすると Shizuku が FGA の権限を確認するダイアログが表示されるので、**許可**してください。Shizuku がまだ起動していない場合は、起動した後にダイアログが出ます。表示されない場合や結果が戻らない場合は、FGA の画面に戻った際に再確認します（スイッチをオンにするたび最大 2 回）。それでも許可されない場合は Shizuku アプリ内で FGA を許可してください。
5. Chaldea を 1 回以上起動し、`userdata.json` が作成されている必要があります。ファイルがない場合、FGA は新規作成せず「Chaldeaのデータファイルが見つかりません。」と表示します。

Chaldea の**外部ストレージを使用**設定をオンにしてデータ保存先を変更している場合は非対応です（既定の場所にファイルがない場合は書き込みません）。`userdata.json` または `.bak` が 16MB を超える場合（通常は 1MB 程度）は手を触れずに見送ります。`cc.narumi.chaldea` と `cc.narumi.chaldea.fdroid` の両方がある場合は、`userdata.json` の更新日時が新しい方に書き込み、どちらを使ったかをステータス行に表示します。

## 反映される内容

| 反映する | 反映しない |
|---|---|
| アイテム（QP、聖晶石、マナプリズム、レアプリズムを含む） | サーヴァント育成計画（`plans`）・優先度（`priority`） |
| サーヴァントコイン（アイテム項目に併せて記録） | `itemsLeft`（残り個数）、重複サーヴァント紐づけ（`dupServantMapping`） |
| 概念礼装（所持/未所持状態、最大レベル、最大限界突破。保管室にあるカードも含めた最高値。所持カードのない所持済み概念礼装は図鑑の最高レベル・限界突破を反映し、未所持の遭遇状態は状態のみ反映） | |
| コマンドコード（所持/未所持状態、所持個数） | |
| 魔術礼装レベル | |
| クラスボード（マス解放・強化） | |
| サーヴァント育成（宝具レベル、霊基再臨、聖杯、スキル 1〜3、アペンドスキル 1〜5、絆レベル・絆上限、HP/ATK フォウ ★3・★4・★5、グランドサーヴァント、装備コマンドコード 5 枠、コマンドカード強化、お気に入り） | |
| 霊衣（コスチューム） | |
| 性別 | |

- アイテムとサーヴァントコインは Chaldea の手動インポートと同じルールで**上書きマージ**します。データがある項目のみ上書きし、削除は一切行いません。
- **ゲーム内でなくなったアイテムは Chaldea 側に以前の値がそのまま残ります。** Chaldea の手動インポートと同様です。
- 概念礼装とコマンドコードは必要なフィールドだけを上書きし、既存項目の他のフィールドは維持します（所持カードがなく図鑑状態が所持（2）の概念礼装は図鑑に記録された最高レベル・限界突破を使用し、新しく追加される概念礼装にその値がない場合はレベル 1・限界突破 0 で記録します）。
- 概念礼装・コマンドコード・サーヴァントは FGA が取得した Atlas 図鑑番号一覧で照合します。
  - 一覧はスイッチをオンにしたとき、アプリ起動時、またはアカウント保存後に Atlas のデータバージョンを確認し、変更があった場合のみバックグラウンドで再取得します（最大 1 時間に 1 回確認し、確認時点でスクリプトが実行中かダウンロード中にスクリプトが始まった場合は残りをスクリプト終了後へ延期。バージョンを読めない場合は 7 日ごとに 1 日最大 1 回試行）。
  - Atlas にまだ載っていない新概念礼装・新サーヴァントはスキップし、Atlas へ追加された後の次回反映時にまとめて書き込みます。
  - 図鑑番号が不明なコマンドコードはスキップし、ステータス行に飛ばした件数を表示した上で次回の反映で再試行します。
- サーヴァント育成は Chaldea の既定インポートルールに従い、サーヴァントごとに**最も条件の良いカード 1 枚**（霊基保管室を含む: レベル → スキル合計 → 作成時刻 → 固有 ID 順）のみを選んで使い、**その最初のカードがロック状態であり、かつ霊基変還・消滅状態でないときだけ**育成値を反映します（1 枚目がロック解除状態なら 2 枚目以降がロックされていても育成値は書き込みません）。装備コマンドコード 5 枠とコマンドカード強化は別のゲームテーブルを基準に反映します。
- 既存のサーヴァント項目の育成優先度（`priority`）、育成計画（`plans`）、FGA が書き込まない残りのフィールドはそのまま維持されます。
- **霊衣（コスチューム）**は Chaldea が自身のアプリフォルダ（`files/game/`）へダウンロード済みのゲームデータを読み取って照合し、Chaldea がゲームデータを取得した後の次回反映時に記録されます。Chaldea 側のゲームデータより新しく登場した霊衣は、Chaldea がデータを更新するまで空欄にしておき、データが更新されると自動で埋まります。現在のアカウント以外の古いアカウントは、そのアカウントで再ログインして保存された際に新しい霊衣データを反映します。
- クラスボードはボード 1 つを丸ごと置き換えます。他のボードはそのまま残ります。
- Chaldea の計画、他のユーザー、FGA が関知しない項目は一切触れません。`itemsLeft`（残り個数）も書き込みません。

## 反映のタイミング

- アカウントデータが更新された後、**1 分間変化が落ち着くと**反映します。前回反映した内容と同じ場合は何もせず、Chaldea も終了しません。
- **スクリプトの実行中は反映しません。** スクリプト終了の 15 秒後に反映します。その間に次のスクリプトが開始されるとキャンセルします。
- **今すぐ反映**ボタンは各サーバーの現在のアカウントを即座に反映します（最後の反映内容と同じでも書き込みます）。スクリプト実行中は押せません。
- Android システムによって FGA プロセスが停止されると反映も止まります。反映は**ベストエフォート方式**で動作し、FGA が再び画面に現れると待機していた項目の反映を再開します。
- **FGO・Chaldeaを使っていないときに停止**（初期値 10 分、**10分後 / 30分後 / 60分後**から選択）: 待機中に設定時間（初期値 10 分）のあいだ FGO（KR/JP）も Chaldea も使われていない場合（どちらも画面に表示されていない、または画面がオフの場合）、その時点の状態に応じて最後に 1 回処理してから待機を停止します。画面がオフになっている間は FGO と Chaldea を使っていないものとみなします。
  - Chaldea が終了していれば、最後に 1 回書き込んで停止します。
  - Chaldea がバックグラウンドにあり**Chaldeaがバックグラウンドにあるとき終了する**が**終了しない**以外の場合、状態を再度確認してから強制終了し、最後に 1 回書き込んで停止します（**終了しない**の場合は終了も書き込みもせず停止します）。
  - Chaldea が画面に見えている、または状態を判定できない場合は、終了も書き込みもせず停止します。
  - 停止後はアプリを開き直したり権限が変わったりしても再開せず、新しいアカウント保存、スクリプト終了、またはスイッチのオフ/オン時に再開します。停止状態でも**今すぐ反映**は動作しますが、1 回だけ書き込んで待機を再開することはしません。残りの未反映アカウントは次回開始時に続けて反映されます。

## Chaldea が起動しているとき

Chaldea は起動中に自身のファイルを保存し直すため、**Chaldea が完全に終了しているときだけ**書き込みます。

- Chaldea が**画面に表示されている場合**（全画面、分割画面、フローティングウィンドウ、その状態で画面がオフになった場合）は決して終了せず待機します。最初の 10 分間は 1 分ごと、それ以降は 5 分ごとに状態を確認します。
- Chaldea の状態を判定できない場合も終了も書き込みもしません（「Chaldeaの状態を判定できません。」）。
- Chaldea が**バックグラウンドで動作中**の場合は経過時間を計測します。設定した時間が過ぎると終了直前に状態をもう一度確認してから強制終了して反映します。その間に Chaldea が再び画面に表示された場合は計測を最初からやり直します。
- 書き込み後、その間に Chaldea が起動していないか再確認します。起動していた場合は反映完了とみなさず後ほどやり直します。

### 自動終了までの時間

**Chaldeaがバックグラウンドにあるとき終了する**から **10分後 / 30分後 / 60分後 / 終了しない** を選びます。初期値は 30 分です。**終了しない**を選ぶと、FGA は Chaldea を一切終了せず Chaldea が自ら終了するまで待ちます。

**今すぐ反映**は Chaldea が起動中であれば終了前に確認ダイアログを表示します。確認した後に状態が変わった場合（例: 画面前面に現れた）はもう一度確認します。

## 新規ユーザーと引き継ぎ

Chaldea のユーザーと FGA のアカウントは**フレンドコード**で対応付けます。Chaldea ユーザーの `lastImportId` がアカウントのフレンドコードと一致すればそのユーザーへ書き込みます。フレンドコードがまだないアカウントは反映しません（「アカウントを特定できない…」）。

一致するユーザーがない場合:

- Chaldea のユーザーが **1 人だけでインポート履歴がなくデータも完全に空**（初期ユーザー）であれば、そのユーザーを引き継いで名前・地域・フレンドコードを設定します。
- それ以外の場合は**新しいユーザー**を追加します。名前は `ゲーム内ニックネーム (KR)` または `(JP)`、地域はそのアカウントのサーバーになります。Chaldea 側で現在選択中のユーザーは切り替えません。
- 新規ユーザーの作成や引き継ぎは各サーバーの**現在のアカウント**のみが対象です。過去にログインした別アカウントはすでに紐づいている場合のみ反映します。
- 紐づいた Chaldea ユーザーの地域がゲームサーバーと異なる場合、地域は変更せずステータス行で知らせます。

## バックアップ

書き込む前に Chaldea の元ファイル**2 つ（`userdata.json` と `userdata.json.bak`）の両方**を FGA アプリ専用フォルダ `files/chaldea-backup/<パッケージ名>/` にコピーし、保存したファイルを読み直して確認できた場合のみ書き込みます。バックアップに失敗した場合は書き込みません。各バックアップフォルダには元のファイル名のまま両方のファイルが入ります。

- `first-before-fga/`: FGA が最初に取得した原本。削除も変更も行いません。
- `backup-…/`: 直近 3 件。最後に FGA が書き込んだ内容と同じファイルなら新しいバックアップを作りません。
- `inflight-base/`: 書き込み中のみ存在するフォルダです。書き込みが確認されると削除されます。
- ログ収集のデータを削除してもこのフォルダは削除されません。

書き込み途中で失敗した場合は、`userdata.json` と `userdata.json.bak` を**それぞれ元の内容へ**戻します。書き込み途中で FGA が停止していた場合は次回反映時にファイルを検査し、`userdata.json` が破損していればバックアップから復元します。このときも 2 つのファイルを個別に元の内容へ戻し、すでに元のままのファイルには触れません。復元を確認できない場合はメッセージを表示し、バックアップフォルダは削除しません。

- 復旧を確認できない場合は最大 3 回まで再試行します。その後は**すべての反映を停止します**（状態の分からないファイルの上へ書き込まないための意図された安全動作）。スイッチをオフ/オンするか**今すぐ反映**を押すまで何も書き込まず、理由はステータス行に表示されバックアップはそのまま残ります。
- 書き込みが終わったように見えても `userdata.json.bak` が元の内容でも新しい内容でもない場合（書き込み途中の停止で一部だけ残った場合）は中断とみなし、両ファイルを個別に元へ戻してから反映をやり直します。両ファイルがすべて確認された後でのみバックアップフォルダ（`inflight-base/`）を削除します。

## root 端末での利用

root 権限のある端末では、Shizuku なしでも root 経由で同じ動作を行います。

- root が使える場合は**自動で root を使用します**。root と Shizuku の両方が使える場合は **root が優先**されます。root を使用している間は Shizuku 権限ダイアログを出さず、ステータス行に `権限: ルート` が表示されます。
- **初回のみ** Magisk や KernelSU が FGA へ root 権限を許可するか尋ねます。スイッチをオンにしたときに表示され、まだ許可されていない状態で**今すぐ反映**を押したときも再度許可を求めます。KernelSU では許可リストに FGA を手動追加する必要がある場合があります。
- Magisk は FGA 起動ごとに 1 回「ルート権限が許可されました」トーストを表示します。気になる場合は Magisk のスーパーユーザー一覧から FGA の通知をオフにできます。
- root で書き込んだ後も Chaldea ファイルの所有者と権限が元のままか確認し、変わっていれば元に戻します。戻せなかった場合は「Chaldeaのファイルの所有者または権限が変わり、元に戻せませんでした。バックアップは残っています。」を表示します。
- スクリプトの実行中は root の確認も接続も行いません。
- root がないか許可していない場合は、上記の Shizuku 方式のまま動作します。
- root への接続が連続で失敗し、その実行中は root を使わないことにした場合でも「root 許可済み」の記録は残します。そのため、次にアプリのプロセスが起動したときに、静かな root 確認をもう一度行います。意図された動作です。

## ステータス行のメッセージ

ステータス行はサーバー（KR、JP）ごとに**最後の結果**を分けて表示します。両サーバーに結果があれば 2 行（`KR: …`、`JP: …`）、片方だけなら 1 行になります。片方のサーバーが成功しても他方のサーバーの失敗メッセージは消えません。Shizuku の問題がある場合は常に先頭に 1 つだけ表示されます。

| メッセージ | 意味と対処法 |
|---|---|
| `オフ。` / `反映する内容はまだありません。` | スイッチがオフか、反映すべき変更がまだありません。 |
| `最終反映 …: アイテムN件、…` | 成功。図鑑番号不明で飛ばしたコマンドコード案内、「Chaldeaのユーザーを新しく作成しました。」、地域案内、使用したアプリ名が付くことがあります。 |
| `待機中: スクリプト実行中です。` | スクリプトが終了すると反映します。 |
| `待機中: Chaldeaが開いています。` | Chaldea を閉じるかバックグラウンドへ移すと続けて処理します。 |
| `待機中: ChaldeaがN分間バックグラウンドにあります` | 設定時間が経過すると終了して反映します。 |
| `FGOとChaldeaをN分間使っていないため自動反映を停止しました。ゲームの新しいデータが届くかスクリプトが終わると再開します。` | 設定時間 FGO と Chaldea が使われなかったため待機を停止しました。次の保存、スクリプト終了、またはスイッチのオフ/オン時に再開します（**今すぐ反映**は 1 回書き込むだけで待機を再開しません）。 |
| `Shizukuがインストールされていません。` / `Shizukuが起動していません。` | Shizuku をインストールまたは起動してください。起動すると続けて反映します（再起動後も同様）。 |
| `ShizukuがまだFGAを許可していません。` / `ShizukuがFGAを拒否しました。` | Shizuku の確認ダイアログまたは Shizuku アプリで許可してください。 |
| `Chaldea同期サービスに接続できません。` | しばらくしてから自動で再試行します。 |
| `Chaldeaの状態を判定できません。` | 終了も書き込みもせず待機します。 |
| `反映中にChaldeaが起動しました。` | 後でもう一度反映します。 |
| `Chaldeaのデータファイルが見つかりません。` | Chaldea を一度起動してください。 |
| `Chaldeaのデータフォルダにアクセスできません。` | Shizuku の権限を確認してください。 |
| `不明なChaldeaのデータバージョンです。` | 非対応のファイル形式のため変更していません。 |
| `Chaldeaのファイルを読めないため変更していません。` | `userdata.json` と `.bak` の両方が破損しています。Chaldea 側で確認してください。 |
| `バックアップに失敗したためChaldeaを変更していません。` | 空き容量を確認してください。次の変更時に再試行します。 |
| `アカウントを特定できない（フレンドコードなし）ため反映していません。` | フレンドコードがまだ収集されていません。ゲームに再ログインしてください。 |
| `アカウントデータが大きすぎるためChaldeaに送れず、反映しませんでした。` | 反映データが Android の Binder 転送上限を超えたため中断しました（Chaldea ファイルには触れません）。 |
| `反映に失敗したためChaldeaのデータを元に戻しました。` | ファイルは元のままです。次の変更時に再試行します。 |
| `復元に失敗: バックアップの場所 …` | 自動で戻せませんでした。表示されたバックアップフォルダ内の `userdata.json` と `userdata.json.bak` を Chaldea の `files/user/` フォルダへ直接コピーしてください。 |
| `以前に中断された反映を確認できませんでした（コード）。` | 中断された書き込みを確認できないため何も書き込みません。エラーコードを連絡いただき、スイッチをオフ/オンすると再試行します。バックアップはそのまま残っています。 |
| `反映に失敗しました（コード）。` | その他のエラーです。エラーコードを連絡してください。 |

失敗メッセージは次の成功時またはスイッチのオフ/オンまで表示されたまま残ります。
