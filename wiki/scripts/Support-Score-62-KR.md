# 클래스 스코어 +62·그랜드 스코어 +16

## 설정과 통과 조건

**서포트 선택 → 서번트 선호**의 클래스와 그랜드 토글을 각각 켭니다. 두 토글을 함께 켜면 항상 적용되는 조건을 모두 만족해야 합니다. 조합 선택 메뉴는 없으며 이전 버전의 조합 값은 사용하지 않습니다. 토글은 기존 저장 키를 유지하고 복사·내보내기·가져오기에 포함됩니다.

| 실제 표시 | 클래스만 | 그랜드만 | 둘 다 켬 |
|---|---|---|---|
| +62/+16 | 통과 | 통과 | 통과 |
| +0/+16 | 탈락 | 통과 | 탈락 |
| +62/+0 | 통과 | 탈락 | 탈락 |
| +16/+62 | 탈락 | 탈락 | 탈락 |
| 일반 +62 | 통과 | 탈락 | 탈락 |
| 일반 +0·+23·+43 | 탈락 | 탈락 | 탈락 |
| 표시 형식·값 미확정 | 클래스 62가 확정돼야 만족 | 특수 표시와 그랜드 16이 확정돼야 만족 | 두 조건을 모두 만족해야 통과 |

**그랜드 조건을 켜면 클래스/그랜드 특수 표시의 +16이 반드시 있어야 합니다.** 클래스만 켜면 일반 `+62`와 특수 `+62/+16`을 모두 허용합니다. 특수 표시에서는 `/` 앞을 클래스, 뒤를 그랜드로 검사합니다. 이 규칙은 1.0.2-beta.3부터 적용하며 이전의 일반 표시에서 그랜드를 무시하던 동작을 대체합니다.

이 표는 조건 규칙이며 모든 특수 값의 실물 이미지가 제공된 것은 아닙니다. 일반 스킬·보구·예장 등 다른 조건도 통과해야 하고, 어펜드 검사는 항상 마지막에 실행합니다. 이 필터는 **선호 선택**에 적용합니다. 기존 ‘실패 시 첫 번째 서포트 선택’ 설정은 선호 조건을 우회하므로 조건을 강제하려면 실패 시 **수동 선택**을 사용하세요.

## 판독과 검증

기존 일반 +62 이미지 비교를 유지합니다. 일반 또는 특수 숫자 영역은 앱에 이미 포함된 Tesseract로 읽으며 새 OCR 엔진·서비스는 추가하지 않았습니다. 네 전처리 결과에서 신뢰도가 높은 두 개 이상이 같은 값을 보여야 해당 값을 확정합니다. `/`가 보이면 일반 표시로 처리하지 않습니다. 작은 `+`가 누락돼도 숫자와 구분 기호가 완전히 읽히면 구분합니다.

- 기존 한국·일본 전체 화면 5장, 두 정규화 순서의 숫자 영역 26개: 클래스 +62·+0·+23·+43 및 토글 네 조합 **104회 통과**.
- 확대 +62/+16 자료 한 장, 두 배율·두 축소 순서: 클래스 62·그랜드 16 및 세 활성 조합 **12회 통과**.
- 기존 0.7.0 코드 검사는 당시의 일반 표시 예외를 포함했습니다. 1.0.2-beta.3에서는 일반 +62의 클래스 단독 통과·그랜드 요구 시 거부, 특수 표시의 AND, 값 불일치·판독 불가, 어펜드 검사 전 필터를 검증합니다.

위 0.7.0 검증의 특수 자료는 확대 스코어 칸 한 장이었으며, 당시 전체 화면 위치·실제 Android 선택·그랜드가 16이 아닌 실물 표시는 검증하지 않았습니다.

### 1.0.2-beta.3: JP 실제 서포트 화면 보완

1920×1080 블루스택 JP 화면에서 `+56/+16`이 보이지만 기존 OCR의 신뢰도가 낮아 후보를 넘기는 사례를 재현했습니다. 글자 수에 따라 스코어 한 줄의 글자 크기도 달라집니다.

기존 OCR·신뢰도 기준과 일반 +62 비교는 유지합니다. 필요한 숫자를 확정하지 못한 경우, 같은 후보의 숫자 칸 안에서 `/+16` 또는 `+62/`를 직접 대조합니다. 구분 기호까지 포함하며, 그랜드의 마지막 `6`도 따로 비교합니다. 이미 확정된 다른 값은 덮어쓰지 않고 잘리거나 불확실한 숫자는 통과시키지 않습니다. 그랜드만 켜면 클래스 62를 추가로 요구하지 않습니다.

이번 JP 목록에서 추린 숫자 영역 101개로 **202개 필드 판정**을 검증했습니다. `+0/+16`, `+56/+16`, `+62/+16`, `+0/+0`, 일반 표시와 잘린 영역을 포함하며, 전체 계정 정보 없이 숫자 칸만 [회귀 자료](../../docs/reference-images/Jp/support-scores/README.md)에 보관합니다. 이 표본이 모든 서버·화면 비율·추후 게임 글꼴을 검증한 것은 아닙니다.

```sh
python -m pip install -r tools/np-level-vision-requirements.txt
python tools/validate_support_scores.py
```

활성 스코어 조건의 실제 통과 여부는 Android 로그의 `FGA.SupportScore` 태그로도 확인할 수 있습니다. 숫자·조건·판정만 기록하며 서번트 이름이나 계정 정보는 기록하지 않습니다.

```sh
python -m pip install -r tools/np-level-vision-requirements.txt
python tools/verify_support_grand_score_images.py \
  --input-dir /path/to/original/screenshots \
  --compound-image /path/to/스코어.png \
  --report class-grand-score-tests.json
```

[정규 릴리즈 0.7.0](https://github.com/puruuun/FGA-Modified/releases/tag/v0.7.0)에서 APK를 설치하거나 기존 Obtainium 설정으로 업데이트하세요.


### 1.6.2-beta.2: 오독 차단

OCR과 점수 템플릿의 값이 다르면 해당 점수는 미확정으로 둡니다. 오른쪽 끝에서 숫자가 잘렸거나 클래스 0~62·그랜드 0~16 범위를 벗어나도 해당 필드는 미확정입니다. 슬래시 뒤 잉크 폭과 자릿수가 맞지 않는 OCR 값은 버리며, 끝자리까지 별도로 확인된 템플릿 증거는 사용할 수 있습니다. 미확정 필드를 요구하는 선호 조건은 통과하지 않습니다. 다른 필드는 독립적으로 검사합니다.

이번 변경은 오독 방지에 한정합니다. JP 62·16 전용 판정 개선은 별도 자료를 받은 뒤 진행합니다.

### 1.6.2-beta.3: JP 최대 점수 검출 보완

일본 서버에서는 숫자 잉크와 슬래시를 찾아 클래스 62·그랜드 16을 각각 확인합니다. 두 자리 숫자를 같은 높이로 맞춘 뒤 별도 원본 자료에서 만든 템플릿과 가까운 오답을 함께 비교합니다. 글자 크기와 위치가 달라도 검사하며, 한 자리 숫자는 최대 점수로 통과하지 않습니다.

OCR이나 기존 템플릿과 충돌하거나 숫자가 잘렸으면 계속 미확정으로 두고 해당 조건을 거부합니다. 한국 서버의 판독은 그대로입니다. 설정과 사용 방법은 바뀌지 않습니다.
