# 서포트 이미지 검색·저장

**1.2.1 개발 베타**에서 서번트·개념예장을 번호 또는 이름으로 검색하고, FGA 설정 언어에 맞는 이름으로 저장합니다. 정규판 1.1.0에는 기존 서번트 번호 가져오기가 포함돼 있습니다.

## 사용 방법

1. **더 많은 옵션 → 추가기능 → 서포트 이미지 검색·저장**을 엽니다.
2. **서번트 / 개념예장**을 선택하고 **도감 번호 또는 공식 이름 일부**를 입력한 뒤 검색합니다. 예: 서번트 `90`, `네로`, `スカサハ`; 예장 `34`, `컬라이더`, `カレイド`.
3. 번호·이름·클래스·희귀도·초상화를 보고 저장할 항목을 선택합니다. 결과가 한 개면 선택되며, 여러 개면 자동으로 첫 항목을 고르지 않습니다.
4. **생성·저장**을 누릅니다. 검색과 전용 이미지 조회는 **JP → KR → NA** 순서이며, 결과가 있는 첫 서버에서 멈춥니다. 서버를 직접 고르는 항목은 없으며 CN·TW는 이미지 조회에 사용하지 않습니다.
5. 전투 설정 → 서포트에서 **선호 서번트** 또는 **선호 개념예장**으로 해당 폴더를 선택합니다.

저장 위치는 선택한 FGA 폴더의 `support/servant/No.번호 이름/` 또는 `support/ce/No.번호 이름/`입니다. 이미지 메이커를 실행하거나 게임을 터치할 필요가 없습니다. 인터넷 연결이 필요합니다.

## 이름 언어와 검색

이름은 **FGA에서 선택한 언어**를 사용합니다. 앱 언어가 시스템 기본값이면 Android의 유효 언어를 따릅니다. 한국어는 KR, 일본어는 JP, 영어는 NA, 중국어 간체·번체는 CN·TW 데이터를 사용하고, 해당 이름이 없거나 지원하지 않는 언어이면 JP 일본어 이름으로 대체합니다.

예를 들어 한국어에서는 No.90을 `No.90 네로 클라우디우스(브라이드)`로 저장하고, 한국 데이터가 없는 No.444는 `No.444 Ｕ－オルガマリー`로 저장합니다. 실제 번역 유무는 조회 시점의 Atlas 데이터에 따릅니다.

도감 번호는 **일본판을 우선**합니다. JP에 검색 결과가 없으면 KR, 이어서 NA 도감으로 넘어갑니다. 같은 내부 ID가 JP에도 있으면 JP 번호를 유지하며, 지역 전용 항목은 해당 지역 번호를 사용합니다. 지역 간 이름을 연결할 때는 도감 번호가 아닌 내부 ID를 대조하므로 번호가 다른 지역의 이름을 잘못 붙이지 않습니다. 공식 이름과 부분 이름을 검색하며, 일본어 이름도 함께 검색할 수 있습니다. 공백·일반 문장부호·영문 대소문자·전각 차이를 정규화합니다. 커뮤니티 별명이나 미실장 항목의 비공식 한국어 번역은 별칭 사전 없이 자동 추정하지 않습니다.

**재림·영의·진명 공개에 따라 달라지는 공식 이름도 같은 서번트로 검색**합니다. 예를 들어 `요정기사 랜슬롯`과 `멜뤼진` 모두 No.312를 찾으며, `멜뤼진` 검색에서는 동명의 다른 클래스도 별도 후보로 표시합니다. 폴더에는 검색어 대신 기존 도감의 대표 이름을 사용하므로 검색어를 바꿔도 폴더가 중복되지 않습니다.

이름 검색 시 Atlas의 공개 게임 데이터 `mstSvt`·`mstSvtLimitAdd`·`mstSvtChange`에서 기본 이름, 재림·영의의 서번트 이름 덮어쓰기, 진명 변경 이름을 모아 내부 ID에 연결합니다. 보구·스킬 이름이나 설명문은 검색어에 포함하지 않습니다. 최초 서번트 이름 검색에는 추가 목록 다운로드가 필요하며, 모은 이름 목록은 24시간 캐시합니다. 번호 검색과 개념예장 검색은 이 추가 다운로드를 하지 않습니다.

다시 생성해 이름이 바뀌면 기존 번호 폴더를 갱신하고 모든 전투 설정의 선호 선택을 함께 유지합니다. JP에 없는 지역 전용 항목은 `KR.No.번호 이름` 또는 `NA.No.번호 이름` 폴더로 저장하여, 같은 번호의 JP 이미지와 기존 선호 선택이 섞이지 않게 합니다. 다른 내장 이미지와 사용자가 만든 파일은 삭제하지 않습니다. 예전 이름을 사용하는 설정 파일도 번호로 현재 폴더를 찾을 수 있습니다.

## 이미지와 검증 범위

서번트는 `extraAssets.faces`·`facesChange`의 재림·영의·지원되는 특수 변형을 수집합니다. JP 전용 이미지 목록이 있으면 그 목록을 사용합니다. 항목이 없거나 목록이 비었을 때만 KR, 이어서 NA를 확인하며 서로 다른 서버의 그림을 섞지 않습니다. 기존의 128×128 전용 초상화 → 158×158 → `(3,47,125,44)` 변환을 사용합니다.

개념예장은 일반 카드 일러스트가 아닌 **`extraAssets.equipFace`의 150×68 전용 이미지**를 사용합니다. 비교 크기로 조정해 일반·그랜드 서포트에서 사용하는 띠 이미지를 생성합니다. 표시 이름의 언어와 별개로 전용 이미지는 JP → KR → NA 순서로 조회합니다. 자료가 없거나 이미지 규격이 다르면 임의로 전체 일러스트를 잘라 저장하지 않습니다.

지원 서버의 실제 게임 표시와 다른 예장 오검출은 화면 표본으로 별도 검증해야 합니다. 모든 미관측 기기·화면 비율에서의 인식을 보장하지 않습니다. 개별 실패는 저장/실패 수로 표시하며 다시 생성해 재시도할 수 있습니다.

목록 데이터는 앱 캐시에 저장하고 24시간 이후 갱신합니다. 유효한 캐시가 있으면 일시적인 네트워크 오류 때 검색에 재사용합니다. 이미지 생성·다운로드는 사용자가 실행할 때만 수행합니다.

## 개발 및 검증

`./gradlew :app:assembleBeta`로 베타 APK를 만듭니다. `.github/workflows/beta.yml`은 앱·설정·스크립트·라이브러리 단위 테스트 후 APK를 생성합니다. **개발 베타는 별도 요청 없이 GitHub Release에 게시하지 않으며**, 컴퓨터에 저장하거나 블루스택에 업데이트 설치합니다. 베타용 Obtainium 등록 링크와 설정은 제공하지 않습니다.

단위 테스트는 언어 매핑과 일본어 대체, 내부 ID 기준 이름 연결, 동명 클래스 분리, 번호·부분 이름·전각 정규화, 예장 전용 자산, JP·KR·NA 순서와 첫 결과에서 중단, 지역 전용 폴더 분리, 이미지 URL·메타데이터 검증, 폴더 이름 변경과 이전 선택 호환성을 확인합니다.

출처: [Atlas API](https://api.atlasacademy.io/docs), [전용 이미지 조사](Support-Template-Coordinate-Study-KR.md).

### 예장 변환 회귀 검사

일본 서버에서 이전에 기록한 일반·그랜드 서포트 화면을 사용해 13종의 예장에 대한 15개 대표 영역을 저장했습니다. 생성 띠와 대표 영역 15개가 일치했고, 서로 다른 내장 예장 28종의 조합 756개는 기본 판독 유사도 0.80 미만이었습니다(최대 약 0.7622). 이것은 기록 화면과 지정한 예장 집합의 픽셀 검사이며 모든 예장·서버의 실전 성공률을 뜻하지 않습니다.

원본 `EquipFaces` PNG를 내려받은 폴더를 지정해 재검사할 수 있습니다. [대표 영역과 원본 URL](../../docs/reference-images/ce-import-crops.json), [28종 원본 파일명](research/support-template-correlations.csv).

```sh
python tools/verify_imported_ce_images.py --assets-dir /path/to/EquipFaces --report ce-import-checks.json
```
