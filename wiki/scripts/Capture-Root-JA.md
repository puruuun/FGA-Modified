# ルート収集モード（アプリ別透過リダイレクト＋ルート監視プログラム）

**その他の設定 → 追加機能 → ログ収集 → 接続モード → ルート**は、root 権限がある端末で Android の VPN スロットを消費せず、**収集がオンになっている間だけ** FGO アプリ（UID）の TCP 443 通信を FGA 内部の透過プロキシ（`127.0.0.1:<ポート>` および `[::1]:<ポート>`）へ送り、ログを収集するモードです。

収集がオフのときはカーネルルール（`FGA_CAP`）も存在せず FGA プロキシもポートを開かないため、FGO は FGA を一切経由せず直接通信します。

---

## 1. 準備事項および必要条件

- **root 権限（`su`）**: Magisk、KernelSU、APatch などで FGA に root 権限を許可する必要があります。
  - 接続モードで**ルート**チップを押すと `"ルート権限を確認中 — 許可ポップアップを押してください"` が表示され、最大 30 秒間 root 権限を確認します。
  - 権限が拒否されたり root がない場合は `"ルート権限を確認できません"` トーストが表示され、元の接続モードのまま維持されます。
- **カーネルの `iptables -t nat` `REDIRECT` 対応**:
  - 収集開始前に `iptables -w 3 -t nat -S OUTPUT` の事前チェックを実行します。
  - 端末カーネルで `nat REDIRECT` を使用できない場合はルールを適用せず、`"この端末ではルートルール(nat REDIRECT)を使用できません"` を表示します。
- **CA 証明書の設定**:
  - **KR 版**: KR 版ゲームがインストールされており、KR 証明書が作成・インストール済みである必要があります。
  - **JP 版**: `JPサーバー（root）` がオンになっており、JP 版ゲームがインストールされ JP 証明書が準備済みである必要があります。
  - 準備できている対象が存在する FGO アプリの UID にのみルールが適用されます。

---

## 2. 動作の仕組み

### 収集をオンにする（`収集をオン` / メイン画面の`ログ収集を開始`）

1. **プロキシリスナー起動**: FGA が先に `127.0.0.1:<ポート>` と `[::1]:<ポート>` で透過 TLS プロキシを開きます。
2. **カーネルルール適用（`FGA_CAP` チェーン）**:
   - `iptables -w 3 -t nat` および `ip6tables -w 3 -t nat` に `FGA_CAP` チェーンを作成し、証明書が準備できた FGO アプリ UID に対して `-p tcp --dport 443 -m owner --uid-owner <UID> -j REDIRECT --to-ports <ポート>` ルールを追加した上、`OUTPUT` チェーンの先頭に `-j FGA_CAP` ジャンプを挿入します。
   - `REDIRECT` ルールの前に、宛先 `127.0.0.0/8`、`0.0.0.0`（IPv4）および `::1`、`::`（IPv6）に対する `RETURN` ルールを先に入れてリダイレクト対象から除外します。そのため DNS ブロック等で `127.0.0.1` が返るホストへの接続は、収集オフのときと同様にゲーム内でそのまま失敗します。
   - FGO アプリの UID のみに適用されるため、FGA 自身がゲームサーバーへ発信する通信が再びリダイレクトされることはありません。
3. **ルート監視プログラム（Watchdog）起動**:
   - root 権限で分離された監視スクリプトが root cgroup へ移動し、バックグラウンドで動作します。
   - 起動直後の最初のソケット確認が成功（`FGA_WATCHDOG_OK`）して初めて収集開始が完了し、失敗した場合は即座にルールをロールバックして収集をオフにします。
4. **再接続に関する案内**:
   - すでに開いていた FGO の接続は既存ソケットをそのまま使うため、収集をオンにした後は FGO が新しく接続した時点（タイトル画面からの再接続、クエスト突入など）から収集が始まります。

### ゲーム通信とゲーム外通信（ブラインドトンネル）の処理

FGO アプリのすべての TCP 443 接続がリダイレクトされるため、プロキシはまず TLS ClientHello の SNI（Server Name Indication、3 秒制限・最大 16 KiB）を確認します。

- **ゲームサーバーホスト（`yfgo-game.netmarble.com`、`game.fate-go.jp`）**:
  - 該当サーバーの証明書コンテキストがある場合、復号して読み取り専用で応答を収集し、元のバイト列をそのまま中継します。
- **ゲームサーバー以外のホスト（ログイン、ゲーム内お知らせ WebView、リソース・データダウンロード CDN など）**:
  - SNI は存在するがゲームサーバーではない場合、復号も記録も行わず `SNI:443` へそのまま接続する**ブラインドトンネル**として通過させます。
  - そのため Netmarble / Aniplex のログイン、お知らせ WebView、データダウンロードはいずれも正常に動作します。
- **SNI がない接続または非 TLS 接続**:
  - 接続先を特定できないため即座に切断し、カードの `想定外の接続(SNI なし・非 TLS 切断)` 件数にカウントします。

### IPv6 対応について

- JP 版（CloudFront）やモバイルデータの IPv6（DNS64/NAT64 を含む）環境に対応するため、IPv4（`iptables`）と IPv6（`ip6tables`）の両方に同じ UID ベースの TCP 443 リダイレクトルールを適用します。
- 端末カーネルが `ip6tables -t nat` ルールに対応していない場合は IPv4 ルールのみ適用し、ステータスカードに `"この端末は IPv6 ルールに対応していないため IPv6 接続は収集されません(ゲームは正常に動作します)"` を表示します。この場合も IPv6 接続は遮断されず直接通過するためゲームプレイに支障はありません。

## 3. 収集をオフにする動作と安全装置

### 通常の収集終了手順

収集をオフにする際は、処理中の FGO リクエストが途切れないよう次の順で終了します。

1. まず `iptables`/`ip6tables` から `FGA_CAP` ジャンプとチェーンを削除し、削除完了（`FGA_CLEANUP_OK`）を確認します。以降の新規 FGO 接続は即座に直接通信に戻ります。
2. プロキシが新規接続の受け付けを停止します。
3. すでに開いていた接続が終わるまで最大 30 秒待ってから、プロキシを閉じて監視プログラムを終了します。

万一ルール削除が一時的に失敗した場合は、プロキシリスナーを閉じずに維持して FGO の通信が途切れないよう保護しながら 10 秒ごとにルール削除を再試行し、通知と画面に `"ルートルールを削除できませんでした。再試行中です。失敗が続く場合は再起動してください。"` の警告を表示します。

### 自動後退（Auto-retreat）

- ゲームサーバーホストとの接続で **30 秒以内に成功なしでクライアント TLS ハンドシェイク失敗が 5 回発生**するか、**ゲームサーバーへの接続失敗が 5 回連続で発生**すると、自動的に収集をオフにしてルールを削除します。
- このとき `"ルートモード収集を自動でオフにしました: <理由>"` のトーストと通知が表示され、以降は FGO がプロキシなしで直接接続します。
- ゲームサーバー以外の外部ホスト（ブラインドトンネル）での接続失敗は件数（`ゲーム外ホスト接続失敗`）をカードに表示するだけで自動後退は起こさず、ルート収集を新しく開始するたびに 0 から数え直します。

### 強制終了・クラッシュ・アップデート・再起動・ネットワーク切り替え時の動作

- **FGA 強制終了 / クラッシュ / アプリアップデート / タスク一覧からのスワイプ終了**:
  - root cgroup で分離実行されている**監視プログラム**が 3 秒ごとに `/proc/net/tcp`（および `/proc/net/tcp6`）で FGA UID 所有のリスニングソケットを確認します。
  - FGA プロセスが消えてソケットが閉じられると、約 3 秒以内に `iptables` と `ip6tables` の `FGA_CAP` ルールをすべて削除して自身も終了します。
  - さらに FGA が再起動またはアップデートされた際、前回の実行によるルールフラグファイルが残っていればバックグラウンドでもう一度ルールと監視プログラムを整理します（フラグがなければ `su` を呼び出しません）。
- **Wi-Fi ↔ モバイルデータ切り替え / 機内モード**:
  - ルールが IP アドレスではなく **FGO アプリ UID + TCP 443** を基準としているため、回線や IP が変わってもルールを再計算する必要がなく、60 秒ごとにチェーンが維持されているか点検して欠落があれば自動で再適用します。
- **再起動**:
  - カーネルの `iptables`/`ip6tables` ルールと一時フォルダの監視プログラムはすべてメモリ上にのみ存在するため、**端末を再起動するとすべてのルールが完全に初期化**されます。

## 4. AdGuard および個人 VPN との併用

- **個人 VPN（WireGuard、Surfshark など）**:
  - ルートモードは Android の `VpnService` を使用しないため、WireGuard などの個人 VPN をオンにした状態でも同時にログ収集を利用できます。
- **AdGuard**:
  - **AdGuard は「自動プロキシ」モードにし、AdGuard のフィルタリングから FGO と FGA の両方を除外してください。**
  - AdGuard がローカル VPN モードで動作したり FGO/FGA の通信を横取りしたりすると、ルートリダイレクトルールと競合する場合があります。
  - **AdGuard → アプリ管理**で FGO（韓国版・日本版の両方）を開き、**AdGuard を通じてトラフィックをルーティング**を**オフ**にします。FGA も同様にオフにします。
    - AdGuard の自動プロキシもルートルールで通信を回しており、AdGuard のルールが FGA のルールより先に適用されます。ルーティングがオンのままだと FGO のゲーム通信が FGA ではなく AdGuard に入り、ログが取れなくなったりゲーム接続に失敗したりする場合があります。
    - この設定は**外部アプリのプロキシモードとは逆**です。外部アプリのプロキシモードでは FGO のルーティングをオンにする必要があるため、接続モードを切り替える際は AdGuard の設定も合わせて変更してください。
  - **AdGuard → 設定 → フィルタリング → ネットワーク → プロキシ**に登録した FGA プロキシサーバー（`127.0.0.1:<ポート>`）はオフにします。このサーバーは外部アプリのプロキシモード専用です。
  - **確認方法**: AdGuard をオンにした状態で FGO に接続できず、AdGuard をオフにすると接続できる場合は、FGO の AdGuard ルーティングがまだオンになっています。ルーティングをオフにした後、FGO を完全終了してから起動し直してください。

## 5. 問題が起きたとき（残ったルールの削除方法）

- 画面で**収集をオフ**を押すか、接続モードを **FGA VPN** に切り替えるとルールは即座に削除されます。
- 万一 root 管理アプリの不具合などでルール削除が失敗し続けても、**端末を一度再起動すればすべての `iptables`/`ip6tables` ルールと監視プログラムが痕跡なく消去されます**。
